## Reuse, rationale and scope

Owned paths are `dimabot/src/utils/lossless_json_view.rs`, `dimabot/tests/lossless_json_view.rs` and this new handoff. Parser/receipt/writer APIs, the owned lossless reader, settings policy, `JsString` representation, nullable trim/slice, number/date algorithms, ledger code, Cargo/features/modules, dependencies, benchmark code, loaders, oracles and goldens were not edited.

Source discovery confirmed that string truthiness decoded the string merely to check emptiness, string scalar reads revalidated a token and accumulated UTF-16 units through the owned reader, and primitive string coercion cloned the resulting owned string through `settings::js_string`. The change extends the existing borrowed key-body helper to validated string leaves. Unescaped UTF-8 bodies are copied directly through the existing `JsString::from(&str)` constructor, which owns the copied text. Escaped strings continue through the existing `parse_json` decoder, including all paired, reversed and lone UTF-16 units. There is no new JSON decoder, string representation, cache, unsafe code, dependency or public boundary.

This optimization depends on the unchanged `JsonDocument::parse` whole-input `RawValue` validation and flat span index. It does not make a prefix parse or trust unvalidated bytes: only validated string spans have their ASCII quote boundaries removed. Input `&str` is valid UTF-8, and a body without a backslash has exactly its literal text; the existing constructor supplies equivalent code units without manual decoding. Invalid controls/escapes, BOM, malformed ignored data and trailing input still fail before a view is available.

String truthiness now checks whether the validated token has more than its two quote bytes. Only `""` represents zero units; every valid JSON escape produces at least one UTF-16 unit, including NUL and lone surrogates. Whitespace strings remain truthy. Other scalar/container truthiness still delegates to the existing settings policy.

A private non-array string helper returns an owned decoded primitive string directly, implementing `String(string)` identity without the second clone. Nonstring leaves and ordinary objects continue through the established shallow settings projection. The root coercion and iterative array-join leaf path share this helper. The heap stack, array separators, null-to-empty join behavior, own noncallable `toString` failures and object-property lookup semantics remain on their existing paths. No array recursion was introduced. `js_number` is unchanged and still delegates conversion to settings after the established array join or shallow scalar projection; its internal string clone was not independently optimized.

Unescaped leaf reads still allocate their owned `JsString`; escaped leaves still use the existing decoder; array joins still build UTF-16 output; number formatting and settings conversion keep their existing allocations. Source-level removal of redundant work is not an allocation or speed measurement. Unknown deeply nested data retains the prior borrowed/indexed behavior and resource boundaries.
