# TypeScript cron workers return

The seven workers that ran as Rust binaries from 2026-10-21 returned to TypeScript on 2026-11-13 because Rust compilation slowed every cron build. The [Node supervisor](../dimabot/src/workers/cron.index.ts) registers all 26 TypeScript workers in the existing `dima-cron` container. The returned entrypoints are `stream_activity`, `dashboard_activity`, `raid_analytics`, `roulette_completion`, `follow_defense_baseline`, `raid_sessions`, and `ai_usage_receipts` under [`dimabot/src/workers/`](../dimabot/src/workers/). The roulette entrypoint is `roulette_completion.worker.ts`; the archived original was `roulette.worker.ts`. Rust worker, supervisor, and binary sources remain historical reference in [`dima-rust/`](../dima-rust/) pending the owner's decision; its library utilities were never used in production.

## Behavior and state

- [Raid analytics](../dimabot/src/utils/raid_analytics.ts) retains change-driven refresh and uses the existing `rustRefresh` and `rustPending` summary fields. Their names are historical; TypeScript adopts the Rust-written scheduling metadata without renaming it.
- [Roulette completion](../dimabot/src/workers/roulette_completion.worker.ts), [raid sessions](../dimabot/src/workers/raid_sessions.worker.ts), and [dashboard activity](../dimabot/src/workers/dashboard_activity.worker.ts) continue immediately when their readiness checks find work. [AI usage receipts](../dimabot/src/workers/ai_usage_receipts.worker.ts) continues immediately after a clean full batch with its lock still owned; failed or partial batches wait.
- [Follow-defense baseline](../dimabot/src/workers/follow_defense_baseline.worker.ts) pauses one second after eight productive passes. [Stream activity](../dimabot/src/workers/stream_activity.worker.ts) uses idle waits of one, two, four, then five seconds and immediately continues after work. [worker_loop.ts](../dimabot/src/workers/worker_loop.ts) implements these pacing helpers, abortable idle waits, batch/phase/health metrics, optional watchdogs, `--once`, `--dry-run`, and shutdown that lets the in-flight pass finish, subject to the supervisor shutdown limit.
- Lease ownership checks include expiry, for example in [raid analytics](../dimabot/src/utils/raid_analytics.ts). TypeScript resumes existing checkpoints, queues, and raid metadata. A read-only comparison on 2026-11-13 found the TypeScript fingerprint equal to the stored Rust fingerprint for all 95 production summaries; the implementation preserves BSON encoding for that compatibility.
- [worker_metrics.ts](../dimabot/src/utils/observability/worker_metrics.ts) uses entry file stems for batch, health, and phase metrics, such as `stream_activity.batch_events`, `raid_analytics.health_query`, and `follow_defense_baseline.phase.queueMs`. Runtime metrics use `<stem>.worker.rss_bytes` and related names; the supervisor emits `<stem>.restarts` and `<stem>.errors`. The [admin Observability page](../admin/src/app/pages/observability/observability-page.component.ts) reads these names.

Worker policy varies: stream and raid analytics exit on pass failure and use idle backoff; both have health probes and no whole-pass watchdog. Roulette exits on failure with a 20-second watchdog. Dashboard retries with a 40-second watchdog and probes readiness. Baseline retries with a 30-second watchdog and a health probe. Raid sessions retries with a 20-second watchdog and probes readiness. AI receipts exits on storage failures or a 20-second per-unit timeout; its per-receipt failures are requeued or dead-lettered. Dashboard and raid sessions use one-second idle waits; AI receipts uses its configured interval.

Rust-specific BSON numeric subtypes in persisted output, typed validation of malformed documents, sanitized log text, child environment allowlisting, ICU collation, per-call timeouts on shared Twitch/Redis helpers, and stdout telemetry frames were not carried over. Fingerprint generation is a separate compatibility path and preserves original BSON numeric types for hashing.

## Verification

Follow the [cron workflow](../ops/README.md#cron-workers). Its [candidate check](../ops/checks/cron-typescript-workers.mjs) runs 13 groups through the real supervisor against disposable MongoDB and Dragonfly. [raid_analytics.test.ts](../dimabot/src/utils/raid_analytics.test.ts) covers the projector; its database group requires `RAIDPORT_TEST_MONGO_URI` pointing at disposable MongoDB. Scope other checks to changed workers and actual shared impact, and check all workers' startup and health after deployment.
