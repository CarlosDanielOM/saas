# Moderation permit Rust handoff (2026-10-29)

The `moderation-permit` Rust port passed its frozen source-parity and isolated Redis validation. This is bounded local feature evidence, not dependency-complete moderation migration. The final frozen source/build snapshot contains 1,335 inputs and pins the complete TypeScript source at SHA-256 `154399463d3773c5d12c06279333ad024fd604adcf173aafb65408b40147238f`. The port began at `c962f437`; async telemetry-context propagation was corrected in `23355cca`. See the [dated acceptance note](moderation-permit-2026-10-29.md) and the [raw evidence bundle](evidence/2026-10-29-moderation-permit-retirement/).

The port covers the source exports and logic: permit constants/types, login normalization, argument parsing, user/channel Redis keys, `SET key value EX seconds` grants, and active-permit reads. It reuses `JsString` for arbitrary UTF-16, ECMAScript trimming and Redis-boundary lone-surrogate replacement, Unicode 17 lowercasing, JavaScript-compatible number formatting, and the shared Redis connection manager. Typed Rust APIs do not emulate invalid JavaScript casts or custom object-to-string hooks. The default native connection path retains the shared manager's five-second initialization/PING behavior. A grant uses no added operation timeout or application-level retry; active checks launch the two GET futures independently, return on the first error, and await both when successful. A detached coordinator keeps the other read running after an error or caller cancellation once both reads have started. The shared socket preserves Redis reply order, which can delay observation behind an earlier reply.

The final source oracle passed and matched Rust for 395 parse cases, 39 login cases, 156 key cases, 78 grant cases, eight reads, and two controlled held-read cases. After an initial native test exposed lost async-local telemetry context, the fixed source and native replay also passed a real `AsyncLocalStorage` context case; the read tasks retained the parent trace context. Source/tree fingerprints were checked against the final snapshot. The initial negative compiler receipt is retained as historical evidence of that caught issue, not as an accepted result.

The isolated private Redis fixture passed the actual network-backed checks. It uses a unique claim acquired with `SET NX EX`, refuses to register pre-existing exact test keys, and deletes only its owned keys when the claim still matches; cleanup is bounded and drop-based. The fixture uses per-operation deadlines and a private task-owned endpoint. It verified the exact grant value and TTL, user and channel permit lookup, expiration, empty-but-present values, both user-key and channel-key GET errors, invalid zero-second SET failure, and 24 concurrent checks through cloned managers. A local forwarding proxy applied a real SET before withholding its reply: cancelling the caller did not cancel the already-sent write, and the exact stored value was read back. A second applied SET with its reply discarded returned an error and was not replayed; the observed SET count remained one per call. Explicit opt-in telemetry recorded operation spans and GET hit/miss observations against a mock telemetry endpoint. These are isolated fixture results, not production Redis checks.

## Remaining dependency and adoption gaps

The TypeScript `permit.ts` and existing callers remain live; no TypeScript caller has adopted the Rust implementation. The TypeScript wrapper also starts global process telemetry, creates cache spans, reports successful GET hits/misses, and logs connection events with caller-specific suppression. `PermitStore::with_telemetry` implements operation spans and GET hit/miss metrics only when explicitly supplied a native `Telemetry`; default `connect`/exports do not start global process telemetry or reproduce the wrapper's connection-event logging. Those application-specific dependencies remain missing, so the port and its transitive closure are partial. Do not add a TypeScript fallback or describe migration completion on the basis of the native library, trait, or fixture.

No permit performance measurement was made. The tests and timing bounds establish functional behavior only. Production container identities were unchanged across the isolated work; owned resources were cleaned. There was no deployment or push.
