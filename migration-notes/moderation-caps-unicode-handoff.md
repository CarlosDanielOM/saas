# Caps Unicode classification preparation (2026-10-29)

**Status: verified Unicode source preparation and native table; no caller adoption or deployment.** The enumerated Unicode `L` and `Lu` facts were independently read back and bound to the pinned source, and the native caps implementation passed the actual-source replay. The table is part of the feature evidence in [moderation-caps-2026-10-29.md](moderation-caps-2026-10-29.md). It is a derived data artifact, not an independently maintained Unicode implementation.

`dimabot/src/utils/moderation/rules/caps.rule.ts` is the source of truth: its private `LETTER` and `UPPERCASE_LETTER` regexes are tested on each JavaScript code point by the existing rule. The native port needs their actual runtime classifications; an independently maintained Rust Unicode table could differ. The fixture checks the complete source SHA-256, the AST's top-level declarations and type-only import, and declaration byte offsets and hashes, then transpiles and evaluates the full source with an appended export of those private objects. It enumerates every value from 0 through 0x10FFFF, including lone surrogate values, and requires Lu to be a subset of L. Its output ranges are sorted, disjoint and maximal by construction. The Rust file contains derived Unicode classification facts, not a translation of V8 code.

The script pins the actual source, moderation schema, package and lockfile, Rust toolchain, TypeScript package metadata and SDK bytes; it requires TypeScript 5.9.3, Node 24.22.1, V8 13.6.233.17-node.58 and the explicit SHA-256 of the executing Node binary. The JSON records those hashes, the script and transpilation hashes, declaration byte evidence, runtime ICU/Unicode versions, counts, ranges and generated Rust hash. Changes to any pinned input require deliberate review and repinning, not a silent update.

The verified preparation used the byte-identical script in the pinned, resource-capped Node image with the source mounted read-only at `/source/dimabot`, TypeScript SDK installed at `/source/dimabot/node_modules`, and a task-owned existing empty output directory mounted at `/task-output` outside `/source`. It set `DIMA_CAPS_SOURCE_ROOT=/source/dimabot` and `DIMA_CAPS_NODE_SHA256=569128f3066ac7be59b10b9a0adef708def642ee37cbf9d560a9bdb68f872108`. With the fixture copied to `/task-tools/moderation_caps_unicode_prepare.cjs`, the recorded commands were:

```sh
node /task-tools/moderation_caps_unicode_prepare.cjs --write /task-output
node /task-tools/moderation_caps_unicode_prepare.cjs --check /task-output
```

`--write` requires an empty directory and exclusive file creation; `--check` requires exactly the two regular output files and recomputes and compares their bytes. The source and script were identical on both invocations. Enumeration is untimed validation, not a benchmark. The resulting `L` table contains 684 ranges covering 145,672 code points; `Lu` contains 655 ranges covering 1,886 code points. The parent independently verified the generated Rust table hash `f47a1f1595777a04f8f97a688a7ca663b949936a1c92758a83b6860abdd4c344` against the source-derived artifact. The caps replay also covered all range boundaries and neighboring code points, representative scripts, titlecase, combining marks, astral characters, and unpaired surrogates. No application behavior or TypeScript callers were switched.
