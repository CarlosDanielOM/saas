## Historical harness protocol

The following records the pinned method used for these completed runs. The JavaScript VM-versus-normal-realm crosscheck is JavaScript-only; Rust timings come from the native release implementation with prepared inputs and validated outputs. A new run needs its own task-owned state and source binding; these instructions do not authorize replaying historical run IDs.

The fixture extracts the actual built-in catalog initializer, error class, and both helper declarations from the TypeScript AST, type-checks the extracted module, and compiles it into a normal CommonJS module. It checks every expected wire in a separate VM realm and in the normal realm. Exactly one live or archived copy of each source is required. SHA-256 evidence covers those source files, the extracted/compiled code, compiler files, Node executable, Rust module and helper dependencies, both harnesses, Cargo inputs, and the toolchain pin. Input strings and expected strings use UTF-16 unit arrays, including lone surrogates.

Five fixed 32-case pools cover normalization of valid ordinary/Unicode whitespace, invalid and reserved inputs, and generation with ASCII, compatibility/UTF-16 names, and 20 occupied aliases. All fixture conversion, catalog/module initialization, and full result comparisons happen before timing. Each timed operation calls one helper on already prepared arguments and adds only ASCII output length or error status plus UTF-16 code/message lengths to a wrapping scalar; inherent helper allocations and error creation remain in the measurement. Traversal and pass counts match, with 20 complete warmup passes and seven trials. These are synthetic pure-helper comparisons, not MongoDB, HTTP, end-to-end latency, or allocation counts.

Use a new empty canonical absolute benchmark directory outside the checkout. The parent first captures the actual compiler identity in the capped compiler container as a separate canonical regular file outside the checkout, for example `/artifacts/fish-favorites/toolchain/rustc.json`. The exact JSON schema is:

```json
{"schemaVersion":1,"path":"/canonical/path/to/rustc","sha256":"64 lowercase hex digits","version":"rustc 1.99.1 (58cf8f9c3 2026-10-13)","verbose":"full rustc -Vv output including trailing newline"}
```

Capture `path` from the canonical actual compiler executable, hash its bytes for `sha256`, and obtain `version` and `verbose` from that executable's `-V` and `-Vv`, respectively. Preserve the trailing newline in `verbose`. Pass the same canonical metadata path and independently recorded file digest to both environments as `DIMA_FISH_ALIAS_RUSTC_PROVENANCE_PATH` and `DIMA_FISH_ALIAS_RUSTC_PROVENANCE_SHA256`. Node validates the metadata bytes and contents without opening the Rust executable; Rust checks those metadata bytes and independently hashes the executable at the recorded path before and after timing. The parent must capture the metadata from the actual compiler used to build the test; the test does not itself invoke `rustc -Vv`.

In the Rust container, additionally provide canonical external regular file paths and independently recorded SHA-256 values for the Node environment's immutable TypeScript compiler artifacts via `DIMA_FISH_ALIAS_TYPESCRIPT_JS_PATH`, `DIMA_FISH_ALIAS_TYPESCRIPT_JS_SHA256`, `DIMA_FISH_ALIAS_TYPESCRIPT_PACKAGE_PATH`, and `DIMA_FISH_ALIAS_TYPESCRIPT_PACKAGE_SHA256`. The captured copies are `/artifacts/posthog-receipt/attempt1/node-provenance/root/node_modules/typescript/lib/typescript.js` and `/artifacts/posthog-receipt/attempt1/node-provenance/root/node_modules/typescript/package.json`; use their canonical paths. Node hashes its actual installed compiler files; Rust verifies the external artifact bytes against both independent pins and Node provenance. The compiler binary and SDK artifacts do not belong in the source snapshot.

With pinned Node 24.22.1 and the metadata variables set, execute `node tests/fixtures/fish_favorite_alias_benchmark.cjs --prepare DIR`. Record its input and provenance SHA-256 values and export them as `DIMA_FISH_ALIAS_INPUT_SHA256` and `DIMA_FISH_ALIAS_PROVENANCE_SHA256`; then execute `node tests/fixtures/fish_favorite_alias_benchmark.cjs --run DIR`. In the compiler container, set the same metadata and input/provenance pins, the four TypeScript artifact variables, and `DIMA_FISH_ALIAS_DIR=DIR`; execute the ignored benchmark in release with the `channel-fish-voice-favorites` feature under repository resource limits. Record the Node and Rust report hashes and pass them as `DIMA_FISH_ALIAS_NODE_SHA256` and `DIMA_FISH_ALIAS_RUST_SHA256` to `node tests/fixtures/fish_favorite_alias_benchmark.cjs --check DIR`. This compares reports and does not retime. The benchmark refuses existing output files and validates source hashes again after measurement.

For a future candidate, freeze its own source first, capture a distinct source binding and independent pins in a new task-owned directory, then review that candidate's harness and proof before accepting its results. The optimized3 and confirmation5 runs documented above already passed their source/report checks; this instruction does not call for replaying or retiming their historical run IDs.
