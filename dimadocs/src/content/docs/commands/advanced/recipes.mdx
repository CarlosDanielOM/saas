These recipes are starting points. Each one is a complete custom command reply, or a pair of commands where noted. Test any recipe that changes channel state in a command only you can use before you open it to others. Syntax details are on [AST Syntax & Data](/commands/advanced/syntax/), and every function is listed on [AST Functions Reference](/commands/advanced/functions/).

## Counters

### Count how many times something happened

```bash
*( ^(#wins) ? %(#wins *(%(#wins) + 1)) : %(#wins 1) )
$(user) has %(#wins) wins!
```

The first line starts the count at `1` when the value doesn't exist yet, and adds `1` after that. The second line posts the total.

- Channel values (`#`) expire **24 hours after their last write**. If nobody triggers the command for a day, the count starts over.
- For a count that must last, use a database variable: `%(*wins ...)` for one count per channel, or `%(**wins ...)` for one count per viewer. **Database writes need Premium or Pro.** On Free, the write is skipped without an error. See [Execution, Errors & Limits](/commands/advanced/execution/).

### Look up another viewer's value

```bash
%(##rank(&p1))
```

`&p1` is the first word the viewer typed, so the command reads `!rank ronchi` as the login `ronchi`. Leave out the selector and `##` and `**` values belong to the person running the command.

## Conditions

### Choose one of two replies

```bash
*( %(#ready) == 1 ? "Ready" : "Not ready" )
```

A ternary `*( condition ? yes : no )` runs one branch. Put any action that changes the channel only in the branch where it should run.

### Run an action only when a condition is true

```bash
*( %(#ready) == 1 ? "Ready" : "" )
```

With an empty second branch, nothing is posted when the condition is false.

## Timed actions

### Pause a command for a set time

This turns `!spoilers` off for five minutes, then turns it back on:

```bash
$(disable.command spoilers 300)
!spoilers is paused for five minutes.
```

The duration is in seconds, from `1` to `604800`. The command returns to the state it had before the change, even if the bot restarts in between. See [Availability functions](/commands/advanced/functions/#availability-functions).

### Send a message and an action later

The timer returns right away. Its message and action run after five minutes, even if the bot restarts in between:

```bash
$(timer 300 "Five minutes are up!" $(trigger.send airhorn))
```

A timer runs at most once, and it expires if it's more than 10 minutes late. See [Execution, Errors & Limits](/commands/advanced/execution/#delay-and-timer-limits).

## Prediction results

Use two commands, so a moderator picks the winner after seeing the choices. Both commands should be set to **Moderators** access.

**Command 1, `!predictions`**: shows the question and the numbered choices.

```bash
$(get.prediction)
```

**Command 2, `!winner`**: resolves the prediction. The moderator types the choice's title or its number.

```bash
$(end.prediction &t)
```

Then a moderator types `!winner Yes` or `!winner 1`. `&t` keeps a title with several words together. `end.prediction` looks up the current prediction on Twitch each time and rejects a number that doesn't exist or a title that matches two choices.

<Aside type="caution">
Don't put `$(end.prediction 1)` in the same reply as `$(get.prediction)`. The winner is then picked without anyone reading the choices first. Keep the two steps in separate commands.
</Aside>

## Split a large command into smaller ones

When one command gets hard to read, move parts into their own commands and call them with `#(commandName args...)`.

```bash
Welcome $(user)!
#(rules)
```

Here `!welcome` posts its greeting, then `!rules` runs and posts its own reply. If the argument has punctuation such as `;`, `?`, or `/`, wrap it in quotes, like `#(poll "Best map?;Nuke/Mirage")`. Without quotes, those characters can be changed on the way through.

Keep these limits in mind:

- At most **five** levels of calls can be nested, and a single run can make at most **50** calls.
- A command can't call itself, directly or through another command.
- The called command **doesn't check its own access setting** when a command you wrote calls it. Only the calling command's access applies. So only call a moderator-only command from a command that is also limited to moderators.
- Each called command posts its own reply, after the main reply.

See [Execution, Errors & Limits](/commands/advanced/execution/#command-reference-limits) for the details.

## Pattern summary

| Pattern | Syntax | Purpose |
|---------|--------|---------|
| Count or start a count | `*(^(#x) ? %(#x *(%(#x) + 1)) : %(#x 1))` | Create a missing counter or add `1` |
| Viewer lookup | `%(##rank(&p1))` | Read a value saved for one viewer |
| Persistent viewer value | `%(**rank(&p1))` | Read a viewer's database value (Premium or Pro to save) |
| Condition | `*(condition ? YES : NO)` | Choose one of two results |
| Conditional action | `*(condition ? ACTION : "")` | Do something only when a condition is true |
| Timed action | `$(timer seconds "message" $(action))` | Run later, at most once |
| Call another command | `#(commandName args...)` | Run a separate command after the reply |
