# Desktop AI turns

**Status:** API candidate deployed and accepted; desktop app integration and app-side verification remain in progress. The [v1 wire contract](../dimabot/DESKTOP_AI_CONTRACT.md) describes the deployed API behavior.

## Source and reuse

The OAuth API derives owner, channel, and broadcaster authority from the authenticated desktop session. Bot and Pet turns use `ai:interact` and `pet:interact`; discovery requires `profile:read`, and `/desktop-ai` activity requires `desktop:connect`. Existing seven-scope grants become eight with either interaction scope or nine with both.

The implementation adds durable turn/conversation records and HTTP admission, read, cancel, speech-event, and ticketed audio routes under `dimabot/src/desktop_ai/`. It reuses the shared chat/action pipeline, existing memory, tools and credit rules, broadcaster action identity, Pet `talk` admission/queue, and existing TTS provider, voice and billing services. Bot audio uses private HTTP delivery and the shared output coordinator rather than the normal public TTS queue. Pet uses its existing elected player. Neither path adds local PC command execution or a parallel AI, Pet, or TTS system. Turn records support seven-day idempotency; the desktop thread context window is 24 hours, while normal shared memory policies remain in effect.

The desktop owner flow auto-submits the final transcript after wake detection for the selected Bot or Pet conversation/command. There is no additional Send gate, parser, or bouncer. Microphone capture is gated across Bot, Pet, normal TTS, and browser output. Bot cancellation does not count as silence proof: for started playback, only a matching initiating-session `ended`/`failed` event or the bounded playback deadline releases the output gate. For Pet and normal TTS stop, durable retired-output proof is tied to the elected peer/socket, previous lease, and execution deadline; a legacy desktop `stopped`/`error` report is not trusted without the same-session stop monitor guarantee.
