# Review of `dima-twitch` at `513bbfc6` (GPT-6.1 Sol, 2026-11-11)

All eleven findings are taken into P2-TWITCH-01b. Lead's additions: cached tokens in Dragonfly are
encrypted with the credential cipher (the reference keeps them in plain text; the key family is Rust's
own and rebuilt at the cutover).

1. **BUG — Graceful shutdown can lose a rotation.** With the documented shared shutdown token, shutdown cancels an OAuth request/body even though the refresh task remains alive; if Twitch consumed the old token, the replacement is lost and the next process requires reauthorization ([lib.rs:35 crates/twitch/src/lib.rs:35], [client.rs:98 crates/http/src/client.rs:98]). Give active credential exchanges a separate drain lifetime and persist their answers before cancelling transport; the current 10-second shutdown grace also falls below the refresh retry budget ([base.rs:153 crates/twitch/src/base.rs:153], [config.rs:106 crates/twitch/src/config.rs:106]).

2. **BUG — A recoverable MongoDB failure discards the only valid refresh token.** After Twitch returns R1, one failed MongoDB read/write exits through `?`, reports a transient failure and drops R1; MongoDB retains consumed R0, so the next refresh wipes credentials ([tokens.rs:598 crates/twitch/src/tokens.rs:598], [tokens.rs:438 crates/twitch/src/tokens.rs:438]). Retain the encrypted rotation and retry/reconcile persistence without repeating the OAuth exchange; this vulnerability is inherited from [tokens.ts:385 dimabot/src/utils/tokens.ts:385].

3. **BUG — Refresh serialization ends before the protected work does.** The unrenewed 5-second lease permits takeover during a 10-second OAuth attempt or subsequent MongoDB work, allowing another process to submit consumed R0 and wipe credentials while the winner still holds valid R1; additionally, public `refresh_token()` bypasses both serialization layers entirely ([config.rs:106 crates/twitch/src/config.rs:106], [tokens.rs:857 crates/twitch/src/tokens.rs:857], [tokens.rs:1312 crates/twitch/src/tokens.rs:1312]). Serialize every refresh entry point, renew ownership through persistence, and treat overlapping rejection as inconclusive rather than immediate revocation; the reference’s same short lease does not make this safe ([twitch_streamers.class.ts:209 dimabot/src/classes/twitch_streamers.class.ts:209]).

4. **BUG — MongoDB CAS does not fence cache publication, permitting lasting lockout.** After an expired lease, B can wipe MongoDB and pause before its cache write, A can persist/cache valid R1, then B’s delayed cache wipe leaves `has_permissions=false`; subsequent streamer calls refuse before reaching MongoDB repair, despite valid stored credentials ([tokens.rs:723 crates/twitch/src/tokens.rs:723], [tokens.rs:665 crates/twitch/src/tokens.rs:665], [helix.rs:162 crates/twitch/src/helix.rs:162]). Fence credential/permission cache writes by generation—including directory hydration/startup writes, whose fence protects billing versions only—and reconcile negative permission results with authoritative state ([streamers.rs:327 crates/twitch/src/streamers.rs:327]).

5. **RISK — A different MongoDB token is assumed to be newer without proof.** If cache holds newer R1 while MongoDB holds older R0, refreshing R1→R2 consumes the usable token, but `persist_rotation` declares R0 “superseded,” restores it to cache and can discard R2; the streamer eventually loses refresh capability ([tokens.rs:840 crates/twitch/src/tokens.rs:840], [tokens.rs:366 crates/twitch/src/tokens.rs:366], [tokens.rs:628 crates/twitch/src/tokens.rs:628]). This is conditional on cache-ahead state, rather than a demonstrated normal-path interleaving: establish/enforce the MongoDB-first invariant before exchange and never infer chronological order merely from inequality.

6. **SECURITY — OAuth error text bypasses secret redaction.** An answer whose `message`, `error_description` or `error` echoes credentials/email reaches both logging destinations verbatim, and returned failure types derive `Debug` over that text ([oauth.rs:57 crates/twitch/src/oauth.rs:57], [tokens.rs:526 crates/twitch/src/tokens.rs:526], [tokens.rs:107 crates/twitch/src/tokens.rs:107]). Classify using private raw text, expose safe categories or sanitized messages, and add echoed-secret fixtures; the reference has this exposure too ([tokens.ts:258 dimabot/src/utils/tokens.ts:258]).

7. **SECURITY — Wiping secret types do not cover the credential pipeline.** Tokens also live in ordinary `String` fields, OAuth response text/JSON, aggregate JSON and form-body `Bytes`, so dropping `AccessToken`/`RefreshToken` leaves other plaintext allocations unwiped ([streamers.rs:75 crates/twitch/src/streamers.rs:75], [tokens.rs:205 crates/twitch/src/tokens.rs:205], [oauth.rs:110 crates/twitch/src/oauth.rs:110], [client.rs:464 crates/http/src/client.rs:464]). Use wiping ownership for application-controlled plaintext buffers and document transport-library limits; this is a memory-exposure risk, not evidence of an existing log leak.

8. **RISK — The tests establish narrower guarantees than “safe refresh.”** The 17 traces check sequential outcomes, final fields, BSON types, actions and attempt counts; two-instance tests exercise ordinary contention, lease overrun and death after an answer, but the slow-refresh test explicitly accepts a wipe and the death test explicitly accepts reauthorization ([parity.rs:43 crates/twitch/tests/live/parity.rs:43], [concurrency.rs:88 crates/twitch/tests/live/concurrency.rs:88], [concurrency.rs:159 crates/twitch/tests/live/concurrency.rs:159], [concurrency.rs:227 crates/twitch/tests/live/concurrency.rs:227]). Add deterministic barriers/failures for delayed cache invalidation, persistence failure, cache-ahead state, graceful shutdown and a consumed refresh whose response times out before a subsequent invalid-token reply; hard-crash/lost-response recovery with single-use tokens remains an unavoidable limitation unless Twitch provides recovery semantics.

9. **RISK — One malformed IV aborts the remaining startup directory load.** Decode errors are skipped, but a cipher error propagates out of the loop, leaving later streamers absent and potentially failing startup for every process using the documented `?` wiring ([streamers.rs:674 crates/twitch/src/streamers.rs:674], [streamers.rs:697 crates/twitch/src/streamers.rs:697], [directory.rs:194 crates/twitch/tests/live/directory.rs:194]). This preserves [the reference dimabot/src/classes/twitch_streamers.class.ts:136], so changing it is a judgement call; I would quarantine/report that account and continue loading others.

10. **DESIGN — The agreed app/bot 401 correction remains pending.** App and bot/moderator refresh hooks currently reread credentials without passing the rejected token, reproducing the known same-token retries ([helix.rs:450 crates/twitch/src/helix.rs:450]). Implement rejection-aware refresh, conditionally replace only the rejected app-cache value, preserve a concurrent winner, and test bot/moderator parity plus repeated requests after a failed refresh—single flight alone deduplicates overlapping work, not every later rejection.

11. **DESIGN — A directory read can hold chat for seconds.** Each lookup waits on Dragonfly’s default 5-second command timeout, with no fallback, and an outage becomes “streamer not found”; the nominal 4.5-second refresh wait can also overrun while awaiting cache commands ([streamers.rs:478 crates/twitch/src/streamers.rs:478], [config.rs:28 crates/store/src/dragonfly/config.rs:28], [tokens.rs:894 crates/twitch/src/tokens.rs:894]). Keeping Dragonfly authoritative is reasonable; shorter caller deadlines and distinguishable unavailable results are judgement calls I would make before wiring this into chat.

Checked and found sound in source:

- MongoDB writes target the same account and compare both refresh-envelope components; a different stored token prevents invalidation, and unrelated fields survive.
- MongoDB encryption matches the reference’s AES-CTR envelope; wipes use explicit null components and expiry, rather than missing fields.
- Runtime expiry uses **seconds**, matching TypeScript; the model’s “[epoch milliseconds crates/model/src/users.rs:354]” comment needs correction.
- Standalone 5xx, timeout/network failure, rate limit, malformed JSON and incomplete success payload do not directly wipe credentials.
- Lock acquisition uses UUID ownership and server-side expiry; release is atomic compare/delete, and waiter timing is monotonic.
- Helix retries only explicit 401 responses, with up to three configured refresh/retry rounds; ambiguous transport failures and 5xx do not replay mutations, rate-limit headers remain available, and moderator authentication uses the bot.
- Startup uses one projected MongoDB cursor, with roughly three sequential Dragonfly operations per streamer; there is no MongoDB query per streamer, and missing hashes hydrate.
- Dragonfly credentials are **plaintext in both implementations**; encryption applies to MongoDB, not the reference’s directory cache.
