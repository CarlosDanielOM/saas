# Caps rule: verified native evaluator (2026-10-29)

## Scope and migration status

The native implementation maps both runtime exports in `src/utils/moderation/rules/caps.rule.ts` (`stripEmoteTexts`, `evaluateCapsRule`), the equivalent input/result types, and the four required fields selected through its type-only `Pick<IModerationRule, ...>`: `capsThresholdMode`, `minCapsCount`, `maxCapsPercentage`, and `minMessageLength`. The actual schema declares the mode as `'count' | 'percentage'` and the other fields as numbers. This closes only the caps source row in the JSON dependency inventory.

The selected pure evaluator and its required dependencies are locally complete. There is no runtime external adapter needed for these functions. The wider moderation settings model, rule registry and application, message-fragment/counting path, and enforcement remain open in TypeScript. The TypeScript source and callers remain live and unchanged; no caller adoption, retirement, deployment, push, or new crate occurred. Total Rust migration remains incomplete and no percentage is calculated. The source inventory remains 806 rows, with 13 locally complete mappings and 7 partial source rows; these counts do not imply whole-project dependency completeness.

## Behavior and implementation

The evaluator preserves the declared TypeScript behavior: sequential non-overlapping literal emote replacement; Unicode code-point iteration; `L` and `Lu` letter classification; the minimum-letter guard; count and percentage comparisons; and the source's nullish text fallback. `JsString` preserves UTF-16 code units, including unpaired surrogates. The native replacement uses Rust's standard string replacement for valid UTF-8, with a local UTF-16 KMP path when ill-formed code units are involved. The Unicode range table was generated by enumerating the pinned source regexes under the pinned Node/V8/ICU/Unicode runtime. Existing JS string and number facilities are reused. Runtime casts, arbitrary coercion hooks and prototype behavior beyond the declared interface are not in scope.
