# Moderation variations native migration

**Status (2026-10-30):** the native implementation, source-bound checks, final scoped validation, and three-round matched benchmark are complete for the bounded helper. This is a **partial local source mapping**: the typed and ordinary JSON boundary, JavaScript own-property presence for `undefined`, the existing 128-level JSON limit, and native RE2 compatibility/resource limits remain documented differences. TypeScript callers remain active and unadopted; this does not claim TypeScript retirement, deployment, or total migration completion. Variation-job/Mongo orchestration is a separate caller concern, not a direct dependency of `variations.ts` or a blocker to this helper's local implementation.

## Scope and implementation

The source is `dimabot/src/utils/moderation/variations.ts`, including its provider exports. It exposes 15 runtime exports and four type exports. Native code is in `dimabot/src/utils/moderation/variations.rs` and `variations_provider.rs`; NFC is shared through `dimabot/src/utils/js_unicode.rs`. The pure feature is `moderation-variations`; the provider adds `moderation-variations-provider`. These features reuse existing crates and support code: no Cargo package or lockfile changes were needed. The native SHA-256 helper reuses `tests/support/sha256.rs`.

The implementation covers validation, NFC term normalization, key generation, spelling variations and bounds, spacing and symbol patterns, override checks, rule compilation, pattern validation, and Muse request/response handling. Native UUID, pinned native RE2, normalization, SHA-256, attribution, and a pooled cancellable HTTP implementation supply the reviewed dependencies. Both typed Rust structs and lossless `JsonValue` adapters are available. The adapters preserve UTF-16 strings and unmodeled JSON fields through object spreads; they model ordinary JSON values, not arbitrary JavaScript objects, accessors, symbols, prototypes, or `undefined` own-property presence. JSON wire output represents `symbolVersion: undefined` as absence. Typed convenience APIs intentionally model declared fields.

The typed and value spacing caches are independent 1,000-entry FIFO caches. The typed cache uses four flag buckets and borrowed-key lookup; the value cache uses serialized JSON keys. Cache hits do not refresh FIFO order. Clones share cache entries, cache results retain `Arc` identity, and the value cache covers source object identity. Borrowed/off paths preserve source identity. The existing lossless JSON parser's maximum depth is 128.

The provider retains one reusable HTTP client pool. `from_env()` refreshes `OPENROUTER_API_KEY` on each generation call while reusing the pool. There is no implicit deadline. Abandoning the request future or signaling the watch receiver cancels pending I/O, including while waiting for headers or the body; dropping the sender alone does not signal cancellation. The bearer credential is sent to the configured endpoint, which must be trusted.

## Compatibility boundaries

NFC uses the pinned Unicode 18 normalization crate over Unicode 17 assigned scalar runs. Unicode 17 unassigned scalars and lone UTF-16 surrogates act as barriers. This keeps the native helper aligned with Node 24.22.1 / V8 13.6.233.17-node.58 behavior. The normalization path uses `is_nfc` only when all input scalars are assigned in Unicode 17; ASCII already borrows. Lowercase and fold behavior is unchanged. The `/\p{L}/u` source behavior uses the pinned V8 Unicode 17 fact table rather than the different property namespace in native RE2.

The source accepts overrides up to 16,000 characters, while native RE2/resource constraints impose a compatibility boundary; malformed-regex diagnostics can also differ by engine. Native JSON parsing can phrase syntax errors differently from Node. Provider comparisons check compatible failure category/outcome where exact engine wording differs. These are bounded differences, so the matrix row remains partial. Caller adoption is reported separately and is not a requirement for local feature completion; no N-API bridge is required.
