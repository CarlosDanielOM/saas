# Expressive-tag and Kokoro utility retirement — 2026-10-29

## Scope and status

This bounded retirement removes the two pure TypeScript utilities `src/utils/tts/expressive_tts_tags.util.ts` and `src/utils/tts/kokoro_voices.util.ts` from the application source tree. Their byte-exact snapshots are preserved under [`archives/dimabot-typescript/2026-10-28/src/utils/tts/`](../archives/dimabot-typescript/2026-10-28/src/utils/tts/), with hashes in the [archive manifest](../archives/dimabot-typescript/2026-10-28/manifest.json). The archive grew from 17 to 19 files; the frozen 806-file baseline is unchanged. The current checkout has 787 TypeScript files, including the six excluded React Email templates. Counts describe source inventory only, not migration percentage or total completion.

The Rust behavior was already implemented in `dimabot/src/utils/tts/mod.rs` and the typed tag support in `tag_types.rs`. This retirement adds the named `EXPRESSIVE_TTS_TAG_GROUPS` view by reusing the four existing catalog slices (`EMOTIONS`, `DELIVERY`, `SOUNDS`, `EFFECTS`); the expressive source replay consumes this same native view. It does not add a duplicate tag catalog or change the existing algorithm. The native API surface maps all source exports, including runtime values/functions and equivalent typed contracts for the source's type-only exports. It includes ordinary and lossless JSON paths for settings normalization and Kokoro voice resolution; `JsString` preserves arbitrary UTF-16 code units for the lossless APIs. Related implementation scope and earlier behavior/performance measurements are recorded in [expressive TTS utilities](expressive-tts-2026-10-29.md), [TTS tag types](tts-tag-types-2026-10-29.md), and [TTS value adapters](tts-value-adapters-2026-10-29.md).

This closes local feature coverage for these two utility modules and permits retiring their TypeScript source snapshots. Application caller adoption is separate and remains open: speech routes, pet settings and preview, provider selection, and the normalizer re-export still need native callers/adapters. Therefore this note does not claim dependency-complete TTS migration, caller cutover, deployment, or whole-project migration completion. Accepted external pet `speech_text.ts` / test and the runtime delta remain open obligations outside the frozen 806-file baseline, as recorded in [TTS tag types](tts-tag-types-2026-10-29.md).
