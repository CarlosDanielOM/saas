## Generated corpora

- `attempt5/` contains the generated post-retirement corpora and prepared benchmark inputs for lossless behavior, producer behavior, receipt parsing, PostHog, Polar, lock behavior, daily reduction, persistence E2E, producer benchmark inputs, and PostHog benchmark inputs. It also retains the actual-source extracted/typecheck outputs and provenance manifests used by source readers. Payloads at least 1 MiB are stored as deterministic `.gz` files; `payload-compression-index.json` records each original and stored path, raw/stored sizes, SHA-256 hashes, and the original task-state path. The originals were byte-compared with task state before compression. To restore a payload, decompress its `.gz` file to the `original_path` listed in the index, then compare the raw SHA-256 there.
- `attempt6/` contains the regenerated backfill, ledger persistence and ledger query references that superseded the failed broad replay attempt. The corpora already existed when the earlier compiler failed: three Rust AST declaration snippets still read the deleted helper via `base.join(file)`. The parent switched them to `ai_usage_source::path` and regenerated the references because their native test source hashes changed. All three were checked and replayed successfully in the final phase.
- `independent-input-hashes.json` in `attempt5/` holds the corresponding independent input hash index.

The ten reused `verification/posthog-rs` files are directly bound in `source-binding.json` to the tracked `reused-sdk-inputs` directory. The 445 pinned Node package files used by some source readers are a separate SDK capture; their source hashes are in the provenance manifests and raw receipts, and the package trees are not duplicated in this bundle.
