Usa estos patrones como punto de partida. Prueba los cambios de estado y las funciones de acción en un comando restringido antes de habilitarlos para el chat.

## Buenas prácticas

### Inicializar o incrementar un contador del canal

```bash
*( ^(#wins) ? %(#wins *(%(#wins) + 1)) : %(#wins 1) )
"$(user) ahora tiene %(#wins) wins!"
```

Esto guarda `#wins` en la caché del canal. Los valores de caché expiran 24 horas después de su escritura más reciente. Para conservar el estado, usa una variable de base de datos como `%(*wins ...)` o una variable de base de datos por usuario como `%(**wins ...)`; las escrituras en base de datos requieren Premium o Pro.

### Leer el estado de otro usuario

```bash
%(##rank(&p1))
```

En este ejemplo, `&p1` debe resolverse al login del usuario objetivo. Sin selector, las variables `##` y `**` se refieren al usuario actual.

### Proteger una acción con una condición

```bash
*( %(#ready) == 1 ? "Ready" : "Not ready" )
```

Una ternaria elige un resultado. Coloca las funciones que cambian estado solo en la rama donde deben ejecutarse y asegúrate de que los permisos configurados del comando permitan invocarlo a los usuarios previstos.

## Resumen de patrones

| Patrón | Idea de sintaxis | Propósito |
|--------|------------------|-----------|
| Inicializar o incrementar | `*(^(#x) ? %(#x *(%(#x) + 1)) : %(#x 1))` | Crear un contador o incrementarlo |
| Selector de usuario | `%(**rank(&p1))` | Leer el valor persistente de un usuario |
| Guarda | `*(condition ? ACTION : "")` | Ejecutar una acción solo si la condición es verdadera |
| Rama | `*(condition ? YES : NO)` | Elegir una expresión según una condición |

## Patrones activados por eventos

Para comandos de redención o EventSub, primero confirma que el comando esté asociado al evento correspondiente. Por ejemplo, `$(reward.input)` tiene sentido en el contexto de una redención de puntos del canal; puede estar vacío durante una ejecución normal desde el chat.

Mantén la moderación, cambios de roles o ajustes del canal, encuestas, TTS y triggers detrás de permisos apropiados para el comando o evento. Prueba el texto y las condiciones antes de añadir esas acciones.

<Aside type="caution">
El bot realiza acciones reales cuando ejecutas estas funciones. Prueba con un mensaje inocuo o un comando restringido antes de habilitar acciones como `$(ban ...)`, `$(set.title ...)` o `$(trigger.send ...)`.
</Aside>

## Cuando un comando se vuelve difícil de mantener

Divide el trabajo en comandos personalizados más pequeños y llámalos con `#(commandName args...)`. Las referencias permiten hasta cinco niveles anidados y se detienen las referencias repetidas en la misma ruta de ejecución.
