# Rust worker migration notes

This directory is the entry point for fresh sessions working on Rust worker migrations. Each record states rollout status, reused sources, what remains in TypeScript, measured observations versus expected benefits, validation evidence, and rollback limits. Seven scheduled TypeScript worker entrypoints have previously accepted Rust replacements. The latest shared-utility candidate, `cron-2056ce9d790c` (image `sha256:adac7d8de9b5c5cfb138f8051a05123ac02a6c3467cc85784873ee85370d892f`), deployed at `2026-10-22T05:15:05.047669035Z`; nine exact-image suites (150 groups) and source identity passed. Its 32-sample watch passed across 332.257 seconds; final readbacks, binary identities, analytics/log checks, and cleanup passed, and the release is accepted. Rollback restores previously accepted run `cron-bf400acbc441` (image `sha256:72df59845ea803f1f619e8d9cfa748a881a0dd0de246da720815a9f8182fda30`) with seven native workers and private helpers. Future verification scope follows root [`AGENTS.md`](../AGENTS.md#cron-worker-verification-scope) and [ops guidance](../ops/README.md#scope-behavior-checks-by-worker-impact). Former `*_RUNTIME=typescript` selectors are historical only where they existed; no `RAID_SESSIONS_RUNTIME` selector existed. See [worker-shared-utils.md](worker-shared-utils.md) for the current accepted release and checks, [dashboard-activity.md](dashboard-activity.md) for prior accepted evidence, [typescript-worker-retirement.md](typescript-worker-retirement.md) for retirement evidence, and [raid-sessions.md](raid-sessions.md) for the earlier accepted migration. Read the project guides and [`ops/README.md`](../ops/README.md) before changing or releasing code. Shared MongoDB and Redis behavior, dotenv loading, Cargo features, and runtime constraints are documented in the [dima-rust guide](../dima-rust/README.md).

The shared-query experiment was deferred after its controlled trials showed no consistent CPU improvement. Run `cron-2ddd455fdd1f` deployed and accepted the raid change-driven refresh; run `cron-7b8a6c88303d` then deployed all five workers after their exact-image suites passed. Its 190.624-second production watch, analytics readback, and cleanup also passed. Keep runtime comparisons separate from production observations, and do not claim a general runtime gain from the short controlled fixtures.

The follow-defense baseline record describes the TypeScript source contract and the scheduler/health upgrade deployed in `cron-240af282cb85`. All three same-candidate runtime suites passed; the bounded production acceptance watch passed. The baseline-only candidate `cron-d33c17d71dd8` passed 11 baseline behavior groups but was cleaned up without deployment after stream health joined scope. The combined candidate passed Rust compilation at a 4 GiB cap. Its 24-channel baseline fixture drain took 4,022 ms, but those synthetic channels had no matching Mongo history; this is not representative full production load. The prior source-imposed 23-second wait is not a measured TypeScript throughput result. The earlier RSS observations were short and unmatched; no CPU or throughput gain is claimed. The raid and stream release evidence above is historical and does not establish the status of this worker.
