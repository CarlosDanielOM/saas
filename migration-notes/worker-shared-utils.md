## Reused sources and remaining boundaries

The refactor centralizes narrow behavior already present in Rust worker ports. It is not a new TypeScript utility migration and does not add a parallel data path.

| Shared source | Reused by | Contract and boundary |
| --- | --- | --- |
| [`bson_compat.rs`](../dimabot/src/utils/bson_compat.rs) | Roulette completion, AI usage receipts, dashboard activity/insights | `js_number(f64)` follows the Node BSON writer for an already-coerced JavaScript Number: finite integral values in inclusive Int32 bounds use BSON Int32; fractions, values outside those bounds, negative zero, NaN, and infinities use BSON Double. `normalize_document(&mut Document)` recursively rewrites nested documents and arrays. BSON Int64 values within inclusive `+/- 2^53` are promoted through a JavaScript Number and rewritten; larger magnitudes keep their Int64 representation. Other BSON types remain unchanged. It does not parse JSON, validate application numbers, or decide which payloads are rewritten. |
| [`utc_time.rs`](../dimabot/src/utils/utc_time.rs) | Raid analytics and dashboard activity/insights | `utc_midnight(DateTime)` floors timestamps to the UTC calendar day, including pre-epoch dates. `inclusive_day_start(days, now)` returns the start of an inclusive calendar range containing today's UTC day. It adds no validation or exclusive end; `days == 0` intentionally retains the existing next-midnight result. |
| Existing [`js_compat.rs`](../dimabot/src/utils/js_compat.rs) | AI usage and dashboard code now reuse `trim`; other utility callers remain | JavaScript whitespace trimming was already a shared primitive. It is now available under the Mongo feature as well as the existing opt-in utility features, so the AI/dashboard private copies are removed. |
| [`worker_process.rs`](../dimabot/src/utils/worker_process.rs) | All seven native worker binaries | `load_env_files` loads only explicitly selected files, synchronously, without overriding existing process variables. `spawn_shutdown_signal` notifies a watch receiver on SIGTERM or Ctrl-C; on Unix signal-registration failure also requests cooperative stop. `IdleBackoff` returns waits of 1, 2, 4, then 5 seconds for consecutive empty batches, remains capped at 5, and returns no wait after work while resetting. |

The time helpers retain each caller's prior range policy. Raid analytics and dashboard ranges use the inclusive calendar start. Follow-defense baseline continues to use UTC midnight as the exclusive end of its preceding 30-day window; this extraction does not switch it to an inclusive-today range. Likewise, `IdleBackoff` is used by stream activity and raid analytics only where already integrated. No worker's detailed wait policy changes: ready-work detection, future-due waits, retries, lease waits, cooldowns, watchdogs, and shutdown drains remain defined by their existing worker code.

## Startup and shutdown ownership

The existing [`cron.index.ts`](../dimabot/src/workers/cron.index.ts) remains the production process owner. It selects the environment allowlist for each native child, spawns the process, collects native metrics, restarts failed children, and on shutdown sends SIGTERM before escalating to SIGKILL after a 25-second grace period. Rust's `spawn_shutdown_signal` only asks the child to stop cooperatively; each worker retains responsibility for stopping new units, completing or draining the active bounded unit according to its existing contract, and aborting/joining its signal task.

`load_env_files` and a binary's repeatable `--env-file PATH` option are for manual executable support. Files are loaded before runtime/watchdog threads: inherited process values win, and for duplicate keys the first selected file wins over later files. There is no automatic `.env` load. Production cron continues to pass its allowlisted environment and does not use the Rust file loader as a second bootstrap.
