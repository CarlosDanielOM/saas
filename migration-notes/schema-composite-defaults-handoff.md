# Schema composite defaults: accepted core extension (2026-10-29)

The `application-schemas` core extension is verified against the actual channel-moderation Mongoose schema and the final isolated Rust candidate. It adds three opt-in capabilities to the existing schema builder without changing the behavior of descriptors that do not select them:

- `FieldDefault::Value(Bson)` keeps a reusable BSON template and clones it for each construction before the normal cast/default/trim/validation pipeline. This represents populated array/object defaults and different offense-subdocument defaults.
- `FieldType::ArrayElement(Box<Field>)` applies the wrapped element's cast and validators, with indexed error paths such as `categories.0`. Existing `Array(Box<FieldType>)` behavior is unchanged. A direct element cast failure stops the array cast; successfully cast elements report their first failed validator at their own index. Explicit null is preserved.
- `Field::minimize()` opts a Mixed value into recursive pruning of empty ordinary object properties after construction and validation. It is opt-in; unmarked Mixed values retain the old behavior. Arrays and nulls remain, including objects nested directly in arrays.

The pinned Mongoose 8.24.2 reference exercised ordinary JSON/BSON data, including Mixed minimization and the source's `cloneObject` handling for special property names and a truthy own `constructor` with inherited `valueOf`. The implementation follows these tested branches, including a non-callable own JSON `valueOf`. It does not claim generic parity for executable JavaScript hooks, arbitrary prototypes, sparse/undefined slots, exotic constructor metadata, or Date/RegExp constructor dispatch. Array element defaults, arbitrary nested element errors, and `required_when` behavior are not established as general ODM behavior. The accepted application use is primitive string arrays with enum validators.
