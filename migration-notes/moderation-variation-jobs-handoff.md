## Source and dependency mapping

The TypeScript module `dimabot/src/utils/moderation/variation_jobs.ts` exports `VariationError`, `variationJobView`, `savedVariations`, `resolveVariations`, `requestVariationJob`, and `processNextVariationJob`. The Rust module behind `moderation-variation-jobs` maps those operations to `VariationJobsService`, public job-view/ID helpers, and one bounded claim/process operation. It does not introduce a job loop or worker. The separate `moderation-variation-storage` feature models the two Mongoose collections and their indexes.

The native module does not invoke Node or a TypeScript runtime; Node is used only by the source-oracle evidence. The concrete native dependency path is:

- `moderation_variation.schema.rs` provides disconnected cache/job repositories, declared TTL and state indexes, source defaults, raw BSON persistence, and strict typed views.
- `variations.rs`, `variations_provider.rs`, and `advanced_policy.rs` provide the existing variation/spacing/validation/provider and paid-plan/retention behavior.
- The existing MongoDB and Redis drivers provide persistence. `VariationJobsService::from_application` acquires the shared Redis application runtime only when a reservation must spend quota; supplied `ConnectionManager` values remain supported for direct construction. The quota EVAL uses the shared cache/eval telemetry path.
- The user entitlement query uses the native users collection with the Twitch account match and plan-tier projection. The channel moderation rule import is type-only and maps to the existing native typed contract. SHA-256 is provided by the already-declared Rust dependency.

The module does not debit AI credits. It retains the source's 500-word and 30-job daily limits, 86,400-second Redis counter TTL, reservation and retry rules, five-minute job deadline, one-job oldest-first claim, batches of at most 20, 60,000 ms provider bound constrained by remaining job time, 180-day cache/job retention, saved reuse, zero credits, persisted provider usage, conditional final update, and failure categories. Mongo and cache values remain raw BSON at persistence boundaries where the source uses Mongoose Mixed.

## Accepted boundary and open work

The native public JSON view omits an optional `symbolVersion` when its source value is `undefined`, as JSON serialization does. The source can distinguish an own property whose value is `undefined` before serialization; the focused test explicitly adapts only at the accepted JSON-helper boundary. Exact JavaScript own-property identity is not claimed. The first native replay exposed this optional-undefined assertion; the mismatch was in the test's identity expectation, not the serialized helper output.

Raw BSON repositories preserve unknown Mixed fields and missing/null shapes as documented, while typed DTOs are strict views of complete ordinary application values. The Rust compiler bridge projects uncommon BSON values into its supported lossless-value boundary; arbitrary JavaScript prototypes, accessors/getters, `undefined` property identity, sparse arrays, and full BSON-to-Node identity are not claimed. Native Mongo error text is compared by category at the synthetic ORM-failure boundary. Native provider/resource and regex diagnostic boundaries are bounded as documented in the variations evidence. Exact raw Mongo/Redis telemetry/console-message parity is not claimed.

The feature row is **partial** within these serialized/BSON/native dependency boundaries. The TypeScript route `dimabot/src/server/routes/moderation.route.ts` still calls request/resolve/view functions, and `dimabot/src/workers/semantic_moderation.worker.ts` still calls `processNextVariationJob`; the caller path has not adopted Rust. Adoption, worker ownership, deployment, and TypeScript retirement are tracked separately. No production cutover is authorized or implied.
