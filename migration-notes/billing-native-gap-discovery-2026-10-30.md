## Worker call path and reusable Rust code

`semantic_worker.ts` first claims a pending `moderation_decisions` row whose deadline is still in the future, then queries `users` by `accounts.$elemMatch({type: 'twitch', id: channelID})`, selecting `plan_tier` and `polar_sh_customer_id`. A literal `premium` or `pro` tier is paid moderation. For paid moderation with a Polar customer ID, it calls `isAiCreditsExhausted(channelID)` and, if not exhausted, `getAiCredits(owner, channelID, { requireVerified: true, signal: AbortSignal.timeout(750) })`. A failed balance check falls back to Lite moderation. A successful paid inference is charged for both `completed` and `uncertain` results, with the stable external ID `moderation:${decision._id}`. Late or failed reviews are not charged. The completion update is conditional on `state: 'processing'` and the deadline remaining in the future.

### Billing and plan rules that constrain the adapter

- `users.plan_tier` is the worker's entitlement input; `polar_sh_customer_id` identifies its Polar customer. The user schema also stores `plan_tier_until`, `polar_plan_event_at`, `polar_plan_event_key`, `polar_plan_effects_pending`, `polar_plan_entitlement_fingerprint`, and hidden `polar_credit_snapshot.{occurredAt,eventKey,meters}`. A fresh-fence lookup must not trust only the tier originally passed by the caller.
- Existing TypeScript `polar_billing_events.ts` resolves paid access from current Polar state: active/trialing paid subscriptions qualify; a `past_due` subscription qualifies only when an actual live subscription-linked grant establishes Polar grace. A customer-state meter snapshot alone does not convert a legacy/manual paid tier to Free unless lifecycle evidence supports it. Plan changes fence/invalidate cached credits, and the reader must reject an older plan version rather than republish stale paid allowance.
- The later `55bd0bb` billing recovery behavior is a separate checkout concern: an unended `past_due` paid or known-Free subscription with no active paid subscription can be reactivated through the customer portal while the user remains Free and `hasActiveSubscription: false`; the recovery subscription does not itself confer paid moderation. A native billing/API migration must retain this captured behavior, but it is outside the worker-scoped adapters proposed below.
- In `getAiCredits`, a no-customer, unfenced caller may receive a plan-limit estimate; a required-verified caller must not treat it as a verified meter balance. If a plan fence exists and Mongo lookup is missing/stale, result is unavailable. Provider failure with a fence remains unavailable; without a fence it may return the plan-limit fallback and checks both exhaustion keys. These distinctions decide whether the worker can use paid moderation.

### Idempotency and uncertain writes

The moderation decision ID is reused as the charge external ID and usage request ID. Local credit projection deduplicates that ID for 31 days, and Polar metadata uses it as the event/entry ID; PostHog maps it to `$insert_id`. Redis EVAL/RPUSH outcomes can be unknown on timeout/disconnect and the native Redis adapters document no application-layer replay. The TypeScript Polar queue uses an 8-second per-channel lock, waits at most 2.5 seconds with 350 ms polling, checks the stored lock token before a separate `DEL` (not an atomic compare-delete), and queues before any non-cache network ingest. Its cache-mode caller queues and performs local accounting while holding the lock. Receipt enqueue is a separate single RPUSH; receipt persistence has its own lock/idempotency behavior. Keep the stable IDs and queue ordering, and do not introduce retries that can double-apply writes.

1. **AI-credit reader (verified bounded implementation).** `migration-notes/ai-credit-reader.md` records the concrete opt-in reader and its accepted checks. This closes the bounded `getAiCredits` adapter gap in this discovery. It does not adopt a semantic-worker caller or close the rest of billing. The final source oracle uses 13 actual-source DTO/wire cases; the reader has three passing normal tests and two passing ignored private-service suites. The source comparison correction for JavaScript UTF-16 fresh-version ordering is covered by the 13th case. Retain the reader's documented race, cancellation, cross-origin, and schema limits; do not treat older moderation-schema case counts as this reader's evidence.

2. **Concrete cache-mode usage accounting adapter for semantic moderation (unverified active authoring).** Port only the source branch used by this caller, with the `moderation:{decisionId}` external/entry ID, contextual-moderation usage metadata, the existing `twitch:{channel}:ai:polarshevent` queue and legacy migration/lock semantics, `AiCreditProjection`, `AiUsageProducer`, and best-effort PostHog tracking. Do not claim the general `ingestPolarSHEvent` export or immediate/batch Polar HTTP ingestion as complete. The credit reader does not cover this branch; source-image binding remains unproven. Fixture coverage should address the missing cases already listed here, especially locked queue migration, partial receipt/PostHog failures, and uncertain writes without blind replay.

These two adapters close the direct billing and usage dependencies relevant to `semantic_worker.ts`; they do not by themselves complete the worker's decision persistence/provider/action path, all callers of `billing.ts` or `polarsh.ts`, general Polar event ingestion, plan/checkout/recovery APIs, usage backfill/reporting, or the total Rust migration. Any implementation should first bind its source oracle to the accepted `55bd0bb` billing capture and resolve the missing immutable API candidate source snapshot before asserting parity with the tested API image.
