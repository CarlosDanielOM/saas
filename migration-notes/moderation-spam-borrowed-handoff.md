# Spam borrowed read-view handoff

The ordinary JSON settings and contextual rule APIs now expose read-only views. Normal array inputs and the static defaults are borrowed; string spread allocates its source code points. Unknown values, UTF-16 and threshold values remain lossless. Context views retain the shared template and its examples, and only construct an owned JSON tree on projection. Existing owned APIs project the same view. This is a separate representation from the legacy owned benchmark; owned JSON still cannot express JavaScript mutable reference identity. Template-owned mutable arcs are shared and projection snapshots them when called.

The invitation path uses compiled byte regexes for ASCII strings and retains the existing Unicode 17 fold and matching path for all non-ASCII and lone-surrogate text. The ASCII whitespace class is precisely the ASCII subset of JavaScript whitespace; original controls are never remapped. Non-broadcaster messages are skipped before conversion and string messages are read directly.

`benchmark_borrowed_sample` validates all 160 prepared outputs before measurement, retains typed results for three warmups and the timed run, and projects/checksums only after timing. It reports `representation: borrowed-read-view`; `benchmark_sample` remains the owned baseline. Source fixture replay also projects the borrowed views. The oracle covers 1,636 pure and 37 async records, including the expanded stress cases.

The borrowed matched run `node-1793341268777902038` passed seven alternating pairs for five workloads, with all 70 actor records and checksums independently verified. Borrowed Rust medians were lower than Node in all workloads. Observed min/max ranges did not overlap for settings, review policy or marker; invitation and rule context ranges overlapped, so no clear repeatable advantage is claimed for those workloads. This is not a significance analysis. The final production readback confirmed 18 production records unchanged and zero task-owned containers, networks or volumes remaining.

The measured API is the read-only view. Materializing owned JSON, output checksum, serialization and destruction are outside the timed interval. Node returns JavaScript objects/arrays; the old Rust baseline builds deep owned JSON. Existing callers that request `to_owned_json` still pay the materialization cost, so this helper benchmark does not establish end-to-end caller speedup.
