# Lossless UTF-16 boundaries for TTS normalization — 2026-10-28

This follow-up closes the earlier TTS normalization gap for valid UTF-8 inputs whose UTF-16-indexed slice splits a surrogate pair. Rust now keeps the sliced code units in `JsString` and preserves them through JSON serialization and the Node UTF-8/BSON boundary. The TTS normalization entrypoints still take Rust `&str`; arbitrary ill-formed UTF-16 already present in a JavaScript input string is outside their input model. This work does not migrate Bits or Twitch callers, cut over production callers, or retire TypeScript.

## Implementation and parity evidence

[`JsString`](../dimabot/src/utils/js_string.rs) retains valid text as UTF-8 and uses a UTF-16 code-unit representation when a slice creates an unpaired surrogate. Its iterator avoids allocating a code-unit vector for ordinary traversal, and slicing has a direct ASCII path. TTS normalization and emote extraction carry this value through their UTF-16-indexed operations. The Rust fixture also checks that JSON encodes an unpaired unit as an escaped surrogate and models the Node UTF-8/BSON boundary replacing it with U+FFFD.

The implementation is commit `5f1c1c1f` (verified source tree SHA-256 `58017cad9f477975be038e1dc251ecb6550befc985e876b9f992e9131dbac173`), authored by GPT-6.1 Terra at high and reviewed by GPT-6.1 Sol at xhigh. The [Node source-oracle receipt](evidence/2026-10-28-utf16-tts/node-1793212201254161097-receipt.json) records 18 actual Node/BSON cases and 27 TTS source cases. Its normalization fixture includes a one-code-unit truncation of a supplementary character. The Rust TTS fixture preserves that leading surrogate code unit, and its raw-JSON test checks the expected escaped representation. Parent verification also confirmed source and harness hashes, fixture checksums, input lengths, iteration counts, and all seven benchmark samples match the receipts.

## Bounded performance sample

The raw paired results are [`tts-normalization-ts.json`](evidence/2026-10-28-utf16-tts/tts-normalization-ts.json) and [`tts-normalization-rust.json`](evidence/2026-10-28-utf16-tts/tts-normalization-rust.json). They report medians from seven samples for normalization plus a UTF-16 checksum; JSON serialization, I/O, provider work, and production request handling are excluded. Values below are microseconds per operation, rounded to three decimals.

| Fixture | Node 24.22.1 | Rust 1.99.1 release |
|---|---:|---:|
| ASCII | 10.524 | 5.501 |
| Unicode | 15.208 | 4.648 |
| Large text | 669.445 | 418.767 |
| Surrogate truncation | 11.155 | 1.484 |

The measured Node benchmark worker reports that TypeScript's compiler is absent from its module cache; preparation and source-oracle processes may load it. These are four prepared workloads on this harness, not a general application throughput or end-to-end TTS claim. The paired values are also shown in the [comparison chart](evidence/2026-10-28-utf16-tts/comparison.html).
