# Moderation variation schema handoff

The local Rust schema feature is implemented and validated against the pinned Mongoose source oracle. The model definitions, defaults, casts, indexes, BSON boundary, and raw MongoDB repository behavior are in [`moderation_variation.schema.rs`](../dimabot/src/schemas/moderation_variation.schema.rs). The feature gate is `moderation-variation-storage`; constructors do not connect or install indexes. Callers choose an explicit database and can install the declared indexes through the schema repository.

The actual TypeScript model source was executed with the pinned Node 24.22.1, TypeScript 5.9.3, Mongoose 8.24.2, and BSON 6.10.4 toolchain. The accepted oracle has 42 model/input cases and matching full BSON hex bytes. Rust replayed all cases, and an isolated private MongoDB fixture exercised CRUD and index installation. See the [evidence bundle](evidence/2026-10-30-variation-schema/README.md), [verification summary](evidence/2026-10-30-variation-schema/verification-summary.json), and [source bindings](evidence/2026-10-30-variation-schema/source-bindings.json). The bundle retains each attempt, the final production readback, and all ten run receipt/log pairs from the final correction sequence, including both failed checks.

The final validation used source tree `ecf01f50421602aec6dba6f7ccf9811e47691816a1817fbca8185b3f7756af83`, bound to code commit `3b5b92b6040e622f47467299db6eed76242951f8`. Of 1,406 source inputs, 1,396 were individually verified against that Git commit; the ten unchanged `verification/posthog-rs/` inputs reuse the earlier verified binding documented in the linked source-bindings file. The capped compiler run passed scoped and all-feature/all-target strict Clippy, minimal and Mongo/Redis profile checks, two ordinary variation schema tests, application/additional/composite schema regressions, the 42-case Mongoose replay, and private Mongo CRUD/index checks. It took 103.2 seconds in the compiler phase and 114.658 seconds overall under 6 CPUs, a 4 GiB no-swap memory cap, 256 PIDs, and two Cargo jobs. Minimum available memory was 9,462,595,584 bytes and the private cache peaked at 6,449,954,816 bytes; startup required at least 5 GiB available.

The two retained failures identified and closed the observed parity gaps: an empty document `_id` string needed the shared truthy-string cast behavior, and an empty object nested in a Mixed array needed minimization. Mixed minimization is opt-in so other raw BSON data is preserved. The oracle does not establish parity for arbitrary JavaScript prototypes, hooks/getters, `undefined`, or sparse arrays.

Raw BSON repositories accept the missing, null, and Mixed shapes that Mongoose accepts. `VariationCache` and `VariationJob` are strict typed views of complete application values; they reject incomplete or otherwise valid raw documents and should not be used when those shapes must round-trip. See the [schema replay test](../dimabot/tests/moderation_variation_schema.rs) for the checked boundary.

This is local feature coverage, not total migration completion. Global dependencies and application callers remain incomplete, and caller adoption has not been validated. Production readback found 18 containers unchanged and zero task-owned resources remaining. No production deployment, push, TypeScript retirement, caller cutover, or performance benchmark occurred.
