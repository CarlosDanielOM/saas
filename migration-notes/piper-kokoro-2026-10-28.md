## Implementation and source contract

- `dimabot/src/server/services/tts/piper_tts.rs` implements both configured backends. A nonblank `PIPER_HTTP_URL` selects HTTP; otherwise the CLI path runs `python3 -m piper -m <voice> -f <output> [--data-dir <dir>] -- <text>`. The HTTP route posts JSON to `/synthesize`; success writes returned bytes to a WAV-named path and preserves the source's permissive behavior for empty bodies and arbitrary success MIME types. Non-success public requests expose the response body, while private requests cancel/discard it. Public error bodies have a 1 MiB safety cap. An explicit zero audio limit rejects nonempty HTTP audio; the source CLI truthiness quirk is preserved, so zero disables its post-write size check.
- `dimabot/src/server/services/tts/kokoro_tts.rs` validates the key, preset voice, and nonblank text, then makes one OpenRouter request using `hexgrad/kokoro-82m`, MP3 output, app attribution, and the source's DeepInfra-only provider constraints. It validates `audio/mpeg`, rejects empty audio, enforces the optional body byte limit, and writes returned bytes to an MP3-named path. There is no Together fallback. `KokoroConfig` redacts both credentials and endpoint in debug output. The borrowed `resolve_kokoro_voice_str` helper avoids cloning a wrapper while retaining the source's Unicode lowercase semantics.
- `http_support.rs` factors the existing Fish service's HTTP client policy, cancellation read, transport error formatting, and bounded audio stream reader. Piper and Kokoro use the same reusable injected `reqwest::Client` path as the Fish slice. Fish now uses these helpers and its compatibility tests were rerun. Its encoding benchmark and earlier AST, pure-helper, and date timings retain their original snapshots and were not rerun in this wave.
- Both providers honor private output paths and the shared public speech path contract. They serialize input through the JS-compatible string boundary where the source accepts UTF-16 strings. HTTP request text/voice values preserve UTF-16 JSON semantics; Piper CLI arguments cross the OS boundary as lossy UTF-8, matching Node's UTF-8 argument encoding. Invalid/unpaired surrogate cases and OS/process diagnostics are documented as normalization boundaries rather than exact byte-for-byte diagnostic parity.

## Wait and cancellation review

The retained provider waits represent source deadlines, not a new cadence: Kokoro keeps its 20-second attempt deadline and Piper keeps its 30-second CLI deadline. Piper HTTP uses one 30-second total native request/body budget. The TypeScript fetch signal is created with a 30-second deadline and remains attached to the response body, so the nested stream reader's later timeout does not establish a 60-second total budget. The actual-fetch plus source-reader loopback probe confirmed this: the original 150 ms signal aborted the body at 155 ms despite headers arriving at 98 ms and the reader's later 150 ms timeout; a control response completed at 56 ms with headers at 27 ms and bytes `01 02 03`. This is one functional timing probe, not a benchmark, source timeout bug, or full Piper service probe.

Piper CLI cancellation/timeout gives the live process a 100 ms TERM grace before KILL, then waits for the direct child. After process-group termination, stderr collection has a separate 100 ms EOF cleanup grace (also on normal root exit) and is explicitly aborted and awaited if it does not finish. These are bounded shutdown cleanups, not synthesis polling intervals. The dedicated process group kills descendants; eventual descendant reaping belongs to the host init. The isolated check confirmed the direct child is reaped and no live group member remains; the implementation does not install a global SIGCHLD handler or process-wide subreaper. No artificial sleep or cadence was added.
