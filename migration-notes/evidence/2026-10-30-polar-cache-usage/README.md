## Verified scope

The final actual-source corpus has 32 records and SHA-256 `c54a4e0a61f9dc04b1230e932ca37f95ee50afcec2c1d14db0ac860e6eb501b1`. All three retained corpus outputs are byte-identical. The final compiler run passed one ordinary Rust test and four ignored fixture tests, with scoped, minimal, Mongo/Redis, and all-feature strict validation. The private Redis replay exercised normalized I/O, logger, receipts, analytics, changed-owner atomic release, and an applied Polar `RPUSH` response-loss case that observed one write and one release attempt. The run used six CPUs, a 4 GiB memory/no-swap limit, 256 PIDs, and two Cargo jobs; compiler/fixtures elapsed 116.913 seconds and total phase elapsed 127.794 seconds. The exact-candidate evidence, including failed and superseded runs, is in [runs/](runs/); concise facts and production readback are in [verification-summary.json](verification-summary.json) and `artifacts/polar-cache-usage/`.

The branch reuses existing pricing/context construction, AI credit projection, receipt builder/enqueue, and PostHog tracking. The accepted owner release uses the existing atomic `ai_usage_lock` Lua script in place of source GET then DEL. The final contention sleep is capped to the remaining 2.5-second monotonic coordination budget. Source UUIDs, clock fields, Redis driver error wording, and the atomic release adaptation are explicitly normalized/documented; this is not a byte-for-byte replay of the complete source RPC trace. The lease governs queue migration/flush coordination, and its wait budget is not an end-to-end Redis RPC deadline.

## Limits and remaining work

This establishes only the cache-mode application branch. The source helper's billing/application wrapper, immediate and batch Polar HTTP ingestion, complete SDK/provider adapter, and semantic worker/caller adoption remain open. No TypeScript retirement, deployment, push, performance claim, or total migration completion is made. The concrete default logger covers cache and console sinks; automatic telemetry/OpenTelemetry attachment and lone UTF-16-surrogate diagnostic payloads remain outside the demonstrated adapter. High-level pending-charge recovery with a stable ID is distinct from replaying an ambiguous in-call `RPUSH` or EVAL result.

The archived `source-snapshot/` contains only the directly relevant Rust source, test, support adapter and actual-source fixture; reconstruct remaining Git inputs from the pinned commit. `reproduction-tools/verify_evidence.py` checks archive payload hashes and corpus identity without running application or toolchain code. The task-specific Polar freeze and launcher scripts, plus their current credit-reader/advanced freezer chain, validators, formatter, and final readback helper, are retained with the SHA-256 values recorded in `reproduction-tools/upstream-tool-provenance.json`. They were copied as static evidence and not executed for this docs-only task. The current `freeze_credit_reader.py` defaults exclude the unwired semantic worker and BSON JavaScript JSON adapter; the Polar wrapper enables the protocol and accounting inputs. The accepted historical 1,456-input binding remains the exact final compiler receipt plus the ten previously verified SDK inputs, independent of present-day freezer defaults. The SDK inputs are referenced by their prior verified hashes. [artifact-sha256.json](artifact-sha256.json) indexes every payload except itself; verify stored hashes before decompression and raw hashes as recorded in the input receipts. `runs/` retains compressed logs, including the failed 8 GiB cache-guard run. That guard stopped and cleaned owned containers at 8,607,584,256 bytes against the 8,589,934,592-byte limit. Cleanup removed only 29 task-owned obsolete private debug executables (891,744,256 bytes); it did not raise the cache limit or modify shared/source/immutable benchmark artifacts. The final cache measured 7,786,528,768 bytes. Production readback found all 18 production records unchanged and zero task-owned resources.
