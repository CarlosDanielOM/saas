## Scope

The five scheduled TypeScript worker entrypoints have been archived outside the application tree at [`archives/typescript-workers/2026-10-21`](../archives/typescript-workers/2026-10-21/README.md):

- `stream_activity.worker.ts` — stream activity projection.
- `raid_analytics.worker.ts` — raid analytics projection.
- `follow_defense_baseline.worker.ts` — follow-defense baseline projection only.
- `roulette.worker.ts` — roulette completion only.
- `ai_usage_receipts.worker.ts` — AI usage receipts consumer.

[`manifest.json`](../archives/typescript-workers/2026-10-21/manifest.json) records base commit `2583ebae7914ac0d1f6988abe88e6d0bd4eb2d96`, each original path, archive path, and SHA-256. The archived bytes retain their original relative imports, but the archive sits outside the dimabot build and image and cannot run in place.

These five responsibilities always run through their native Rust binaries in both the Node cron runtime and `tsx` development. The former `STREAM_ACTIVITY_RUNTIME`, `RAID_ANALYTICS_RUNTIME`, `FOLLOW_DEFENSE_BASELINE_RUNTIME`, `ROULETTE_COMPLETION_RUNTIME`, and `AI_USAGE_RECEIPTS_RUNTIME` TypeScript selectors are retired; setting them no longer selects TypeScript. A failed native child is restarted as that Rust child by the existing supervisor. There is no manual selector, development default, silent fallback, or archive lookup at runtime. `cron:dev` with `CRON_WORKER_RUNTIME=tsx` requires all five Rust executables at the paths defined by native worker metadata under `/usr/local/bin/`; if a binary is missing or fails, the supervisor reports/retries that Rust child without substituting TypeScript.

The archive does not include other TypeScript cron workers, the follow-defense API/route/getter or shared calculation utility, raid producers and APIs, roulette APIs or `roulette-actions`, Polar backfill, AI receipt producers, shared utilities, or TypeScript parity fixture code used by existing suites. Those remain active. Some shared TypeScript helpers serve both APIs and parity fixtures; retained helpers and fixtures do not provide a scheduled worker runtime or fallback.

## Restoration boundary

The current Rust-only policy requires all five worker behavior suites plus the sixth [Rust-only cron retirement check](../ops/checks/rust-only-cron.mjs) on each cron candidate. That check asserts the retired entrypoints and runtime fallback are absent. An intentional future TypeScript restoration is a reviewed behavior change: manually copy the selected archive file to its recorded path, review the supervisor registration and corresponding tests, and revise the matching Rust-only retirement assertions so they test the new intended contract. Preserve the five workers' functional coverage, run the updated candidate checks, and use the normal candidate deployment workflow. The archive does not contain a runnable import graph at its archive location. No automatic restore command, runtime flag, fallback path, or quick restore script exists. A code-only cron deployment does not alter production environment configuration.

The sixth check runs the actual supervisor with `CRON_WORKER_RUNTIME=tsx` and all five former selectors set to `typescript`; it verifies the archive and TypeScript entrypoints are absent from the image, exercises native stream projection, and injects missing-binary/nonzero exits to confirm same-Rust restart behavior. Its six groups passed against the exact candidate image. It is distinct from the five worker-specific suites. Candidate coverage of API/request-time code remains syntax/source-reviewed only for this release; those API checks were not rerun as runtime suites, and no API deployment is in scope. Roulette's lazy settlement on API reads remains existing request-time behavior and is separate from the retired scheduled completion child.
