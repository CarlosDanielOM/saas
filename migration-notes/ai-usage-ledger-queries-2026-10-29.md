## Scope and reuse

This verified opt-in slice maps `loadAiUsagePacingHistory`, `loadAiUsageLedgerTransactions`, and their pacing/window interfaces from `dimabot/src/utils/ai_usage_ledger.ts` to `dimabot/src/utils/ai_usage_ledger_queries.rs`. It reuses the accepted ledger-state read adapter, receipt parser/classifier, existing daily/receipt schemas and native collections, shared BSON/date/Number/coercion helpers, and the caller-supplied Mongo client/pool. It adds no parallel collector, rollup, cache, worker, index installation, retry, polling, lock, or transaction. Daily pacing reads stored rollups over inclusive UTC day keys after state coverage; transaction reads preserve the source sort and materialize the full cursor before mapping so a late cursor error wins over earlier row-mapping failures.

The raw lean transaction carrier preserves all 16 own properties and distinguishes undefined, explicit null, wrapper and malformed legacy BSON values. Source evaluation order is retained for Date conversion, Number conversion, classification, truthiness shortcuts, and errors. The native Math.max branch explicitly preserves the V8 NaN sign bit found by the pinned diagnostic. Compatibility is bounded to declared identity/date inputs and ordinary lean BSON under Node's default promotion settings; executable accessors, custom prototypes, other promotion settings, malformed-wire decoder equivalence, and engine resource exhaustion are outside the claim.

The opt-in feature is `ai-usage-ledger-queries = [ai-usage-ledger-reads, ai-usage-receipt-parser]`. No crate package, lockfile, default feature, or deployed profile changed. This adapter is not full ledger migration: persistence, backfill/rebuild, model/bootstrap, API and caller adoption remain open. Existing callers remain TypeScript. No performance benchmark was run.
