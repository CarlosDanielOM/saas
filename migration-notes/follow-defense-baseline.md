## Reused sources and contract

The baseline was already calculated by `dimabot/src/utils/follow_defense_baseline.ts` and consumed by `dimabot/src/utils/follow_defense.ts`. It reads the existing `follow_relationship_ledgers`, `streamsessions`, and `follow_attack_logs` collections represented by the Mongoose schemas. The Rust projector reuses those collections and the existing Dragonfly due queue and per-channel cache; it creates no collection or index. This migration moves the scheduled aggregation into a supervised native child while preserving the existing JSON and cache behavior. The route, getter, API, bot, and TypeScript calculation remain the consumer and explicit rollback paths.

The projector uses the preceding **30 complete UTC days**, ending at today's UTC midnight. It groups follows and eligible completed offline streams by UTC day, and excludes days containing an `attack` mode record from both sources. `averageDaily = max(total ledger follows, total stream follows) / max(1, 30 - excludedDays)`. `averageStream = total stream follows / eligible stream count`, or `0` when there are no eligible streams. `attackThreshold` is `ceil(max(500, 2 × averageDaily, 2 × averageStream))` only when at least seven sample days and three eligible streams exist; otherwise the JSON field is present as `null`. A successful refresh writes `follow:defense:baseline:<channelID>` with a seven-day TTL and reschedules that channel in `follow:defense:baseline:due` for one hour later. A failed query keeps a 60-second retry score and the previous cache. The existing getter requests a refresh for missing or stale data, deduplicated for 60 seconds, and returns `null` after two days of staleness so lost cache data cannot lower a large channel to the fixed threshold.

The historical TypeScript worker polled at one-second intervals and had a 30-second watchdog. The native child is selected by the existing cron supervisor; ordinary tick/query failures remain in that child and retry through the queue receipt, while a process failure is handled by the supervisor's normal same-worker restart. `FOLLOW_DEFENSE_BASELINE_RUNTIME=typescript` was the historical configuration-based rollback selector and no longer selects the archived entrypoint. Native mode passes MongoDB and Dragonfly connection settings plus basic runtime variables to a child running as UID/GID 65534 when launched by root. It does not run two projectors together.

## Scheduler and health telemetry upgrade

The deployed baseline scheduler adds the following behavior. The contract is source-backed; candidate checks passed in `cron-240af282cb85`, and the bounded production acceptance watch passed.

- Backlog health is probed from the existing Redis due queue every 30 seconds, with a two-second timeout covering the Redis-only probe. A successful probe reports due-channel count and, when work is due, the oldest due age. Probe failures and unavailable values stay unknown; they do not become zero. Last-success age uses monotonic process time and remains unknown after startup until a channel refresh succeeds during that process lifetime.
- Empty-queue polling backs off by 1, 2, 4, then 5 seconds, capped at 5 seconds. A successful refresh resets the idle delay. Queue polling plus the following query time determines pickup delay, so the 5-second value is a polling bound, not a bound on end-to-end completion.
- Channels are processed sequentially in bursts of eight successful refreshes, followed by a one-second cooldown. Each channel still uses at most three concurrent read-only MongoDB aggregate queries.
- Per-channel phase timings are `queueMs`, `claimMs`, `ledgerMs`, `streamsMs`, `attacksMs`, `publishMs`, and `rescheduleMs`. A completed phase records its duration even when it fails. Cancelled or unreached phases are omitted. The three MongoDB query timings overlap because those queries run concurrently, so their sum can exceed elapsed refresh time.
- The admin view uses the existing process-health and queue-phase display. Phase rows describe parts of a refresh and are excluded from job and failure totals; missing health values remain unknown.
