# Moderation blacklist reference handoff

These are authored-only, unexecuted drafts. Copy the three test artifacts into an isolated read-only source snapshot (and keep generated output outside the repository); no source, fixture, benchmark or test was run. Parent must review and integrate with the final native API and build feature before validation. No claims of correctness, performance, deployment, or complete migration follow from this handoff.

The reference loads both entire pinned TypeScript sources with TypeScript 5.9.3 transpilation and real Node builtins; the only runtime import resolves to the actual compiled normalize module. AST evidence records imports, type-only status, exported declarations and function signatures. The schema import is type-only, and no Mongoose behavior is involved. The source and runtime export checks enforce the intended module boundary. Metadata records source pins, compiled outputs, required native/core/test files, Cargo/toolchain hashes, and the pinned Node/V8/ICU/Unicode/TypeScript versions and Node executable digest. Every listed native/core/test path must exist; generation fails if one is missing. Inspect and record any additional relevant paths in the frozen evidence. Hash the actual Rust test executable and all benchmark inputs externally in the coordinator, and record compiler version and image digest as well.

Run reference with `DIMA_BLACKLIST_SOURCE_ROOT` pointing to the isolated snapshot's dimabot directory, using the exact pinned Node binary and an existing empty absolute task-owned output directory: `node .../moderation_blacklist_reference.cjs --write DIR`; `--check DIR` reconstructs and requires exact bytes and only the expected file. Each input term/text, folded text, RegExp source, and matched text uses numeric UTF-16 units; metadata labels and flags are ordinary JSON strings. Null terms encode null/undefined compile input, null text exercises the nullish fallback, and null compiled pattern is explicit. The output also records direct exec on folded and raw strings, including UTF-16 start/end. Raw null text for direct exec uses the empty string. The typed input domain is optional vectors of strings, optional text and patterns produced by this compiler: this does not establish arbitrary external JavaScript RegExp support. `advanced.ts` constructs its own folded string with character-wise offset mapping before executing the literal; raw exec cases probe engine behavior but do not validate that full caller's offset mapping.

The corpus includes the seven existing test groups, stable ties and duplicate terms, whitespace-based alternation priority, greedy whitespace, escaping, direct Unicode case folding (including U+0345), astral and malformed UTF-16, plus varied boundary combinations. Unicode 17 property membership and each intended branch still require evidence review against the generated outputs; an empty match or absent category is not proof of intended coverage. Review the Unicode 17 examples against the shared pinned property tables.

Benchmark generation uses a separate empty task-owned directory and `moderation_blacklist_benchmark.cjs --write DIR`, then exact `--check DIR`; this generates one input file with complete source-derived expected outputs. For each named suite `short`, `long`, `many`, `unicode`, run one actor sample at a time with identical fixture and iterations. Node uses `--sample SUITE`; Rust uses the ignored test with `DIMA_BLACKLIST_BENCH_SUITE=SUITE`. Both use `DIMA_BLACKLIST_BENCHMARK_FIXTURE`, `DIMA_BLACKLIST_BENCH_ITERATIONS`, and `DIMA_BLACKLIST_BENCHMARK_SHA256` containing the independently computed lowercase input digest; each refuses a mismatch. Both prepare patterns outside the timer, prevalidate complete outputs, perform three full workload warmups within each sample process, time evaluation including folding, retain results through each pass and drop warmup results before timing, compare all measured outputs and compute the same FNV-1a-style UTF-16 checksum after timing. Each reports warmups, input hash, operation count, and checksum. The Rust test requires sha2 enabled in the selected feature configuration. Keep total iterations bounded to avoid memory pressure, and choose the same count for both actors within each workload. The Node sample additionally emits SHA-256 of the fixture, executable, and full projected result sequence. The coordinator must independently hash the fixture and Rust executable, verify actor metadata, operation counts and checksums, and fail on any mismatch.

Coordinator requirements: perform seven measured Node/Rust pairs per workload, alternating which actor starts each pair; each invocation performs its own three full warmups in-process. Run sequentially under the repository's production-host isolation, hard resource caps, and no-swap policy, recording samples individually and environmental/load evidence. Validate both actors and the full reference suite before timing; repeat preparation outside every timer. Record complete source, compiled, native, Node and Rust executable hashes, pinned toolchains, test image, exact command lines, iteration counts, and fixture hashes. Report each workload independently and the raw samples; do not aggregate heterogeneous workloads or claim speedup without measured evidence. This is a runner design, not generated timing evidence. The parent should check that the Rust runner compiles with the final feature configuration and that both runners' output protocols match before executing samples.

## Paired coordinator

`tools/blacklist_paired_coordinator.cjs` is a parent-only unexecuted draft; use only after functional parity and an isolated capped validation environment are established. It uses the current integrated runners, not the older authoring copies. Invoke with the exact pinned Node executable. Supply all of these explicit environment variables:

- `DIMA_BLACKLIST_PAIRED_SOURCE_ROOT`: absolute isolated `dimabot` source root; its parent is the receipt manifest root.
- `DIMA_BLACKLIST_PAIRED_NODE`, `BINARY`, `FIXTURE`, `PROVENANCE`, `RECEIPT`, `BUILD_LOG`: absolute paths for the pinned Node executable, exported Rust test executable, generated benchmark JSON, exporter provenance JSON, successful compiler receipt JSON, and Cargo JSON-lines build log. Each shorthand has the same `DIMA_BLACKLIST_PAIRED_` prefix.
- `DIMA_BLACKLIST_PAIRED_REPORT_DIR`: absolute nonexistent output directory outside the workspace and fixture directory, with an existing parent.
- `DIMA_BLACKLIST_PAIRED_ITERATIONS`: identical iteration count per sample, from 1 through 100000.
- `DIMA_BLACKLIST_PAIRED_NODE_SHA256`, `BINARY_SHA256`, `FIXTURE_SHA256`, `PROVENANCE_SHA256`, `RECEIPT_SHA256`, `BUILD_LOG_SHA256`, `ORACLE_SHA256`, `NODE_BENCHMARK_SHA256`, `TYPESCRIPT_SHA256`, `TYPESCRIPT_PACKAGE_SHA256`, `SOURCE_TREE_SHA256`: independently checked lowercase SHA-256 pins for the indicated files and canonical receipt source manifest. Node SHA must additionally equal the strict pinned executable. Oracle and benchmark paths are under the source root; TypeScript paths are `node_modules/typescript/lib/typescript.js` and `node_modules/typescript/package.json`.

The coordinator checks the full receipt source manifest against current mounted bytes, requires relevant inputs in that manifest, verifies schema-style exporter provenance, successful Cargo log, release test profile, musl target artifact path, and static x64 ELF without interpreter or dynamic dependencies. Static ELF alone cannot establish libc identity; musl is bound to the reported Cargo target path and compiler provenance. It independently recomputes each expected pool checksum from fixture evaluation units, then records seven alternating sequential pairs per suite. Each fresh actor performs three full warmups internally. It saves bounded raw output, commands, checksums, per-suite metrics and before/after hashes to a new exclusive report directory; each invocation has a 120-second deadline and a 1 MiB per-stream cap. On a failed validation it records a failed report and exits nonzero; the parent must inspect the report and independently verify the host/resource isolation evidence. No benchmark result or performance conclusion has been generated.
