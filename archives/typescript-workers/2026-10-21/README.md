# Retired TypeScript worker entrypoints

This archive preserves the six previously accepted TypeScript worker entrypoints and the dashboard-activity entrypoint removed from the cron source tree. Their original paths, source digests, and base commit are recorded in [`manifest.json`](manifest.json).

The archived files preserve their original bytes and import paths. They are historical source only: the archive is outside the application build and Docker image, and its files are not executable in place. The first six responsibilities use native Rust binaries in both the Node cron runtime and `tsx` development; raid sessions passed eight exact-image suites (102 groups) and production acceptance on candidate `cron-7a8ca7924412`. Dashboard activity is deployed as the seventh native child in `cron-bf400acbc441`; all twelve same-image suites passed. Its 32-sample, 332.216-second production watch, final readbacks/comparisons, and cleanup passed; all seven workers are release-accepted. Former `*_RUNTIME=typescript` keys are retired only for workers that historically had those selectors; no `RAID_SESSIONS_RUNTIME` selector existed and similarly named fixture keys are ignored. Native startup or process failure is handled by the supervisor's same-worker Rust restart, with no TypeScript fallback. The current source declares seven native binaries for `cron:dev` with `CRON_WORKER_RUNTIME=tsx`; the deployed dashboard image has no TypeScript fallback.

`cron-bf400acbc441` passed nine then-run standard exact-image suites (150 groups) plus three candidate-specific supplemental legacy cron checks (four reported groups). These are historical acceptance results, not a standing suite-count requirement; future coverage is scoped to changed workers and concrete impact on existing workers, with startup/health checks for all workers after cron replacement. The 32-sample, 332.216-second production watch and final cleanup passed. The coordinated email-template check is specific to `cron-9ff771d91cda`. To intentionally restore a TypeScript worker, manually copy its original file to the recorded path, review supervisor registration and tests, and revise matching Rust-only retirement assertions. Preserve functional coverage for changed behavior and verify the candidate before deployment. There is no automatic archive restore command, selector, fallback flag, or quick restore script. See [`migration-notes/typescript-worker-retirement.md`](../../../migration-notes/typescript-worker-retirement.md) and the [dashboard migration record](../../../migration-notes/dashboard-activity.md).
