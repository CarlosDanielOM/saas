AST is the advanced layer behind custom commands. It lets one command remember values, make decisions, call functions, and run other commands. Use it when a fixed reply is not enough.

<Aside type="caution">
This section is for advanced setups. If a fixed reply is enough, start with [Commands Overview](/commands/overview/).
</Aside>

## Do you need AST?

A command message is plain text by default. Once it uses an AST prefix (`$(`, `%(`, `*(`, `^(`, `%del(`, or `#(`), that part runs as AST.

| Plain text is enough when... | Use AST when... |
|------------------------------|-----------------|
| The reply never changes | The reply has a number that changes, like a counter |
| You only need a link or a fixed sentence | You need to remember something between uses |
| | You need if/else logic, a random pick, or a loop |
| | You want the command to call a function or another command |

**Plain text** (no AST):

```bash
Join our Discord: example.com/discord
```

**AST** (a counter that changes each time):

```bash
*( ^(#wins) ? %(#wins *(%(#wins) + 1)) : %(#wins 1) ) $(user) has %(#wins) wins!
```

What it does:

1. Checks whether `#wins` exists.
2. If it exists, adds 1 to it. If not, creates it with `1`.
3. Prints the updated total, such as `Carlos has 3 wins!`.

<Aside type="note">
`#wins` is a cache variable. It expires 24 hours after its last change. For a count that must last, use a database variable (`*wins`), which needs Premium or Pro.
</Aside>

## Important: variables are not built in

DomDimaBot does **not** create AST variables for you.

- You create a variable by writing it: `%(name value)`.
- Context data comes from **functions** like `$(user)` and `$(twitch.game)`, or from **arguments** like `&p1`.

```bash
%(#wins *(%(#wins) + 1)) $(user) now has %(#wins) wins!
```

## What AST is for

- save counters and user progress
- build replies that change
- run if / else logic
- work with lists and loops
- call Twitch, moderation, availability, TTS, roulette, trigger, and EventSub functions
- schedule delayed AST actions that survive bot restarts
- chain commands together

## Quick mental model

Think of AST commands as small scripts inside a custom command.

- `%(...)` = read or write your own variables
- `%del(...)` = delete a variable or list item
- `$(...)` = call a function
- `*(...)` = compute logic, or run a loop
- `^(...)` = check whether something exists
- `#(...)` = run another command from this command

## Plan-aware features

Some AST features depend on the streamer's plan.

| Feature | Free | Premium | Pro |
|---------|------|---------|-----|
| Memory variables | Yes | Yes | Yes |
| Cache variables (`#`, `##`) | Yes | Yes | Yes |
| Database variables (`*`, `**`) | Writes are ignored | Yes | Yes |
| Loops nested inside each other | 2 | 3 | 4 |
| Passes per loop | 25 | 50 | 100 |

<Aside type="note">
Database variable writes require Premium or Pro. Cache values expire 24 hours after each write. See [Variables and storage](/commands/advanced/syntax/#variables-and-storage) for details.
</Aside>

## Recommended workflow

1. Start with a plain text response
2. Add arguments like `&p1`
3. Add functions like `$(user)` or `$(twitch.game)`
4. Add variables only when you need state
5. Add conditionals and loops last

<Aside type="tip">
If an AST command can ban users, grant roles, change title/game, start polls, or trigger media, keep it restricted to moderators or the broadcaster.
</Aside>
