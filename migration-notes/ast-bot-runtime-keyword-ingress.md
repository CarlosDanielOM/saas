# AST keyword ingress — lane F authoring handoff

This is unexecuted authoring, not an acceptance or migration-completeness claim. Sources: `dimabot/src/handlers/keywords.handler.ts`, the keyword branch and authorization union in `dimabot/src/handlers/commands.handler.ts`, `dimabot/src/utils/keywords.ts`, and the existing native keyword cache, fresh keyword-state adapter, command executor and delivery module. The cache index/body and delivery implementations are reused; the missing handoff was a command entry point accepting the body already resolved by ID. Cached bodies are configuration only. The existing fresh keyword-state read remains after cooldown acquisition.

Public entry points:

```rust
pub fn execute_command_with_body<'a, S: CommandStore + 'a, P: AstBodyParser + 'a>(
    store: &'a mut S, parser: &'a mut P, request: &'a CommandReference, raw: JsonValue,
) -> BoxFuture<'a, Result<CommandExecutionResult, AstRuntimeError>>;

pub async fn handle_keywords<C: KeywordIngressCache, S: CommandStore, P: AstBodyParser, T: ChatSender>(
    channel_id: &str, event: &KeywordChatEvent<'_>, bot_account_id: &str,
    identity: &JsValue, effect_context: Option<EffectToken>, cache: &C,
    store: &mut S, parser: &mut P, sender: &mut T, logger: Option<&Arc<Logger>>,
) -> Result<(), AstRuntimeError>;
```

`KeywordChatEvent` contains borrowed `chatter_user_id` and `text` plus the original `event_data: JsValue`; the caller must extract the first two from that same event. The cache seam is implemented by `NativeKeywordCache`. The handler creates source-equivalent initial command-reference state, preserves the whole text as argument and chat authorization, and invokes the shared executor and delivery path. Callers must provide the configured bot account ID. No module initialization connects to services.

## Test status and gaps

`dimabot/tests/ast_keyword_ingress.rs` contains in-memory filtering, body handoff, argument, fresh count, permission, bot, and cooldown-result delivery checks. `dimabot/tests/fixtures/keywords_handler_reference.cjs` transpiles and loads the real keyword and command handler sources, runs the real keyword handler and matching helper with executor/cache/delivery seams mocked, and supports `--write DIR` / `--check DIR`. The ignored Rust oracle test reads `AST_KEYWORD_ORACLE` generated by that fixture and checks its observable contract; this currently compares both suites to the same expected outputs rather than directly serializing native observations. The fixture loads the real command module but mocks its execution in the ingress scenario.

Ignored private-service tests require a separate execution lease and explicitly task-owned loopback services and a unique `ast_ingress_test_...` database. They are authored to exercise real Mongo legacy fallback including the `_id` tie-break, the empty-string tombstone, the duplicate-login-index retry, and real keyword cache count persistence/readback with private Redis. The resource owner must provision and clean the database and Redis namespace. Loopback and database-name assertions are guardrails, not proof that an endpoint is disposable; verify ownership before running. The legacy fixture uses the same timestamp for its two documents, so an additional differing-timestamp case would strengthen the sort check.

**Remaining blocker:** the requested real `NativeCommandStore::acquire` Redis `SET NX PX` contention and expiry integration test has not been authored. It needs construction of the real command store and its required directory/command collaborators under a private Redis lease; the in-memory cooldown check does not prove Redis behavior. Direct native-to-oracle comparison, comprehensive error and ordering cases, compilation, formatting, and all test execution remain outstanding. The shared runtime/feature wiring and actual chat caller remain integration dependencies. The private tests and fixture are not verified and may need correction after compilation or execution. No Cargo, formatter, test, Node, Docker, network, commit, push or deployment was run in this lane.

The ignored Mongo tests use the process-wide lazy client: execute each in a fresh test process so a client created on one Tokio runtime is not reused after that runtime shuts down. The handler currently skips a malformed cached body without a string `cmd`; the TypeScript schema expects a string and its helper would throw on a malformed value, so malformed-body parity remains unresolved.
