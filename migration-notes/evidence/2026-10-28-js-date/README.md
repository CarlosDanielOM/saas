This evidence pack records the isolated V8 `Date.parse` port, including the initial UTC benchmark, the fast-path recheck, the final source-matched candidate, and a negative control. The feature's scope and supported timezone limits are in the [migration note](../../js-date-2026-10-28.md).

## Benchmarks

These are local synthetic measurements of the public Rust UTF-16 entrypoint plus checksum/valid-count work against prepared Node strings using the same cases and checksum work. Each workload had a 10,000-iteration warmup followed by seven samples of 100,000 operations; reported values are median microseconds per operation. Matching checksum, valid, and invalid counts were required before comparing elapsed time. There was no network, database, mock, serialization, production CPU, or RSS measurement.

The initial UTC candidate exposed libc timezone lookup overhead. Its exact per-workload outputs are preserved in the `js-date-node-before-utc-*.json` and `js-date-rust-before-utc-*.json` files. The first comparison (Node/Rust, µs/op) was ISO 0.154412/0.465472, legacy 0.157712/1.945191, invalid 0.116994/0.124535, and mixed 0.163004/1.052298. The post-UTC candidate added an explicit `TZ=UTC` fast path. Its intermediate raw results are in the `js-date-node-after-utc-*.json` and `js-date-rust-after-utc-*.json` files.

The final comparison is [js-date-comparison.json](js-date-comparison.json):

| Workload | Node (µs/op) | Rust (µs/op) | Rust / Node |
|---|---:|---:|---:|
| ISO | 0.15153045 | 0.17096845 | 1.1283× (12.83% slower) |
| Legacy | 0.15071521 | 0.13399589 | 0.8891× (11.09% less elapsed time) |
| Invalid | 0.12110956 | 0.13148971 | 1.0857× (8.57% slower) |
| Mixed | 0.17155715 | 0.16839724 | 0.9816× (1.84% less elapsed time) |

All four final workloads had equal Node/Rust checksums and valid/invalid counts. Preserve both measured regressions; the modest mixed-workload difference is not a statistical claim. Only UTC was benchmarked after the fast path, so no performance conclusion is available for other timezones. The earlier 17-call regression was addressed with the explicit UTC fast path; the parser keyword micro-optimization was not shown to create a material ISO gain, so no causal speedup is attributed to it. These fixture results are not production throughput or memory claims.
