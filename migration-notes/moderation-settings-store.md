## Reuse and source contract

The TypeScript loader uses `moderation:${channelID}:settings`, a 300-second Redis TTL, and exact no-settings sentinel `{"none":true}`. It consumes a full `findOne({channelID}).lean()` document. Defaults prime the cache after seeding; save routes invalidate it. The adapter reuses existing native defaults and spam projection, lossless JSON/UTF-16 handling, BSON-to-Node JSON conversion, and blacklist pattern compilation. The remaining gap was the concrete Redis/MongoDB coordination and the local compiled-pattern cache.

Rust accepts caller-owned `ConnectionManager` and `Database` clients, does no constructor I/O, and returns an `Arc<JsonValue>` with the original BSON `Document` retained after a cold MongoDB read. A cold result retains BSON Date/ObjectId/Long type information for future callers; cache hits follow the source JSON.parse representation. Defaults’ date values therefore have a known cold-read versus cache-hit distinction that caller integration must handle. Whole-document conversion preserves unknown fields. Borrowed property access and scalar version retention avoid a deep JSON object clone in the adapter; this is a structural reuse observation, not a comparative speed claim.

Redis command order follows the source. Invalidation deletes Redis before clearing compiled patterns and clears only after a successful reply. Priming clears patterns before SET. Empty or malformed cache content falls through to Mongo. A no-document SET-NX loser reads the winner and returns valid non-sentinel JSON or defaults. Database hits SET the full projected document before returning. Commands use one absolute deadline and an abort receiver. Cancellation or timeout after a mutation is sent leaves the outcome uncertain; the adapter never retries. The application caller still needs to log structured errors and implement the source handler’s fail-open policy.

Compiled-pattern behavior preserves cached `None`, UTF-16 rule IDs, number/string version distinctions, binary64 equality, and object/array reference identity. Same-version changed terms retain the original cached pattern, matching source behavior. The source map is unbounded; no eviction was added because recompilation after eviction could alter same-version matching. `remove_channel_patterns` and `clear_patterns` are explicit lifecycle operations, not an automatic bounded-cache policy.

## Boundaries and remaining work

- `lossless_json::parse_json` imposes a 128-level depth limit; over-depth cache payloads can fall through to Mongo even if native JSON.parse would accept them. The shared BSON converter rejects unsupported BSON shapes/types.
- The adapter takes typed UTF-8 channel IDs and UTF-16 rule IDs. A channel containing lone surrogates cannot be represented by `&str`; malformed JavaScript settings, terms, IDs, prototype behavior, and arbitrary runtime mutations still need an explicit caller policy and differential coverage.
- Cold-read BSON values are retained alongside a JSON projection; cache-hit values are parsed JSON. Defaults contain date values whose JS Date behavior is not reproduced by the projection alone.
- Compiled-pattern storage remains source-compatible and unbounded. Do not claim it is bounded or introduce eviction without a behavior contract.
- Global bootstrap, source cache acquisition failures, structured logging/telemetry, caller fail-open behavior, permissions, chat history, action execution, promotional moderation, seeding, and orchestration remain open. The TypeScript handler and its consumers remain active; there is no caller adoption, retirement, deployment, or release.
