# Flat Mongoose insert preparation handoff

The shared `SchemaDefinition::cast_flat_set_on_insert` helper prepares only flat equality filters and flat `$setOnInsert` documents for declared Mongoose model descriptors. It supports String, Number, Bool, Date, Mixed, and Array<Mixed> fields; applies upsert defaults; suppresses defaults for paths in the filter/update; uses the supplied clock for `Now`; strips unknown update paths; and reuses the existing field caster. It deliberately skips validators, save hooks, and minimization, preserving Mixed empty objects. When strict casting empties the update, it copies a nonempty filter into `$setOnInsert`, matching Mongoose `castUpdate`. The helper preserves input order and appends defaults in schema order.

Its bounded inputs exclude top-level BSON Undefined, operators, dotted paths, nested schema types, and implicit `_id`, version-key, timestamp, or middleware behavior. The moderation decision descriptor uses supported String, Number, Date, Mixed, and Array<Mixed> fields, with explicit array defaults and no version key or timestamp middleware. The pinned source oracle exercised 11 flat-upsert cases; fixture SHA-256 is `414a348a790317d92947959fd9a448dd544fb3dfd7286315ce98f290736432e8`.

`utils::bson_json` extracts the variation-job JSON conversion into a shared utility. `compiler_bson_json` is a lossy compiler projection: unsupported BSON types become empty objects, integers cross the JavaScript number boundary, and UTF-16 strings can be lossy on BSON output. Use it only for compiler-owned JSON-like fields. Raw BSON remains authoritative for Mixed and non-JSON values; callers preserve raw values and patch only the fields owned by the compiler. This helper does not establish general business-field semantics for unsupported BSON.
