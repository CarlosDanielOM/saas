## Source contract and reusable paths

The TypeScript schema exports `ModerationContextMessage`, `IModerationDecision`, and the `ModerationDecision` Mongoose model. The two relative imports are type-only: `IModerationRule` comes from channel moderation settings and `ModerationMatch` from advanced moderation. `mongoose` is the runtime dependency that constructs the exported model. The model uses `moderation_decision` (Mongo pluralized collection `moderation_decisions`), disables the version key, defines a TTL index on `expiresAt`, and defines compound indexes on `(channelID, createdAt desc)`, `(state, deadline, createdAt)`, and `(charge.status, createdAt)`.

The native path reuses `SchemaDefinition`, its field caster/default resolver, `SchemaRepository`, the shared BSON conversion core, and the existing channel moderation / advanced moderation native types. The specific remaining contract gap is general Mongoose model behavior and application-level use: a descriptor/repository is not a Mongoose document engine, and producer/worker/route behavior remains separately owned. The new flat insert-preparation method is deliberately narrower than Mongoose: it accepts flat equality filters and flat `$setOnInsert` documents over String, Number, Bool, Date, Mixed, and Array<Mixed> fields; skips validators, save hooks, and minimization; suppresses defaults when a path is already present; and retains Mixed empty objects. It does not implement top-level BSON Undefined, implicit IDs/version/timestamps, dotted updates, operators, or nested schemas.

The extracted `compiler_bson_json` path is only a compiler-facing projection for JSON-like data. It is lossy for some BSON values and is not a general Mixed-field replacement. Raw BSON remains authoritative; application code retains raw values and patches only compiler-owned fields. The supported decision descriptor field kinds are String, Number, Bool, Date, Mixed, and Array<Mixed>; unknown fields remain strict. The source Mongoose model itself is permissive for String-valued `mode`, `state`, and `verdict`, even where the TypeScript interface names string unions.

## Boundaries and open work

This evidence does not claim full Mongoose document/object identity, validators, save hooks, middleware, implicit ID/version/timestamp behavior, nested schema types, dotted/operator upserts, or arbitrary BSON conversion parity. The native `IModerationDecision` is a typed view of the model contract, not a whole-SDK representation; the native enum views are narrower than the runtime-permissive Mongoose String paths. `compiler_bson_json` is non-authoritative for raw Mixed and other non-JSON BSON. The decision producer/callers and broader application adapter remain open; their status does not change this bounded model evidence or make deployment a condition of migration completeness.
