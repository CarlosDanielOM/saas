# AST Syntax & Data

AST syntax reference: expression prefixes, variables and storage, arguments, escaping, arrays, operators, conditionals, loops, delete, command references, and timers.

Source: https://docs.domdimabot.com/commands/advanced/syntax/
Language: en
Documentation index: https://docs.domdimabot.com/llms.txt

This page is the reference for writing AST commands. New to AST? Read the [AST overview](https://docs.domdimabot.com/commands/advanced/index.txt) first.

## How a message is read

Only parts that start with a prefix are run. Everything else is copied exactly as typed, including quotes, punctuation, and emoticons.

```bash
Hi $(user)! Welcome to "the stream" :)
→ Hi Carlos! Welcome to "the stream" :)
```

Inside a prefix, the rules are different:

* A prefix runs until its matching `)`.
* Double quotes, `${ }`, and `%[ ]` arrays only work **inside** a prefix.

> caution:
>
> Writing `"$(user) has 2 wins!"` prints the quote marks too. Write `$(user) has 2 wins!` instead.

## Arguments

When a viewer runs a command, their words are available as placeholders. Word 1 is the first word after the command name.

| Placeholder            | Meaning                                       | Example                        |
| ---------------------- | --------------------------------------------- | ------------------------------ |
| `&p1`, `&p2`, `&p3`... | Word number 1, 2, 3...                        | `&p1` = first word             |
| `&t`                   | Everything from the last numbered word onward | `&t` = the rest of the message |

### Rules

* A word that was not typed becomes blank.
* `&t` takes the words after the highest `&pN` that appears before it.
* You may reuse a `&pN` after `&t`, but a **new** `&pN` after `&t` is an error: `[Parser error: cannot create new &pN after &t]`.
* In chat commands, what a viewer types is plain text. It cannot run AST code.

### Examples

```bash
Command: !greet Hello World
Message: Hello &p1 and &p2!
→ Hello Hello and World!
```

```bash
Command: !echo lots of args here
Message: &p1 &p2 &t
→ lots of args here
```

```bash
Message: &t &p1
→ [Parser error: cannot create new &pN after &t]
```

## Arrays

A list stores several values. A list can be read, changed, and counted.

### Adding and reading lists

```bash
%(items[] extra)
%(items)
→ ["extra"]
```

Reading a whole list prints it as JSON, such as `["a","b"]`.

### Literal lists

A literal list writes its values inline. It only works inside a prefix. Use `[]` to add its items to a list. A plain assignment stores the items as one comma-separated text value, not as a list.

```bash
%(colors[] %[red, green, blue]) %(colors)
→ ["red","green","blue"]

%(pick %[1, 2, 3][random]) %(pick)
→ 2 (a random 1, 2, or 3)
```

### Accessors

| Syntax            | Meaning                         | Example                    |
| ----------------- | ------------------------------- | -------------------------- |
| `%(arr[0])`       | Item by position, starting at 0 | `%(items[0])`              |
| `%(arr[-1])`      | Item counted from the end       | `%(items[-1])` = last item |
| `%(arr[random])`  | Random item                     | `%(items[random])`         |
| `%(arr[].length)` | Number of items                 | `%(items[].length)`        |
| `%(arr[] value)`  | Add an item at the end          | `%(items[] extra)`         |
| `%(arr[2] value)` | Replace the item at a position  | `%(items[2] updated)`      |
| `%del(arr[1])`    | Remove the item at a position   | `%del(items[1])`           |
| `%del(arr[])`     | Clear the whole list            | `%del(items[])`            |

A position that does not exist reads as blank. Replacing a position that does not exist does nothing.

### Examples

```bash
%(items[0])
%(items[random])
%(items[].length)
%(items[] extra)
%(items[1] replacement)
%(pick %[1, 2, 3][random]) %(pick)
```

## Command references

You can run one command from inside another:

```bash
#(othercmd arg1 arg2)
```

The words after the command name become its argument. The reference prints nothing in your message.

### Rules

* Commands can call other commands up to 5 levels deep.
* A command cannot appear twice in the same chain. Cycles are blocked.
* Up to 50 references can run for one message.
* Your message is sent first. Sibling references run in the order you wrote them; each one's nested references finish before the next sibling runs.
* Each referenced command sends its own reply. Its reply is not parsed again.
* A referenced command that cannot run is skipped, for example because it is on cooldown or disabled.

# Built-in commands

Default access, syntax, and behavior of DomDimaBot's built-in chat commands, such as !poll, !duel, and !vip.

Source: https://docs.domdimabot.com/commands/built-in/
Language: en
Documentation index: https://docs.domdimabot.com/llms.txt

Built-in commands are ready-made tools that come with DomDimaBot. Viewers and moderators type them in chat. Each one has a default **Who can use it** level and a cooldown, and you can change both. `!so` is an editable default custom command; see [Custom commands](https://docs.domdimabot.com/commands/overview/index.txt) for its access and editing rules.

Some built-in commands work as soon as the bot is on, and the bot adds them for you: `!s` (text to speech), `!commands`, `!cc`, `!ec`, `!dc`, `!enable`, `!disable`, `!clip`, `!promo`, `!amor`, `!sumimetro`, `!memide`, `!ponerla`, and `!mecabe`.

The rest need full access, such as `!so`, `!poll`, `!endpoll`, predictions, `!title`, `!game`, `!followage`, `!onlyemotes`, the `!vip` and `!mod` tools, `!clearchat`, `!vanish`, `!ruletarusa`, `!duel`, `!anuncio`, and the timer commands `!cct`, `!ect`, and `!dct` (timers start and stop with your stream). Until you click **Activate Bot**, the **Commands** page shows them locked with **Needs full access**. See [Getting Started](https://docs.domdimabot.com/getting-started/index.txt).

## Turn them on or change access

* **On the dashboard:** open **Commands**, find the **Built-in** section, and use the **On for chat** switch. Open a command to change **Who can use it**.
* **In chat:** moderators can use `!enable <name>` and `!disable <name>`. The name works with or without `!`.
* **Reserved built-in commands cannot be deleted.** Editable default templates, such as `!s` and `!followage`, can be edited or deleted.
* **Cooldowns:** most built-in commands wait 10 seconds between uses. The wait is shared by the whole channel. `!s` and `!vanish` have no wait.

New channels get `!s` on for everyone. When you activate the bot, `!clearchat` is added turned off. If you already made your own command with the same name, such as `!s` or `!so`, the bot keeps yours. Existing channels keep their saved settings.

In the tables below, **Everyone** means anyone in chat, **Mods and above** includes mods, editors, admins, and you, and **Editors and above** includes editors, admins, and you.

## Details

### Ruletarusa

* Each pull has a 1-in-3 chance of firing.
* A loss normally gives a timeout of 10 seconds. Each following loss adds 10 seconds: 20, then 30, and so on. One channel has a 300-second minimum. The count resets 10 minutes after the first loss.
* Editors and the channel owner can't play.
* A moderator who loses is removed as a moderator during the timeout and added back afterward.

### Duels

* `!duel <user>` challenges a viewer. The viewer has 30 seconds to reply with `!duel accept` or `!duel decline`.
* Challenging the streamer skips the reply. The streamer fights right away, with better odds.
* A loser gets a timeout when timeouts are on. The default is 60 seconds. Change this in **Widgets** → **Duel**.
* The streamer and editors are never timed out. A moderator who loses is removed as a moderator during the timeout and added back afterward.
* Duel messages use the language configured for the Duel widget on Premium and Pro. On Free, they use the streamer's account language until a Duel language is saved; after that, they use the saved widget language.

### Polls and predictions

* Separate the title, the options, and the duration with `;`. Separate options with `/`. Duration is in seconds.

  ```text
  !poll Will the streamer win?;Yes/No;60
  !predi Will the streamer win?;Yes/No;60
  ```

* Twitch sets the limits for title length, the number of options, and the duration. If Twitch rejects a request, the bot replies with Twitch's error.

* `!endpredi` uses the outcome number. `1` is the first outcome. The number must match an outcome.

* Each command needs an active poll or prediction. If there isn't one, the bot says so.

### Changing built-in settings with `!ec`

Moderators can change a built-in command's cooldown or access without the dashboard:

```text
!ec -cd=30 ruletarusa
!ec -ul=mod duel
```

Put the options before the name. Access and cooldown limits from [Custom commands](https://docs.domdimabot.com/commands/overview/index.txt) apply here too.

# Follow Defense

Detect bursts of follows from bots or hate raids, pause follow alerts, and ban tracked followers only when a wave becomes an attack.

Source: https://docs.domdimabot.com/follow-defense/
Language: en
Documentation index: https://docs.domdimabot.com/llms.txt

Follow Defense watches for sudden bursts of follows, such as follow bots or hate raids. When a burst starts, it pauses follow alerts and tracks who followed. It bans followers only when a wave reaches Attack mode. It runs in the background and is available on every plan.

Viewing Follow Defense needs the `moderation:view` permission. Changing settings, activating Attack, and banning raid followers need `moderation:manage`. The channel owner has both.

**Needs full access:** Follow Defense starts working once you activate the bot. You can set it up before that; the page shows a **Needs full access** note with an **Activate Bot** button. See [Getting Started](https://docs.domdimabot.com/getting-started/index.txt).

## Set it up

1. Open **Modules → Follow Defense** in your channel dashboard. Check the current mode and tracked followers.
2. Keep the defaults during a first observation period. Turn off **Enable Follow Defense** only if another tool already handles follow floods.
3. Set the **Silent** and **Protection** thresholds above your normal bursts. Leave **Attack threshold** empty for dynamic sensitivity, or enter a number.
4. Decide whether **Reset attack on new raid** should stay on. It is on by default.
5. If you add a `!defmode` command, restrict it to trusted moderators, because it can queue bans.
6. After an incident, review **Past waves** and any raid sessions, then adjust the numbers.

[![Follow Defense settings and current status for DemoStreamer](https://docs.domdimabot.com/guides/growth/follow-defense-en.png)](https://docs.domdimabot.com/guides/growth/follow-defense-en.png)

*Example thresholds and a quiet sample channel; no moderation action is running.*

## Modes

| Mode           | Starts when (defaults)                                               | What it does                                                                                                     | Bans?          |
| -------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------- |
| **Normal**     | No burst is active                                                   | Nothing.                                                                                                         | No             |
| **Silent**     | 10 follows within 5 seconds                                          | Pauses follow alerts and tracks the wave.                                                                        | No             |
| **Protection** | 100 follows in the 5-second window, or the tracked wave grows to 100 | Pauses follow alerts and tracks every follower. Outside a raid, posts a warning in chat. Can escalate to Attack. | No             |
| **Attack**     | The attack threshold is reached, or a moderator starts it            | Bans everyone tracked in the wave, and each new follow while Attack is active.                                   | Yes, permanent |

By default, each mode stays on for 60 seconds after the wave is refreshed by a burst of follows. You can change this shared duration in the settings. As an active wave grows, its tracked follow count can reach the Protection or Attack threshold even when those follows did not all arrive in one 5-second window. Each mode is checked on its own, and the highest qualifying mode wins: Attack beats Protection, and Protection beats Silent.

> caution:
>
> Bans from Attack are permanent Twitch bans, not timeouts. Outside a raid, only Attack bans followers. Protection and Silent never ban. A burst is a signal of unusual activity, not proof that every follower is abusive. Tune the thresholds to your channel, and review the tracked wave before you rely on automatic Attack.

## Attack threshold

Leave **Attack threshold** empty to use dynamic sensitivity. The threshold comes from your last 30 days of follows and completed streams. It is used only after your channel has at least 7 days of follow activity and 3 completed streams. The threshold is never lower than 500, and it can be higher for channels with a larger normal volume.

Until there is enough history, automatic Attack has no threshold and does not start from a burst. Silent and Protection still work.

To set a fixed threshold, enter a positive whole number. Use a fixed number only when you have a clear reason.

## Follow alerts

While Silent, Protection, or Attack is active, the bot holds back follow alert messages in chat. Each held follow is counted.

When the mode ends, the bot posts one summary, but only if follow alerts are on for the channel:

* Silent or Protection: `N additional follows were received while announcements were paused. Thanks for following!`
* Attack: how many announcements were blocked and how many accounts were banned so far.

Follow Defense does not change overlays or other integrations. Check those separately if they also show follow alerts.

A burst alone does not prove malicious intent. Attack history records the mode, whether a raid was involved, the follow totals, and the ban results.

## Raids

A raid session starts capturing associated follows for 5 minutes; each captured follow can extend that window by another 5 minutes. Sessions remain available in the dashboard for up to 72 hours. The minimum viewer setting applies to raid announcements; it does not decide whether Follow Defense records a raid session.

During a raid:

* Raid follows do not start an automatic Attack and are not banned by default. If **Reset attack on new raid** is off, an already active Attack carries over and can ban follows from the new raid.
* Follows are tracked in the raid session panel. Free channels can review sessions and followers. Banning a whole session from history requires Premium or Pro; banning one historical follower requires Pro. Free channels can still activate Attack while live protection is active.
* Protection can still start.

**Reset attack on new raid** is on by default. A new raid changes an active Attack to Protection. If you turn it off, an active Attack carries into the new raid, and that raid's follows can be banned.

A manual Attack during a raid marks the raid as a possible hate raid and queues the recorded raid followers for review. It does not guarantee immediate bans. The raider's channel can appear in **Hate Raid Sources**. That label is not proof of intent.

## Manual controls

* **Activate Attack Mode** starts Attack. You must type `ATTACK` to confirm.
* **Stop Attack Mode** resets the current mode to Normal.
* In chat, `$(bot.mode attack)` queues Attack, and `$(bot.mode status)` shows the current mode and the seconds left. When called by the bot personality through AI chat, both need moderator level (7) or higher. In a custom command, the command’s access setting controls who can invoke them. For example, a `!defmode` command can respond with `$(bot.mode attack)`; consider limiting it to trusted moderators.

## History

**Past waves** lists each time a mode started, newest first. For each wave you can see the mode, what started it, the total follows and their rate, whether a raid was involved, and how many were banned.

## Turn it off

Turning off **Enable Follow Defense** stops new decisions and stops holding back follow alerts. Existing history stays. Turning off Attack or Protection also cancels defense actions that are still pending.

If you depend on another bot or service for follow alerts or moderation, confirm how that tool behaves before you switch systems.

# Plans

Compare the Free, Premium, and Pro plans, including monthly AI credits, command cooldowns, upload and storage limits, and which modules each plan unlocks.

Source: https://docs.domdimabot.com/plans/
Language: en
Documentation index: https://docs.domdimabot.com/llms.txt

DomDimaBot has three plans: Free, Premium, and Pro. The channel owner's plan sets the AI credits, limits, and modules for the channel, including command cooldowns for every viewer. Check **Pricing** on the public site for the current offer before you subscribe.

## Monthly plans

| Plan    | Price shown on the site | AI credits per month |
| ------- | ----------------------: | -------------------: |
| Free    |                      $0 |               25,000 |
| Premium |                $6/month |              200,000 |
| Pro     |               $15/month |              800,000 |

Paid-plan credit allowances follow the active billing period. Free monthly refills restore credits used in the previous period, up to 25,000; unused allowance does not add extra credits. Purchased credit packs roll over; paid-plan recharge packs expire at the end of the applicable billing period. Your balance and reset date appear in **Credit usage** on the dashboard. AI features such as AI chat, memory processing, and speech or clip tools use the channel's credits. Use varies by feature and settings. To add credits without changing plan, use **Buy AI credits** in the profile menu.

See [AI assistants](https://docs.domdimabot.com/ai-assistants/index.txt), [Text to Speech](https://docs.domdimabot.com/tts/index.txt), and [AI personality](https://docs.domdimabot.com/ai-personality/index.txt) for the features that use credits.

## Limits

| Limit                                 | Free      | Premium   | Pro      |
| ------------------------------------- | --------- | --------- | -------- |
| Shortest command cooldown you can set | 5 seconds | 3 seconds | 1 second |
| Private Media Library storage         | None      | 250 MB    | 1 GB     |
| Largest single upload                 | 5 MB      | 25 MB     | 100 MB   |
| Stream Timeline availability          | 90 days   | 90 days   | 90 days  |
| Viewer snapshot retention             | 90 days   | 90 days   | 90 days  |

* One editable command per channel can have a cooldown of `0`. Otherwise, use at least your plan's minimum. Reserved commands cannot be changed to `0`, but existing zero-cooldown defaults such as `!vanish` keep that setting.

# Text to Speech

Set up the speech overlay, pick a voice engine, use the !s command and AST speech functions, and manage filters, queue limits, and AI credits.

Source: https://docs.domdimabot.com/tts/
Language: en
Documentation index: https://docs.domdimabot.com/llms.txt

Text to speech (TTS) reads messages aloud on your stream. Your viewers use the `!s` chat command, and your commands and channel point rewards can use AST functions. The audio plays through a browser source in OBS, so the stream hears it.

**Who can change it:** the channel owner, or an admin with `tts:manage`. Admins with `tts:view` can see the settings but cannot change them.

**Plans:** every plan includes every voice engine. Usage comes from your monthly [AI credits](https://docs.domdimabot.com/tts/index.txt#ai-credits-and-fallbacks).

## Set up the speech overlay

1. Go to **Modules → Text to Speech** and turn on **Enable channel TTS**.
2. In **Speech URL**, click **Copy URL**.
3. In OBS, add a **Browser Source** with that URL. Keep the source active while you want speech to play.
4. Check that the bot is on (the dashboard header shows **Bot in your chat**) and that the **Speech Chat** command (`!s`) is on under **Commands**. Then type `!s Hello chat!` in your chat to test it. `!s` works without activating the bot.

If the browser source is not connected, new speech requests are refused with the message "Speech overlay is not connected." Queued speech waits until the source reconnects.

## Choose a voice engine

Pick the engine in **Modules → Text to Speech → Voice**. The engine you pick is the default for `!s` and for `$(tts ...)`.

[![Settings, TTS active, Kokoro selected, English voice controls and save bar.](https://docs.domdimabot.com/guides/alerts/tts-en.png)](https://docs.domdimabot.com/guides/alerts/tts-en.png)

*Text to Speech settings in English, with Kokoro selected. DemoStreamer example data.*

| Engine         | Voices                                                                                         | Cost                                    | Voice tags |
| -------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------- | ---------- |
| **Piper**      | One English voice (Ryan, `en_US-ryan-medium`) and one Spanish voice (Ald, `es_MX-ald-medium`). | 1 credit per 50 characters, rounded up. | Removed.   |
| **Kokoro**     | Preset voices, for example `af_heart` (English) and `ef_dora` (Spanish).                       | 1 credit per 15 characters, rounded up. | Removed.   |
| **Fish Audio** | Cloned voices. Four built-in voices, plus any voice you find in the voice browser.             | 1.5 credits per character, rounded up.  | Works.     |

**Dima Voice** appears in the list as "Coming soon." You cannot select it yet.

### Piper

Piper uses the Ryan voice for English and the Ald voice for Spanish. The dashboard uses the channel's default language to choose between them.

Piper keeps working when your credits run out. Its usage can make your credit balance negative.

### Kokoro

Use Kokoro for a set of preset voices. Pick a default Kokoro voice in the dashboard, or choose one per command with `$(tts.kokoro voice_name text)`.

### Fish Audio

Fish Audio provides cloned voices. The four built-in voices are:

* `gojo` (Gojo)
* `rias_gremory` (Rias Gremory)
* `toji_fushiguro` (Toji Fushiguro)
* `carlos_bodoque` (Carlos Bodoque)

Fish Audio is the only engine that reads [voice tags](https://docs.domdimabot.com/tts/index.txt#voice-tags-fish-audio-only).

### Find and save Fish voices

Open **Find voice** in the Fish Audio section to search the voice library. Samples from Fish play for free. Generating a preview uses credits.

Click the star on a voice to save it as a **favorite**. A channel can keep up to 20 favorites. Then give a favorite a **nickname** so you can use it in commands:

* Use 1–40 letters, numbers, or underscores. Start with a letter.
* Nicknames are not case sensitive. They are saved in lowercase.
* Nicknames must be unique. You cannot use the names of the four built-in voices.
* If you do not set a nickname, DomDimaBot creates one from the voice name. For example, **Pinky Pie** becomes `pinky_pie`. If that name is taken, a number is added, such as `pinky_pie_2`.

Only owners and admins with `tts:manage` can save, rename, or remove favorites.

### Use a Fish voice in a command

For `$(tts.clone ...)` and its alias `$(tts.fish ...)`, the first argument is one voice key. Use a built-in key, a favorite's nickname, or a Fish voice ID. Names with spaces do not work here.

```text
$(tts.fish carlos_bodoque &t)
$(tts.fish bodoquin &t)
```

In the first line, `&t` is the text the viewer typed. In the second line, `bodoquin` is the nickname of a saved favorite.

`$(set.voice ...)` also accepts a favorite's full display name, including spaces.

## Chat command: `!s`

**Usage:** `!s <message>`

`!s` runs as a normal AST command. It reads the message with the channel's default engine and voice. The shipped **Speech Chat** command is on for everyone, with no cooldown.

The default template is:

```text
$(tts $(user) dice: &t)
```

So chat hears the viewer's name, then `dice:`, then the message. To change the wording, edit the **Speech Chat** command under **Commands** or from the TTS page. The language setting changes the voice, not the template text.

```text
!s Hello chat, welcome to the stream!
```

Chat messages go through the [message filters](https://docs.domdimabot.com/tts/index.txt#message-filters-and-limits) before they are read. If nothing readable is left after filtering, the request is refused.

**Cooldowns:** the Speech Chat command has a 0-second cooldown. Each channel can have only one editable command with a 0-second cooldown. Other commands must wait at least 5 seconds on Free, 3 seconds on Premium, or 1 second on Pro.

## AST functions

Use these in custom commands, timers, and channel point rewards. See [Advanced commands](https://docs.domdimabot.com/commands/advanced/index.txt) for how AST works.

| Function                          | What it does                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$(tts <message>)`                | Speaks with the channel's default engine and voice.                                                                                                                                                                                                                                                                                                                                                        |
| `$(tts.ai <message>)`             | Same as `$(tts ...)`.                                                                                                                                                                                                                                                                                                                                                                                      |
| `$(tts.speak <message>)`          | Speaks with Piper, even when another engine is the default.                                                                                                                                                                                                                                                                                                                                                |
| `$(tts.piper <message>)`          | Same as `$(tts.speak ...)`.                                                                                                                                                                                                                                                                                                                                                                                |
| `$(tts.kokoro <voice> <message>)` | Speaks with a Kokoro preset voice, such as `ef_dora`.                                                                                                                                                                                                                                                                                                                                                      |
| `$(tts.clone <voice> <message>)`  | Speaks with a Fish Audio voice. The first argument is a built-in key, a favorite's nickname, or a Fish voice ID.                                                                                                                                                                                                                                                                                           |
| `$(tts.fish <voice> <message>)`   | Same as `$(tts.clone ...)`.                                                                                                                                                                                                                                                                                                                                                                                |
| `$(set.voice <voice>)`            | Changes the channel's default Fish voice and makes Fish the default engine. Accepts a built-in key, a favorite's nickname, or a favorite's display name. The bot then posts "TTS voice changed to …" in chat. In AI personality chat it requires moderator access. In a streamer-authored command, the streamer chooses who can trigger it; set access carefully because this changes the channel setting. |

```text
$(tts Hello chat!)
$(tts.speak This uses Piper.)
$(tts.kokoro ef_dora Hola chat!)
$(tts.clone gojo Hello from Gojo!)
$(tts.fish carlos_bodoque &t)
$(set.voice my_favorite)
```

Functions that read viewer text, such as `&t`, work best in channel point rewards that have **Viewer must type something** turned on. See [Channel Rewards](https://docs.domdimabot.com/rewards/index.txt).

For `$(tts.status)`, `$(tts.connected)`, `$(tts.queue.length)`, and the skip, clear, and refresh controls, see [TTS status and controls](https://docs.domdimabot.com/commands/advanced/functions/index.txt#tts-status-and-controls).

### Queue and overlay behavior

* Speech plays in order, one item at a time, for each channel.
* The **Maximum messages waiting** setting counts the message that is playing now. With the default of 5, one message can play and four can wait.
* If the browser source is disconnected, new requests are refused. Messages already waiting stay in the queue and play when the source reconnects.
* A message that was interrupted by a disconnect is not replayed.

## Message filters and limits

Set these in **Modules → Text to Speech → Message limits**:

| Setting                            | Default | Range  | What it does                                           |
| ---------------------------------- | ------- | ------ | ------------------------------------------------------ |
| **Maximum characters per message** | 280     | 30–500 | Longer messages are cut to this length.                |
| **Maximum messages waiting**       | 5       | 1–20   | The queue size, including the message that is playing. |
| **Skip emotes**                    | On      |        | Removes emote names before reading.                    |
| **Links become \[link]**           | On      |        | Replaces links with `[link]` before speech.            |
| **Tidy extra spaces**              | On      |        | Collapses repeated spaces.                             |

The filters apply to chat messages and to AST speech. Tags are filtered before the length limit is applied.

## Voice tags (Fish Audio only)

Fish Audio can change how a line sounds when you add a tag in square brackets:

```text
!s [happy] Great stream today!
!s [whisper] [pause] Can you keep a secret?
$(tts.clone gojo [excited] Let's go!)
```

Owners and admins with `tts:manage` can turn tags on or off in **Modules → Text to Speech → Voice tags**. All tags are on by default. A tag that is off, or that the bot does not recognize, is removed before synthesis. Piper and Kokoro remove every tag and read the rest of the message.

The tags are:

### Emotions

`[happy]` `[sad]` `[angry]` `[excited]` `[calm]` `[nervous]` `[confident]` `[surprised]` `[scared]` `[worried]` `[disappointed]` `[curious]` `[sarcastic]` `[satisfied]` `[delighted]` `[upset]` `[frustrated]` `[depressed]` `[empathetic]` `[embarrassed]` `[disgusted]` `[moved]` `[proud]` `[relaxed]` `[grateful]` `[disdainful]` `[unhappy]` `[anxious]` `[hysterical]` `[indifferent]` `[uncertain]` `[doubtful]` `[confused]` `[regretful]` `[guilty]` `[ashamed]` `[jealous]` `[envious]` `[hopeful]` `[optimistic]` `[pessimistic]` `[nostalgic]` `[lonely]` `[bored]` `[contemptuous]` `[sympathetic]` `[compassionate]` `[determined]` `[resigned]`

### Voice and delivery

`[whisper]` `[shouting]` `[soft]` `[singing]` `[slow]` `[fast]` `[emphasis]` `[screaming]`

### Vocal sounds

`[laugh]` `[chuckle]` `[giggle]` `[cry]` `[sigh]` `[gasp]` `[inhale]` `[exhale]` `[sobbing]` `[groaning]` `[panting]` `[yawning]` `[snoring]` `[clear throat]`

### Pauses and effects

`[pause]` `[long-pause]` `[audience laughing]` `[background laughter]`

Some short forms also work. For example, `[anger]` means `[angry]`, `[whispering]` means `[whisper]`, `[laughing]` means `[laugh]`, and `[crowd laughing]` means `[audience laughing]`. Turning off a tag also turns off its short forms.

## Channel admin access

Channel owners always have access to TTS. For channel admins, the permissions are separate:

* `tts:view` lets an admin read the TTS settings.
* `tts:manage` lets an admin change the settings, save or rename favorites, and preview voices. It includes `tts:view`.
* `commands:manage` lets an admin edit the **Speech Chat** `!s` command. It does not give access to the TTS settings.
* `*` gives full access to TTS and commands.

You can combine these with `chat:admin`. For example, an admin can manage chat but only view the TTS settings.

## AI credits and fallbacks

AI credits are shared by all AI features on your channel. Each plan includes this many credits per month:

| Plan    | Monthly AI credits |
| ------- | -----------------: |
| Free    |             25,000 |
| Premium |            200,000 |
| Pro     |            800,000 |

Credits per message:

* **Piper:** 1 credit per 50 characters, rounded up.
* **Kokoro:** 1 credit per 15 characters, rounded up.
* **Fish Audio:** 1.5 credits per character, rounded up for each message.
* **Voice previews** use credits the same way as the engine they preview.

If credits run out or a voice cannot be generated, TTS switches to a fallback voice so speech keeps working:

* **Credits run out, Fish Audio or Kokoro requested:** Free plans switch to Piper. Premium and Pro plans use Kokoro.
* **Fish Audio or Kokoro fails to generate audio:** the message is read with Piper.
* **Credit status cannot be checked:** the message is read with Piper.

The voice you chose stays saved. Only the message that needed the fallback uses the fallback voice.

For your channel's settings in general, see the [dashboard](https://docs.domdimabot.com/dashboard/index.txt) guide.
