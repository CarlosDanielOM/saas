# Socket.IO: what the clients need, and the design

Second view by GPT-6.1 Sol (2026-11-11) on the plan for `dima-socketio`, kept as the input for that
package. Section 1 is the evidence, section 2 the options Sol weighed, section 3 the proposed design
and test list, section 4 what was wrong in the plan. Line references are to the reference at
`0c71108e`.

## Decision (lead)

**Own layer on `engineioxide`, limited to what the clients use.** Sol recommended a pinned fork of
`socketioxide` (option B) to avoid owning packet parsing, binary assembly, namespaces and
acknowledgements. Set aside, for these reasons: a fork that is never rebased is code we own anyway
(about 13,000 lines in three crates, with adapters, extractors and a MessagePack parser nothing
here uses); the changes recovery needs go through its socket construction and adapter, the parts a fork
would have to rewrite; and section 1 shows the clients use a small part of the protocol: text events
and acknowledgements only, no rooms, no binary payloads, no broadcast flags. Binary packets are
refused, so there is no attachment assembly to own. Engine.IO (polling, WebSocket, upgrade,
heartbeat), where most interoperability risk lives, still comes from `engineioxide`.

Taken from Sol as written: recovery only for the namespaces that have it today and only for the
events the reference would have stored (section 4, points 1 and 2); ASCII-only namespace matching with
admission before allocation; the vendored `/socket.io/socket.io.js`; every Engine.IO limit set
explicitly; hard bounds on sessions, replay buffers and queues (section 3; the numbers are starting
values); the test list against `socket.io-client` 4.8.3 and 4.7.5. If the worker finds `engineioxide`
cannot carry this, the fallback is option B, decided before more is built.

The raw WebSocket endpoint `/v1/desktop/ws` (section 1, point 23) is not part of this crate; it comes
with the API's desktop package on the upgrade contract of `dima-web`.

## 2. Options (Sol)

1. **Choose B: socketioxide with a targeted, pinned fork.** Keep `dima-socketio` as the application-facing wrapper. Replay is needed in some retained clients, but that does not justify independently owning parsing, binary assembly, namespace lifecycle and acknowledgement machinery. This is an engineering judgement, not a measured implementation result.

2. **A—own layer on engineioxide:** highest effort and broadest correctness/security risk. Engineioxide supplies transport mechanics, while Socket.IO still requires multiplexing, packets, acknowledgements and binary reconstruction. The plan is more work than the demonstrated clients need. Relative estimate: **large**, including substantial interoperability hardening. Sources: [Engine.IO protocol](https://socket.io/docs/v4/engine-io-protocol/), [Socket.IO protocol](https://socket.io/docs/v4/socket-io-protocol/).

3. **B—add exactly these pieces:** private recovery IDs and CONNECT fields; session restoration and disconnect eligibility; eligible-event offsets and replay routing; replay/live ordering; middleware/recovery policy; expiry and memory bounds; structured CONNECT_ERROR data. **An adapter alone cannot do this:** 0.18.7 constructs the socket and `{sid}` response internally, keeps transport send methods private, and stringifies middleware errors. Public dynamic namespaces use path patterns, requiring explicit JS-equivalent name validation. Relative estimate: **medium-to-large**, with ongoing fork maintenance. Sources: [`ns.rs:101–147`](https://docs.rs/socketioxide/0.18.7/src/socketioxide/ns.rs.html#101-147), [`socket.rs:307`](https://docs.rs/socketioxide/0.18.7/src/socketioxide/socket.rs.html#307), [`socket.rs:735`](https://docs.rs/socketioxide/0.18.7/src/socketioxide/socket.rs.html#735), [`io.rs:480`](https://docs.rs/socketioxide/0.18.7/src/socketioxide/io.rs.html#480).

4. **C—no protocol recovery:** smallest transport effort, but presently loses legacy replay behavior. Application replay can serve these clients without changing their JS library, yet matching individual reconnect progress needs an identity/cursor the legacy clients do not provide; unconditional recent-event replay risks duplicates. C becomes preferable if those clients are explicitly migrated to IDs, receipts and snapshots. Existing Studio provides a reusable application model, but extending it is additional feature work: `dimabot/src/overlays/live.ts:664`, `dimabot/src/overlays/live.ts:678`.

## 3. Design and verification (Sol; module names apply to either option)

1. **Modules:** `transport` for Engine.IO integration/settings; `namespace` for registration/admission; `auth` for typed handshake policy; `emit` for direct/broadcast/ack routing; `recovery` for sessions and replay; `limits` for accounting; `lifecycle` for shutdown. Feature handlers remain outside the protocol crate. This follows the dependency direction and owned-task rules in `dima-rust/MIGRATION.md:138`.

2. **Proposed bounds—all sizing remains unverified against production load:** 4,096 concrete namespaces, 8 namespaces per Engine.IO connection, 4,096 Engine.IO connections globally; 64 connections per verified client address. Apply separate trusted-proxy handling before address limits; never trust arbitrary forwarded headers. Preserve tighter existing authenticated caps: two desktop connections/session, 16 pet peers/owner and 1,024 pet peers globally. Existing caps: `dimabot/src/pets/socket.ts:61`, `dimabot/src/pets/socket.ts:70`, `dimabot/src/desktop_ai/activity.ts:302`.

3. **Replay state:** per-namespace ordered deque plus offset index; store immutable event arguments, target rooms/exclusions, offset and monotonic expiry. Hard limits: 120 s, 4,096 events and 8 MiB per namespace; globally 32,768 events/64 MiB, whichever limit arrives first. Evict oldest records; a cursor older than retained history causes fresh connection, never partial “successful recovery.” Proposed policy follows [SessionAwareAdapter’s restore/broadcast semantics](https://github.com/socketio/socket.io/blob/socket.io%404.8.3/packages/socket.io-adapter/lib/in-memory-adapter.ts).

4. **Sessions:** key by `(namespace, cryptographically random pid)`; retain `sid`, authorized room IDs and a typed recoverable-data snapshot, excluding transport handles, tasks, credentials and live peer references. Bound at 120 s, 256 sessions/namespace, 4,096 globally, 16 KiB/session and 32 MiB globally. Atomically claim restoration to prevent concurrent reuse. Eviction means fresh authentication and `recovered=false`.

5. **Room policy:** automatic own-ID room plus at most 16 application rooms/socket; room names at most 128 bytes. No generic client “join room” event. Before any join, verify namespace, authenticated principal/capability, channel/resource access and revocation status; derive room IDs server-side. Recheck authorization before restoring protected membership. Preserve fresh-auth-only namespaces.

6. **Payload/queue policy:** explicitly configure 1,000,000-byte inbound Engine.IO payload and WebSocket message limits; also cap reconstructed binary aggregate, JSON depth and attachment count. Proposed attachment cap: 16, assembly deadline: 5 s. Bound outbound messages at 16 MiB, ordinary per-socket queues at 128 events/2 MiB, preview queues at 16 MiB, and all outbound queues at 128 MiB. Preview’s real maximum is **unverified**; fixture measurements must establish a compatible outbound ceiling. Audio currently travels in base64: `dimabot/src/server/services/tts/voice_preview.service.ts:140`.

7. **Slow consumers:** coalesce replaceable snapshots; drop/count explicitly lossy samples; disconnect on reliable-event queue exhaustion, retaining recovery state where permitted. Never silently discard moderation, terminal playback or money-related work; its durable application record remains authoritative. Limit in-flight server acknowledgements to 32/socket with explicit deadlines. Bound recovery draining too: stream the retained range under a per-socket cursor, without creating an unbounded copied replay vector.

8. **Shutdown:** stop admission first; cancel owned namespace pollers/subscriptions; resolve or fail pending acknowledgements; allow at most 5 s to drain bounded output, then close polling and WebSocket transports; join tasks and release sessions/buffers. In-memory recovery does not survive API replacement. Every task must follow the core shutdown owner: `dima-rust/MIGRATION.md:157`.

9. **Verification setup—proposed, not executed:** lead runs Node in a disposable offline container on a private test network with the exact candidate Rust server, mocks and synthetic fixtures. Preload pinned clients **4.8.3 and 4.7.5** before removing external network access. Exercise polling-only, WebSocket-only and polling→WebSocket; compare application results with the frozen reference. Also load the vendored `/socket.io/socket.io.js` asset.

10. **Recovery cases:** first CONNECT response `{sid,pid}`; reconnect auth `{pid,offset,...auth}`; correct namespace binding; unknown/expired/evicted offset; reconnect before any offset exists; replay exactly after the cursor with correct room/exclusion filtering; events during restoration; competing reconnects; intentional disconnect versus transport failure; retained `sid`/rooms/data; client `recovered` true/false. `recovered` is computed by the JS client from matching private IDs, not a wire boolean. Source: [client `socket.ts`](https://github.com/socketio/socket.io/blob/socket.io%404.8.3/packages/socket.io-client/lib/socket.ts).

11. **Transport/protocol cases:** upgrade probe race with concurrent emits, failed upgrade preserving polling, duplicate GET/POST, outstanding long-poll close, heartbeat timeout, unknown `sid`, invalid EIO/transport, namespace multiplex/disconnect, regex boundaries and Unicode, invalid namespace, malformed/reserved packets, oversized/deep payloads, partial/extra/interleaved binary attachments, binary EVENT/ACK, empty/multiple-argument ACK, missing/late/duplicate/wrong ACK IDs, and structured `{message,data}` CONNECT_ERROR. Protocol basis: [Socket.IO](https://socket.io/docs/v4/socket-io-protocol/), [Engine.IO](https://socket.io/docs/v4/engine-io-protocol/).

12. **Application/recovery interaction cases:** acknowledgement IDs remain unambiguous across reconnects; pending acknowledgements are not resurrected or replayed; only eligible events acquire offsets; disabled-recovery namespaces always authenticate again; speech reset precedes accepting new playback; clip reconnect cannot silently advance twice; Studio receipts/leases survive reconnect; token rotation blocks delivery; overflow/expiry produces an observable gap or fresh snapshot. Existing behavior to exercise: `dimabot/src/server/routes/public/speech.html:127`, `dimabot/src/server/websocket.ts:85`, `dimabot/src/overlays/live.ts:678`.

## 4. Problems and omissions in the first plan

1. **“Recovery replays each event” is wrong.** The reference stores ordinary EVENT packets without acknowledgement IDs and without the volatile flag; binary events and ack-bearing events are excluded. Direct `socket.emit` also routes through the adapter when recovery is configured. Preserve eligibility and targeting, not an offset indiscriminately appended to every packet. Source: [adapter broadcast implementation](https://github.com/socketio/socket.io/blob/socket.io%404.8.3/packages/socket.io-adapter/lib/in-memory-adapter.ts); [socket emission implementation](https://github.com/socketio/socket.io/blob/socket.io%404.8.3/packages/socket.io/lib/socket.ts).

2. **Recovery requires an earlier received offset.** A client disconnected before its first eligible event cannot recover the first missed event. This particularly weakens “overlays rely on recovery” as a blanket justification. Recovery also cannot bridge the one-cutover process replacement. Source: [recovery documentation](https://socket.io/docs/v4/connection-state-recovery/); current in-memory adapter selection: `dimabot/src/pets/socket_adapter.ts:8`.

3. **The ledger overstates speech’s need for replay.** Its browser explicitly ignores recovered speech until reset, while preview clients disable reconnect. They are poor reasons to build recovery; trigger/clip/furry are the relevant evidence. `dimabot/src/server/routes/public/speech.html:135`, `dimasite/src/app/features/tts/tts-voice-preview.component.ts:59`, `dima-rust/ledger/packages.md:41`.

4. **Namespace matching needs explicit semantics and admission before allocation.** Rust regex `\w`/`\d` must not silently broaden JS’s accepted names; enforce ASCII classes and full anchors. Reject invalid/excess namespace creation before inserting permanent child state. Current dynamic children are not cleaned up: `dima-rust/ledger/http.md:160`.

5. **The browser client asset is a delivery requirement.** Replacing the server library must not remove `/socket.io/socket.io.js`; vendor the pinned JS distribution. Otherwise the DimaFX overlay fails before it connects. `dimabot/src/server/routes/public/dimafx.html:12`.

6. **Do not inherit engineioxide defaults blindly.** Version 0.17.7 defaults polling payloads to 100 KB while WebSocket message/frame ceilings are much larger; configure all relevant limits explicitly. Source read: [`engineioxide 0.17.7 src/config.rs`](https://docs.rs/crate/engineioxide/0.17.7/source/src/config.rs).

7. **Call the wire versions precisely:** these JS Socket.IO 4.x clients use Socket.IO **protocol revision 5** over Engine.IO **revision 4**. Calling the implementation “Socket.IO v4 protocol” invites implementing the older wire revision. Source: [Socket.IO protocol introduction](https://socket.io/docs/v4/socket-io-protocol/).

8. **Remaining uncertainty:** production usage of legacy files, external desktop client behavior, legitimate connection counts and maximum outbound snapshots/audio were not verified. This review ran no builds, tests or containers and changed no files.
