# JavaScript Unicode 17 string core (2026-10-29)

## Status and scope

The reusable Rust string core is implemented and verified for the selected Node 24 / Unicode 17 behavior: `lowercase` implements default locale-independent lowercase on arbitrary JavaScript UTF-16 strings, and `fold_text` implements NFD, Unicode Mark removal, then that lowercase operation. The code preserves lone surrogates and handles their contextual interactions. The core is feature-gated and uses the existing `unicode-normalization` 0.1.26 crate; this work adds no crate, lockfile change, or worker-profile change.

This does not complete `src/utils/moderation/normalize.ts`. The separately authored `moderation/normalize.rs` adapters, JavaScript value coercion, regex escaping parity, and application/AST caller adoption remain unverified or open. A shared primitive does not close that source row, its API contract, or its callers. No TypeScript source was retired, no caller adopted the core, no release or push occurred, and total migration completion remains incomplete. No new dependency-ledger row is created for this shared helper.

## Data provenance and compatibility boundary

The source oracle uses `src/utils/moderation/normalize.ts` SHA-256 `07822ff6efe5d707173b6b9e9415b16edfb0eb055c3a03416bf4b4c0c11740ab`. The 1,318-input frozen source snapshot has SHA-256 `5680c2a75af337fc665d6ad76eebb1f57cb9ef4f066de047be505d16e898c819`, bound to code commit `a1088ba9`. Runtime pins are Node 24.22.1, V8 13.6.233.17-node.58, ICU 78.3, Unicode 17.0, TypeScript 5.9.3, and Node executable SHA-256 `569128f3066ac7be59b10b9a0adef708def642ee37cbf9d560a9bdb68f872108`.

The generator, accepted reference JSON, and generated Rust file are pinned respectively to `7c464ae4144db4a082a56593ddabf7c804a21503489a2db5abf446eb8e942f2f`, `aba3756c8cacc9a25432c282f15141dc5d34da317c13618cfcfa43253c0e3246`, and `6c9529a54bd192de38852f31421383d3295dc9010ca463037b6383e361040aeb`. The generated tables contain 1,488 lowercase mappings; 4,632 `Cased` code points in 158 ranges; 2,794 `Case_Ignorable` code points in 464 ranges; 2,543 Unicode 17 Mark code points in 327 ranges; and 299,382 assigned code points in 735 ranges. `Cased` and `Case_Ignorable` overlap at 268 code points, so the casing context scan checks `Case_Ignorable` first. The retained Node reference also contains 6,432 contextual cases and 13,253 single-code-point NFD facts; the latter are reference evidence, not runtime mapping tables.

The crate's existing `unicode-normalization` 0.1.26 tables are Unicode 18, newer than the pinned Node data. The implementation reuses NFD only inside runs of Unicode 17 assigned scalars, treating unassigned code points and UTF-16 surrogate units as boundaries, then applies the Unicode 17 Mark table. NFD stability for code points assigned in both versions is specified by [Unicode Standard Annex #15](https://www.unicode.org/reports/tr15/). The Unicode 17 primary data references include [UnicodeData.txt](https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt), [DerivedCoreProperties.txt](https://www.unicode.org/Public/17.0.0/ucd/DerivedCoreProperties.txt), and [SpecialCasing.txt](https://www.unicode.org/Public/17.0.0/ucd/SpecialCasing.txt). These references explain the data model; the parity oracle remains the pinned Node runtime's actual built-ins. No Rust standard-library Unicode version is assumed, and no standard-library mismatch was reproduced in this work.
