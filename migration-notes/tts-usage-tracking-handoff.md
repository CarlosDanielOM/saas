The native tracker reuses the existing TTS pricing code and the verified Polar batch adapter. It implements the six Redis counter/expiry commands and source-compatible local 30-day expiry, including nonpositive values. Cache failures are logged and billing continues; durable-ingestion errors map to `TTS usage recording unavailable` only when durable usage is required. Cache-only ingestion remains an explicit mode, while normal tracking uses batch ingestion. `TtsUsageTracker::from_cache` performs no I/O; the lazy entry point acquires the shared Redis connection. The HTTP client is shared and initialized lazily. Default logging has console and Redis sinks; application metadata/OTel sink composition remains a bootstrap concern.

The native API includes `TtsUsageTracker`, `track_tts_usage`, their options/context/result/error types, the time-to-next-month helper, and the existing pricing exports.
