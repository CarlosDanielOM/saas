## Responsibility and reuse

This port includes the complete scheduled dashboard responsibility: privacy-preserving projection of retained command/message metadata into daily scalar aggregates, 7/30-day activity and emote ranks (including the channel's current Twitch emote catalog), and cached weekday/game insight reports. The existing TypeScript helpers in `dimabot/src/utils/dashboard_activity.ts` and `dashboard_insights.ts` define the parity reference. The HTTP readers and queue producers remain in `dimabot/src/server/routes/dashboard.route.ts` and those shared helpers. They continue to serve requests, mark activity summaries dirty, queue insight summaries, and read the existing payloads; the native worker replaces only scheduled projection and refresh execution.

The projector reads existing `stream_activities` records (Mongoose model `stream_activity`) and the `stream_activity_states` checkpoint (`dashboard-daily-v1`). It does not reuse or alter the timeline projector's checkpoint, aggregates, or event capture. Existing Twitch handlers and `captureStreamActivity` remain the producers. The insights path reuses `streamsessions`, `streamviewersnapshots`, and `domain_events` (Twitch journal events for follows and incoming raids). The emote path reuses `twitch:CHANNEL:emote-catalog:v1`, `app:twitch:token`, the existing client credentials, and the fixed Twitch OAuth/Helix endpoints. These are existing sources; the remaining gap is scheduled refresh/projection, not a missing collector or parallel schema.

No new Mongo collection or index is created by the native worker. Existing Mongoose contracts are:

- `dashboard_activity_daily`: `_id` SHA-256 string; `channelID` string; `day` BSON Date at UTC midnight; `kind` in `command|emote|coverage`; `key` and `label` strings; `count` and `lastSeq` are Mongoose Numbers; `firstAt` and `expiresAt` BSON Dates. Indexes: `{channelID:1,day:1,kind:1}` and TTL `{expiresAt:1}`.
- `dashboard_activity_summary`: channel `_id`, `dirtyAt`, `nextRefreshAt`, `leaseUntil`, `owner`, `updatedAt`, mixed `payload`, and `error`; queue index `{nextRefreshAt:1,leaseUntil:1}`.
- `dashboard_insights`: channel `_id`, refresh/lease/owner/update/error fields, mixed `payload`, and `expiresAt`; indexes `{nextRefreshAt:1,leaseUntil:1}` and TTL `{expiresAt:1}`.
- Source collections and field shapes remain those of `stream_activity.schema.ts`, `stream_activity.schema.ts`'s state model, `stream_session.schema.ts`, `stream_viewer_snapshot.schema.ts`, and `domain_event.schema.ts`.

## Compatibility contract

Daily IDs hash the JSON array `[channelID, UTC-midnight ISO string, kind, key]` with SHA-256. Projection batches select at most 500 due, retained command/message rows in `(occurredAt,_id)` order; only `dashboardProcessed:null`, `occurredAt <= now`, and `expiresAt > now` qualify. A durable active-ID checkpoint and sequence fence are saved before writes. Replays may accept duplicate-key upsert collisions only when caused by an already-applied sequence; other write errors fail the batch. Existing duplicate-safe update semantics, marker updates, lease release, and `dirtyAt` race protection are retained.

All persisted instants remain BSON Dates. Daily boundaries and report periods use UTC, with the current day plus the prior six or 29 days. JavaScript string slicing is by UTF-16 code unit (100 units for command key/label and 64 for emote labels); the native path preserves that behavior, including surrogate-boundary cases. Locale ordering for game names follows Node's default English `localeCompare` behavior through ICU root collation, including case/accent tie ordering and stable exact ties; byte/codepoint sorting is not compatible. Cargo declares `icu_collator` 2.3.0 and the current lockfile resolves 2.3.1.

Typed Mongoose Number fields and mixed report payloads must retain Node's per-value BSON number selection: finite integral values in the signed 32-bit range serialize as BSON Int32 except negative zero; all other numeric values serialize as Double. This applies to daily counts and sequence fields as well as nested summary data. Mixed insight payload normalization also preserves Node's safe Int64 boundary behavior, including the inclusive `±2^53` edge. Non-numeric BSON emote counts are skipped, matching the TypeScript path, rather than coercing or failing the batch. New count and boundary tests plus the isolated checker preserve strict TypeScript `$type` parity for these values. Insight values ignore non-finite inputs, clamp negative scalar values to zero, and round derived values to two decimal places with JavaScript `Math.round` semantics. Coverage is approximate: only observed snapshot intervals of at most ten minutes count; missing starts, offline time, and longer gaps are not interpolated. A follow timestamp is assigned only when exactly one selected session interval covers it. Completed offline sessions only are eligible; incoming raids can exclude an entire session. Reports retain UTC weekday mapping, thresholds (three streams, two hours; 80% weekday sample coverage), truncation behavior, top-five game ordering by viewer-hours, and best-day/game tie breaks.

Privacy is unchanged: projection stores per-channel/day scalar counts and labels, not message bodies, command arguments, actors, or per-user/per-day rows. API access checks and request-time behavior remain TypeScript-owned.

## Scheduler, leases, and external catalog

The worker performs at most one projection batch (500 source rows), one activity summary, and one insight summary per tick. It uses readiness checks across all three queues and continues after yielding while any work is ready, including a saved expired checkpoint whose replay emits zero retained rows. It waits one second when idle, when work is future-due or leased, or after an error. The source's count-only one-second idle sleep is replaced by this readiness-aware rule; no artificial cooldown is added while ready work remains.

The reviewed waits retain their purpose: 60-second projector and summary leases; 10-second projector lease heartbeat; 40-second initialization/tick watchdog (below the lease duration); 60-second activity refresh cadence; 300-second insight refresh cadence; 30-second summary error retry; and one-second idle/future/lease/error wait. The emote catalog refreshes after one hour, serves stale cached data for up to one day, retries a failed refresh after 60 seconds, and uses a one-day Redis key TTL. Helix and OAuth requests each have a three-second bound; OAuth has an explicit bound so a stalled token refresh cannot hold a tick until the watchdog. There is no per-item sleep or external rate-limit cooldown in the source. Signals finish the current bounded work and readiness check before shutdown.

The catalog key is `twitch:CHANNEL:emote-catalog:v1`, with JSON `{emotes:[{id,name}],checkedAt:ISO|null,retryAt:epochMs}`. A catalog younger than one hour is ready; one younger than one day is stale; older/missing data is unavailable. IDs must match ASCII `[a-zA-Z0-9_-]{1,64}` and the response is capped at 2,000 emotes. Existing cache/provider failures preserve stale/unavailable behavior. Production URLs remain `https://api.twitch.tv/helix/chat/emotes?broadcaster_id=CHANNEL` and `https://id.twitch.tv/oauth2/token`; the OAuth form uses `client_id`, `client_secret`, and `grant_type=client_credentials`. `app:twitch:token` is reused and refreshed with the returned `expires_in` TTL. Tokens and raw provider errors are not logged. Redirects are disabled; standard proxy variables and `SSL_CERT_FILE` support isolated provider fixtures.
