## Source mapping and dependency boundaries

The six TypeScript runtime exports are `VariationError`, `variationJobView`, `savedVariations`, `resolveVariations`, `requestVariationJob`, and `processNextVariationJob`. Their native counterparts are typed error/view helpers and `VariationJobsService` operations. The TypeScript schema exports the cache model, `VariationJob` type, and job model; the native `moderation_variation.schema.rs` repository declares the same two collections, defaults, fields, and TTL/state indexes. The schema's `GeneratedVariation` import is type-only. In the job source, the channel-rule import is type-only; the Mongoose cache/job/users models, Dragonfly client, advanced moderation constants/policy, variation/provider functions, and `node:crypto` are runtime dependencies mapped to the existing native schema, users query, shared Redis runtime, moderation/provider modules, and Rust SHA-256 implementation.

Native storage keeps raw BSON for Mixed and partial documents. Strict `VariationCache`/`VariationJob` DTOs represent complete typed application values and are not replacements for raw BSON when unknown or incomplete values must round-trip. The source's optional `symbolVersion: undefined` own property is omitted at the explicitly tested JSON serialization boundary; exact JavaScript own-property identity is outside the claim. The reference compiler projects uncommon BSON values into its supported comparison representation; this does not claim arbitrary BSON-to-Node or JavaScript prototype/getter/sparse-array identity. Native driver error text is compared by category for injected ORM-like failures, not asserted byte-for-byte.

The native module does not invoke Node or a TypeScript runtime; Node is used only by the source-oracle evidence. The mapping retains the source's 500-word/30-job daily quota and one-day Redis TTL, source Lua, reservation and failed-job retry behavior, five-minute deadline, oldest-first one-job claim, maximum 20 terms per provider batch, provider timeout bounded by the lesser of 60,000 ms and remaining job time, 180-day retention, zero credits, persisted provider usage, and conditional state/deadline updates. Redis application acquisition is lazy until quota is needed; cache/eval telemetry is supplied at that operation. The shared native bootstrap does not reproduce all source console messages and connection-event logging.
