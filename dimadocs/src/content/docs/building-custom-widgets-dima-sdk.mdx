This guide is for creators building custom widgets for Overlay Studio. A widget is a small HTML, CSS, and JavaScript package that runs in a sandboxed frame. Native widgets use the Dima SDK; StreamElements packages use a compatibility layer built on that SDK.

For the streamer workflow, see [Custom widgets](/custom-widgets/).

You can also write a widget directly in Overlay Studio with **New widget** and the Dima SDK starter. See [Write code in Studio](/custom-widgets/#write-code-in-studio).

SDK typings are included with [Download for your editor](/custom-widgets/#use-your-own-code-editor).

## Package files

A package can contain these files:

| File | Purpose |
|---|---|
| `widget.json` | Optional manifest for Dima widgets; required to declare the native Dima engine and its data needs. StreamElements widgets without it are detected from their code. |
| `widget.ini` | StreamElements map from file sections to filenames. |
| `html.txt` | Markup inserted into the frame’s body. |
| `css.txt` | Styles inserted into the frame. |
| `js.txt` | A classic JavaScript script, run after the HTML. |
| `fields.txt` | A JSON object describing editable settings. |
| `data.txt` | A JSON object with saved setting values. |

For a StreamElements package, `widget.ini` points to the HTML, CSS, JavaScript, fields, and data files. For a native Dima widget, use `widget.json` and the same content files; `widget.ini` is not needed. The importer preserves the original fields and data text for export.

### `widget.json` manifest

The manifest is a JSON object. It accepts these fields:

| Field | Required | Meaning |
|---|---:|---|
| `engine` | No | `"dima"` for native Dima SDK code, or `"streamelements"` to enable the StreamElements compatibility layer. Defaults to `"dima"` when a manifest is present; with no manifest, imports default to StreamElements. |
| `api` | No | Dima SDK version. Defaults to `1`; unsupported versions are refused. |
| `uses` | No | Array of data categories the widget needs: `chat`, `alerts`, `storage`, `counters`, `session`, `signals`, `polls`, `goals`, `tts`, `triggers`, `rewards`, `pets`, `duels`, `roulette`, and/or `dimafx`. Defaults to an empty list. Unknown entries are reported and ignored. |
| `name` | No | Widget name shown in Studio. |
| `author` | No | Creator name. |
| `version` | No | Your package version string. |
| `description` | No | Short description of the widget. |
| `signals` | No | Optional signal declarations for ready-made commands in Studio (up to 30). Each has a lowercase `name`, optional `description` (up to 200 characters), and optional `values` examples (up to 30, each up to 60 characters). Invalid declarations are skipped with the import note `signal declaration skipped`. |

```json
{
  "engine": "dima",
  "api": 1,
  "name": "Pastel chat",
  "author": "Ana",
  "version": "1.2.0",
  "description": "Chat with pastel bubbles",
  "uses": ["chat", "alerts", "storage", "counters", "session", "signals", "polls", "goals", "tts", "triggers", "rewards"],
  "signals": [{ "name": "feed", "description": "Feed the pet", "values": ["pizza", "cake"] }]
}
```

Declare only what the widget actually needs. `chat` permits chat, delete, and clear events; `alerts` permits follow, subscription, gift, Bits, raid, and tip alert categories; `storage` permits persistent values; `counters` permits command counts; `session` permits recent events and totals; `signals` lets chat commands control the widget; `polls` and `goals` permit their live state; and `tts`, `triggers`, `rewards`, `pets`, `duels`, `roulette`, and `dimafx` permit those bot events. Real tip events are not available yet. In Studio, the manifest’s `uses` list is shown to the channel owner, and a published widget receives only the categories it declares. Editor button tests are available independently of `uses`.

## Editable settings

`fields.txt` is a JSON object keyed by each setting’s name. Each entry can include `type`, `label`, `value` (default), `group`, and type-specific options such as `min`, `max`, `step`, and `options`. Fields with the same `group` name appear together in a collapsible group; ungrouped fields appear under **General**. Hidden values are still available to your code. Search in Studio matches setting labels. A layer stores only its changed values; resetting a setting removes that override.

Supported types are:

- `text`, `textarea`, `number`, and `slider` (with optional `min`, `max`, and `step`)
- `checkbox`
- `colorpicker`
- `dropdown`, with `options` as an object mapping option values to labels
- `googleFont`
- `image-input`, `video-input`, and `sound-input`; use `multiple: true` for a list of URLs
- `button`, which sends an editor-only `button` event to the widget
- `hidden`, whose value is not shown in the editor

For example:

```json
{
  "accent": { "type": "colorpicker", "label": "Accent", "value": "#7c3aed", "group": "Look" },
  "limit": { "type": "number", "label": "Messages on screen", "value": 6, "min": 1, "max": 30, "group": "Chat" },
  "hideCommands": { "type": "checkbox", "label": "Hide !commands", "value": true, "group": "Chat" }
}
```

The resolved value for a field comes from its default, then the package’s `data.txt`, then that overlay layer’s changed value. Use the result in HTML or CSS with `{key}` or `{{key}}`, for example `{{countLabel}}`. Substitution replaces known keys only; arrays are joined with commas and null becomes empty text. In native Dima widgets, substitution runs in HTML and CSS only; read values in JavaScript from `Dima.fields`. In StreamElements widgets, substitution also runs in JavaScript for compatibility. The importer protects closing `</script` and `</style` sequences in substituted values.

## Dima SDK v1

The SDK is available as `Dima` inside the widget frame.

```js
const ctx = await Dima.ready();
// ctx: { widget, channel, fields, mode, muted, session }
Dima.fields; // current settings
const unsubscribe = Dima.on('chat', message => { /* ... */ });
Dima.off('chat', handler); // or call the function returned by Dima.on
Dima.storage.get('key'); // Promise resolving to a JSON value or null
Dima.storage.set('key', { seen: true }); // Promise
Dima.counters.get('!deaths'); // Promise<number>
Dima.html(message); // escaped text plus safe Twitch emote images
Dima.escape(viewerText); // escaped string
Dima.log('loaded'); // appears in Studio's Widget log
await Dima.setField('accent', '#ff66aa'); // editor only
```

Native Dima widgets use `Dima.storage.get/set`, the `storage` event and `"storage"` in `widget.json` `uses`. StreamElements widgets keep `SE_API.store` and `kvstore:update`.

`Dima.setField(key, value, reload = true)` is for editor-only tools. It changes a setting from code and validates it against the field definition. It rejects in live mode. `Dima.done()` is a no-op in v1. Native Dima widgets get a storage namespace scoped to their widget. StreamElements widgets share the `se` namespace across the channel. Storage update events are `DimaStorageUpdate { key, value, namespace }`. Widgets only receive updates for their own storage namespace: the widget ID for native Dima widgets, or `se` for all StreamElements widgets in the channel. This matches StreamElements' shared kvstore.

### Command signals

Declare `"signals"` in `uses` to receive command signals. You can optionally declare up to 30 signals in `widget.json`; Studio uses their names, descriptions, and example values to prepare commands: with no `values`, the command sends no value; single-word examples send the viewer's first word (`&p1`); an example with spaces sends all text after the command (`&t`). Names use lowercase letters, digits, and `_`, up to 40 characters. Invalid declarations are skipped with the import note `signal declaration skipped`.

```json
{
  "uses": ["signals"],
  "signals": [{ "name": "feed", "description": "Feed the pet", "values": ["pizza", "cake"] }]
}
```

Subscribe to every signal or one name. Signal values come from viewer text: render them with `textContent` or `Dima.escape()`, never `innerHTML`.

```js
Dima.on('signal', signal => { /* handle every signal */ });
Dima.on('signal:feed', signal => {
  document.querySelector('.pet-status').textContent = `Eating ${signal.value || 'snack'}`;
});
```

`DimaSignal` contains `id`, `name`, `value` (text after the name, or `''`), `json` (parsed only when the value is a JSON number, boolean, array, or object; otherwise `null`), `args` (value split on spaces), `at` (milliseconds), `user`, `source`, and `target`. `user` contains `id`, `login`, `name`, and verified Twitch badge roles (`broadcaster`, `moderator`, `vip`, `subscriber`), or `null` when unknown. `source` contains `kind` (`command`, `keyword`, `event`, or `studio`) and `name`. `target` is the layer name for targeted signals, otherwise `null`.

For StreamElements compatibility, the same data arrives through `onEventReceived` with `listener: 'dima:signal'` (`obj.detail.event.name`, `.value`, `.user`, and other signal fields), so one widget file can support both engines.

### Events

Subscribe with `Dima.on(type, handler)`. It returns an unsubscribe function. You can also call `Dima.off(type, handler)`.

| Event | `data` shape | Requires `uses` |
|---|---|---|
| `chat` | `DimaChat` (shape below) | `chat` |
| `chat.delete` | `{ messageId: string, userId: string \| null }` | `chat` |
| `chat.clear` | `{ userId: string \| null }`; `null` means the whole chat | `chat` |
| `alert` | `DimaAlert` (shape below) | `alerts` |
| `button` | `{ field: string, value: unknown }` | Editor only; always available in preview |
| `fields` | The current settings object | Editor only |
| `storage` | `DimaStorageUpdate { key: string, value: unknown, namespace: string }` after a storage write | `storage` |
| `session` | `{ data: Record<string, unknown>, recents: unknown[] }` | `session` |
| `signal` / `signal:<name>` | `DimaSignal` | `signals` |
| `state` | `DimaState` (`{ name, value }`) | `polls` or `goals`, according to `name` |
| `tts` | `DimaTts` | `tts` |
| `trigger` | `DimaTrigger` | `triggers` |
| `reward` | `DimaReward` | `rewards` |
| `pet` | `DimaPet` | `pets` |
| `duel` | `DimaDuel` | `duels` |
| `roulette` | `DimaRoulette` | `roulette` |
| `dimafx` | `DimaDimafx` | `dimafx` |

### Live state

Use `Dima.state(name, handler)` for the latest known polls or goals value and later changes. The current snapshot is sent again when an OBS source connects or reconnects. The handler runs as soon as a value is known, then whenever it changes. If no value is known yet, it does not run; an unknown value is not an empty poll or goals list. The return value stops listening. You can also subscribe to every state change with `Dima.on('state', ({ name, value }) => …)`.

```js
const stopPolls = Dima.state('polls', ({ poll, prediction }) => {
  document.querySelector('#poll-title').textContent = poll?.title ?? 'No poll yet';
});
Dima.state('goals', goals => {
  document.querySelector('#goal-count').textContent = String(goals.length);
});
// Later: stopPolls();
```

`polls` requires `"polls"` in `uses` and has shape `DimaPolls` (`{ poll, prediction }`); each value is `null` or a `DimaPoll`. A poll has `kind` (`poll` or `prediction`), `id`, `title`, `phase` (`active`, `locked`, `completed`, `archived`, `terminated`, `resolved`, or `canceled`), `choices`, `startedAt`, `deadline`, `endedAt`, `winnerId`, and `revision`. Each choice has `id`, `title`, `votes`, `users`, and `points`, with optional `channelPointsVotes` and `color`. Poll and prediction data is totals only and never identifies voters. It reaches the widget once Twitch poll and prediction events are enabled; Studio shows the same **Polls & predictions** setup as the Overlay tab.

`goals` requires `"goals"` in `uses` and is an array of `DimaGoal` values from the Goals page. Each goal includes `id`, `name`, `metric` (`follows`, `subs`, `bits`, or `currency`), `mode`, `target`, `current`, `percent`, `currency` (code or `null`), `status` (`scheduled`, `active`, `reached`, or `ended`), `startsAt`, `endsAt`, `windowSeconds`, and `period`. Money values use currency units (for example, `87.5`). State changes after edits or progress updates within seconds, and time-based changes are sent at least once a minute. This state includes goal targets and status; it never runs goal completion actions.

### Bot events

These events are live-only: an OBS source that reconnects does not receive events sent while it was disconnected. Every event includes `at` (milliseconds) and `test` (`true` for Studio tests).

| Event | Data | Notes |
|---|---|---|
| `tts` (`uses: ["tts"]`) | `DimaTts`: `id`, `phase` (`start` or `end`), `text`, `user`, `reason` | `text` is the filtered text spoken. Start is sent when audio plays; end is sent once when it finishes, with reason `ended`, `skipped`, `cleared`, or `interrupted`. Both phases share an `id`; messages that never play produce no event. |
| `trigger` (`uses: ["triggers"]`) | `DimaTrigger`: `id`, `triggerId`, `name`, `mediaType` (`audio`, `video`, `image`, or `unknown`) | Sent when a trigger alert is sent by a command, channel-point redemption, or Bits rule. It contains no media URL. A custom-widget-only overlay can observe the send but does not play the media. |
| `reward` (`uses: ["rewards"]`) | `DimaReward`: `id`, `reward: { id, title, cost }`, `user`, `input` | Sent for every channel-point redemption, including rewards without a bot action. `input` is viewer text when supplied; use `textContent` or `Dima.escape()`, never `innerHTML`. |
| `pet` (`uses: ["pets"]`) | `DimaPet`: `id`, `kind`, `phase`, `text`, `mood`, `result` | Sent when the pet starts speaking and once when it finishes, only for replies that spoke. Handle `done` even if no `speaking` arrived first. `text` is what the pet said, never the viewer’s question. Private DomDimaBot desktop app replies are not sent to widgets. |
| `duel` (`uses: ["duels"]`) | `DimaDuel`: `id`, `phase`, `challenger`, `opponent`, `mode`, `winner`, `loser`, `endsAt` | Names are Twitch logins. `started` is sent when a challenge is accepted or someone challenges the streamer; `ended` is sent once after the fight, with the result revealed only then. |
| `roulette` (`uses: ["roulette"]`) | `DimaRoulette`: `id`, `rouletteId`, `name`, `phase`, `label`, `endsAt` | Sends `spinning`, then `result` with the landed label when the spin ends. A result can be missed if DomDimaBot restarts during a spin. |
| `dimafx` (`uses: ["dimafx"]`) | `DimaDimafx`: `id`, `item`, `source`, `bits`, `credits`, `user`, `message` | Sent once when a DimaFX item starts playing; the DimaFX overlay must be connected. Viewer identity is included only when shared with the extension. Custom TTS `message` is viewer text; use `textContent` or `Dima.escape()`, never `innerHTML`. |

`DimaPet.kind` is `talk`, `ask`, or `tts`; `phase` is `speaking` then `done`. `mood` is null when moods are off, and `result` is `completed` or `stopped` only on `done`. `DimaDuel.phase` is `started` then `ended`; `challenger` and `opponent` are Twitch logins, `mode` is `overlay` or `chat`, `winner` and `loser` are null until `ended`, and `endsAt` may be null. `DimaRoulette.phase` is `spinning` then `result`; `label` is present only on `result`. For `DimaDimafx`, `item` is `{ id, name, type }`, `source` is `bits`, `credits`, `saved`, or `test`; `bits` and `credits` are the amount paid or null. `user` contains `{ id, login, name }` only when the viewer shared their identity with the extension, otherwise it is null. `message` is the viewer's text only for custom TTS items; otherwise it is null.

```js
Dima.on('tts', event => {
  if (event.phase === 'start') document.querySelector('#spoken').textContent = event.text;
});
Dima.on('trigger', event => console.log(event.name, event.mediaType));
Dima.on('reward', event => {
  document.querySelector('#reward-input').textContent = event.input ?? '';
});
Dima.on('pet', event => {
  if (event.phase === 'speaking') document.querySelector('#pet').textContent = event.text;
});
Dima.on('duel', event => console.log(event.phase, event.challenger, event.opponent));
Dima.on('roulette', event => {
  if (event.phase === 'result') document.querySelector('#winner').textContent = event.label ?? '';
});
Dima.on('dimafx', event => console.log(event.item.name, event.source));
```

The `DimaPet`, `DimaDuel`, `DimaRoulette`, and `DimaDimafx` typings describe these event objects. StreamElements-compatible widgets receive the same events through `onEventReceived` listeners `dima:pet`, `dima:duel`, `dima:roulette`, and `dima:dimafx` (`obj.detail.event`). All four event types include `at` (milliseconds) and `test` (`true` for Studio tests). They are live-only and are not replayed after an OBS reconnect.

### Studio state and event tests

The **Bot events** row appears when a widget in the overlay uses one of these categories. It can send TTS (start and then end three seconds later), Trigger, Channel points, Sample poll, Sample goals, Pet reply, Duel, Roulette, and DimaFX purchase to the preview or OBS. Paired events send their second phase about three seconds later. The code editor preview offers the same tests. Sample state sent to OBS is shown for about a minute, then the real state returns. Studio previews start with the channel’s real polls and goals.

The **Replay recent chat** button is in the **Chat** row and works in the preview only. It sends the channel’s last 20 stored messages, oldest first. Replay is text only: it has no emotes, name colours, or badge images, and messages deleted by moderators may appear, so they are not sent to OBS.

`Dima.ready()` resolves to an object with `widget: { id, layerId, name, revision }`, `channel: { id, login, name }`, `fields`, `mode` (`"editor"` or `"live"`), `muted`, and `session` (or `null`).

A chat event has this shape:

```ts
{
  id: string; platform: 'twitch'; at: number;
  user: {
    id: string; login: string; name: string; color: string | null;
    badges: Array<{ set: string; version: string; info: string; title: string;
      images: { '1x': string; '2x': string; '4x': string } }>;
    roles: { broadcaster: boolean; moderator: boolean; vip: boolean; subscriber: boolean;
      founder: boolean; artist: boolean; staff: boolean; partner: boolean; turbo: boolean; prime: boolean };
    subMonths: number | null;
  };
  text: string;
  parts: Array<
    | { type: 'text'; text: string }
    | { type: 'emote'; text: string; id: string; animated: boolean; images: { '1x': string; '2x': string; '4x': string } }
    | { type: 'cheer'; text: string; prefix: string; bits: number; tier: number }
    | { type: 'mention'; text: string; user: { id: string; login: string; name: string } }
  >;
  kind: 'text' | 'highlighted' | 'intro' | 'power-up' | 'gigantified';
  action: boolean; firstMessage: boolean; bits: number; rewardId: string | null;
  reply: { id: string; user: { id: string; login: string; name: string }; text: string } | null;
  sharedChat: { channelId: string; messageId: string } | null;
}
```

An alert event has this shape:

```ts
{
  id: string; type: 'follow' | 'sub' | 'resub' | 'gift' | 'bits' | 'raid' | 'tip';
  at: number; test: boolean; user: { id: string; login: string; name: string } | null;
  amount: number; // months, gifts, Bits, raid viewers, or tip amount
  tier: '1000' | '2000' | '3000' | 'prime' | null;
  months: number | null; streak: number | null; message: string | null;
  recipient: { id: string; login: string; name: string } | null;
  currency: string | null; rule: { id: string; name: string } | null;
}
```

`DimaSession.data` is a StreamElements-style snapshot with keys such as `follower-latest`, `subscriber-recent`, `cheer-session`, and `follower-week`. `recents` contains recent alert items. The `*-session` values cover the current stream, or the past 24 hours if no stream start is available; `*-week` covers the past 7 days; and `*-month` (followers, subscribers, Bits, and raids) covers the current UTC calendar month. The `*-latest` and `*-recent` values come from the newest 500 alerts. Each `*-recent` list contains up to 25 items.

`follower-total` and `subscriber-total` are the current follower and subscriber totals shown on the dashboard. Follows update as they happen. `cheer-total` and `raid-total` cover the last 90 days, the retention period for channel events, so they can decrease as older events age out. Subscriber counts include each subscriber once plus gifted subs; a 5-sub community gift adds 5.

The StreamElements manual goal keys `follower-goal`, `subscriber-goal`, `cheer-goal`, and `tip-goal` each have shape `{ amount }`. They follow the first active goal of that kind in the streamer's Goals list, or the first reached goal if none is active. If there is no goal, the value is 0. The amount is goal progress, not its target. Goal counting options (since creation, current count, set dates, rolling window, or calendar month) are chosen on the Goals page. Money (`tip-goal`) is in currency units (for example, `12.34`) and includes everything counted by the goal, such as Bits, subs, and custom items, not only tips. Session updates include these values and arrive through the Dima `session` event or StreamElements `onSessionUpdate`; goal or progress changes reach widgets in OBS within seconds. Tests update session totals in the preview and send updated totals to OBS after each test alert, without changing real data. Tip event values (`tip-*`) stay at 0 until DomDimaBot tipping is available; the manual `tip-goal` value can still show a Goals page goal.

Some totals that cannot yet be calculated are present as zero. StreamElements HTML inline `onerror="…"` handlers can call functions defined in the widget's script; early image errors wait until that script has run, matching StreamElements behavior.

`Dima.html(message)` escapes message text and produces `<img>` elements for Twitch emotes. Use `Dima.escape` for viewer-controlled text you insert into HTML yourself. For other dynamic DOM text, prefer `textContent`.

### Complete native example

This small chat widget is adapted from the `dima-chat` sample. It declares the data it reads, displays safely escaped chat, listens for moderation events, and uses the storage and counter APIs.

`widget.json`:

```json
{
  "engine": "dima", "api": 1, "name": "Dima sample chat", "author": "DomDimaBot",
  "version": "1.0.0", "description": "A compact chat overlay", "uses": ["chat", "storage", "counters"]
}
```

`fields.txt`:

```json
{
  "accent": { "type": "colorpicker", "label": "Accent", "value": "#7c3aed", "group": "Look" },
  "limit": { "type": "number", "label": "Messages on screen", "value": 6, "min": 1, "max": 30, "group": "Chat" }
}
```

`html.txt`:

```html
<ol class="chat" aria-live="polite"></ol>
<footer><span class="count">0</span> alerts · <span class="deaths">0</span> deaths</footer>
```

`css.txt`:

```css
:root { --accent: {accent}; }
body { margin: 0; color: white; font: 18px system-ui, sans-serif; }
.chat { display: flex; flex-direction: column; gap: 6px; list-style: none; padding: 12px; }
.msg { padding: 8px 12px; border-left: 4px solid var(--accent); background: #111c; }
.msg img.dima-emote { height: 1.4em; vertical-align: middle; }
```

`js.txt`:

```js
const chat = document.querySelector('.chat');
const count = document.querySelector('.count');
const deaths = document.querySelector('.deaths');
let fields = {};
Dima.ready().then(async ctx => {
  fields = ctx.fields;
  count.textContent = String((await Dima.storage.get('alerts')) ?? 0);
  deaths.textContent = String(await Dima.counters.get('!deaths'));
});
Dima.on('fields', next => { fields = next; });
Dima.on('chat', message => {
  const item = document.createElement('li');
  item.className = 'msg';
  item.dataset.id = message.id;
  item.innerHTML = '<strong>' + Dima.escape(message.user.name) + '</strong> ' + Dima.html(message);
  chat.append(item);
  while (chat.children.length > Number(fields.limit || 6)) chat.firstElementChild.remove();
});
Dima.on('chat.delete', ({ messageId }) => {
  chat.querySelector('[data-id="' + CSS.escape(messageId) + '"]')?.remove();
});
Dima.on('chat.clear', () => { chat.replaceChildren(); });
```

The native example has no `widget.ini`; Studio adds these files to an overlay when you import the package.

## StreamElements compatibility

Set `"engine": "streamelements"` (or import a package without a manifest) to load the compatibility layer. It listens to Dima SDK events and exposes the familiar browser events:

- `onWidgetLoad` fires after `Dima.ready()` with `detail.channel`, `currency`, `fieldData`, `recents`, `session`, `overlay`, and `emotes`.
- `onEventReceived` receives chat as `listener: "message"`, message deletion as `"delete-message"`, user chat clear as `"delete-messages"`, alerts as `"follower-latest"`, `"subscriber-latest"`, `"cheer-latest"`, `"raid-latest"`, or `"tip-latest"`, plus `"widget-button"`, `"kvstore:update"`, `"dima:signal"`, `"dima:polls"` (`event.poll`, `event.prediction`), `"dima:goals"` (`event.goals`), `"dima:tts"`, `"dima:trigger"`, and `"dima:reward"`.
- Session updates fire `onSessionUpdate` with `{ session }`.

For chat, `event.data` includes `time`, IRC-style `tags`, `nick`, `userId`, `displayName`, `displayColor`, `badges`, `channel`, `text`, `isAction`, `emotes`, and `msgId`; `event.renderedText` is escaped HTML with Twitch emotes. Alert objects include the listener-specific fields such as `name`, `amount`, `tier`, `message`, `gifted`, `sender`, or `currency` where applicable.

The supported `SE_API` methods are `store.get/set`, `counters.get(name)`, `sanitize({ message })`, `cheerFilter(text)`, `getOverlayStatus()`, `resumeQueue()`, and `setField(key, value, reload)`. Native Dima storage is scoped to each widget; StreamElements storage remains channel-wide through `SE_API.store`. `sanitize` returns the message unchanged. A widget with a `widgetDuration` setting queues alert events received by `onEventReceived`. Alerts play one at a time. Each waits for that many seconds, up to 300, unless `SE_API.resumeQueue()` releases the next alert early. Up to 50 alerts can wait. Chat and other events never wait. Without `widgetDuration`, alerts are not queued. `setField` only works in the editor. The layer does not provide a StreamElements API token, StreamElements-only API calls, or third-party emotes. StreamElements has no whole-chat-clear event. A whole-chat clear reloads StreamElements widgets so they start fresh. A user clear maps to `delete-messages`. Native Dima widgets receive `chat.clear` with `userId: null` for a whole-chat clear.

StreamElements widgets substitute `{key}` and `{{key}}` in HTML, CSS, and JavaScript. Native Dima widgets substitute in HTML and CSS; JavaScript reads current values from `Dima.fields`. When settings change in the editor, native Dima widgets receive a `fields` event; StreamElements widgets reload, matching their usual behavior.

## Limits and reliability

| Limit | Maximum |
|---|---:|
| HTML or CSS file | 512 KB each |
| JavaScript file | 1 MB |
| Fields file | 256 KB |
| Data file | 128 KB |
| `widget.json` manifest | 16 KB |
| Whole package | 2 MB |
| Settings per widget | 500 |
| Changed settings per layer | 64 KB |
| Store value | 64 KB of JSON |
| Store keys per channel | 500 keys and 2 MB total |
| Store key name | 100 characters |
| RPC request payload | 64 KB |
| Calls from one frame | 30 RPCs per second |
| Log messages from one frame | 200 per minute |

A widget frame sends a heartbeat every two seconds. If it stops responding for ten seconds, Studio reloads it, up to three times in five minutes; then it stops the widget and shows an error. Excess RPCs or log lines are dropped. A tight infinite loop can still stall the page because the sandbox is not a separate process. Keep work small, avoid blocking loops, and use timers for repeated work.

## Security

Each widget runs in an iframe sandbox with scripts enabled and an opaque origin. It cannot read the site’s storage or login, access the parent page or other layers, open popups or forms, navigate the top page, or control OBS. The SDK provides an in-memory `localStorage` and `sessionStorage` shim; do not rely on those values persisting between frames. Only the live data categories declared in `uses` are delivered. Escape viewer-provided text before inserting it into HTML, or use `textContent` for plain text.
