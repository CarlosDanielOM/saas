## Stream timeline expansion roadmap

Goal: help the streamer answer “what happened during my stream, and what changed audience engagement?” Timeline alignment can reveal correlation, not prove that an event caused an audience change. TLN-01–08 mark implemented source foundations; their nested unchecked items and TLN-09 capture remaining product, coverage, and verification work.

### Current baseline (source-audited)

[`stream_timeline.ts`](../dimabot/src/utils/stream_timeline.ts) returns sampled viewers/messages/minute/command-rate, five-minute distinct chatter counts (initial partial coverage is `null`), title/game changes, raids, redemption markers, owner notes, and coverage/truncation indicators. Activity projections add command/emote ranks and trends; command actor detail is Pro-gated. Emote capture is Twitch-native only. A separate dashboard projector can backfill retained `stream_activity` command/emote metadata into UTC-day scalar counts; it cannot reconstruct events from before source collection or metadata no longer retained. Redemption status is the initial received state, without ongoing fulfillment reconciliation. Credit rows are the latest 100 AI receipts in the session time window, matched by channel/customer; this is temporal association, not causal or chatter attribution. Event details use 100-row cursors and people use 50-row cursors. Reads/outputs are capped (including 2,000 chart rows); the query horizon is 90 days, participant/marker TTLs are 90 days, and source event expiry can differ. Viewer snapshots store cumulative command counts ([schema](../dimabot/src/schemas/stream_viewer_snapshot.schema.ts)). Durable Twitch channel-topic events default to 90 days ([retention defaults](../dimabot/src/domain_events/domain_event.types.ts)); follows, subscriptions, bits, and raids use that topic, while poll/prediction events override it to one day ([producer](../dimabot/src/domain_events/twitch_eventsub_events.ts)). Each row's `expiresAt` is authoritative, including older records. The route resolves the channel owner's tier and `analytics:view`; it gates comparison, actor detail, and credit detail, while the base timeline remains available under analytics permission ([route](../dimabot/src/server/routes/stream_timeline.route.ts)). Dashboard commands/emotes return cached 7/30-day top-five ranks to authorized `dashboard:view` users; they do not return day-by-day or per-user detail, and existing daily/per-user tier gates are unchanged ([activity route](../dimabot/src/server/routes/dashboard.route.ts)). These are source facts, not claims of complete reporting or live event coverage.

### Timeline performance requirements

Keep these P0 performance requirements for ongoing expansion. Figures below are draft targets and planning math, not guarantees. Isolated 100k and 1m fixtures have run (evidence in PERF-05); broader workload remains pending. A read-only live check confirmed five activity indexes; full query plans and all source indexes were not audited, and no production benchmark was performed. At 100,000 events/channel/day, the average is about 1.16 events/second; if each event is retained as one source row for 90 days, that is 9 million source rows before indexes/projections. Bursts and per-message database work can dominate that average.
