## Proposed decomposition (PROPOSAL — the lead decides)

124 packages in 21 crates, 22 waves. Target 400–1200 LOC per package; areas are defined by ordered rules in `ts_graph.mjs` (`RULES`), and areas over 1200 LOC are cut into consecutive packages along directory boundaries.
Every import cycle is assigned whole to one crate by an anchor rule (`SCC(...)`), so file cycles never cross crates (checked: 0 cycles cross a crate boundary).

**Coverage check (run by the script, it aborts on failure):** every non-test file is matched by a rule, the packages are built from that assignment, a `Map` from file to package throws on a second insertion, and the script asserts assigned files (762) = non-test files (762), missing = 0, duplicates = 0, packaged LOC (111,226) = non-test LOC (111,226).

Waves: wave 0 packages depend on no other package; wave N depends only on waves < N. Packages that import each other (package-level cycles, all inside one crate) share a wave and must be built together or have their cycle broken first. Dependencies count value and type imports, because Rust needs the types.

### Cycles that do not map to a crate DAG
