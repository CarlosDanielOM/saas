---
title: Custom widgets
description: Import StreamElements widgets into Overlay Studio, adjust their settings, test them, and publish them to OBS.
---

Custom widgets let you add a StreamElements custom widget to an Overlay Studio overlay. Import it once, then add it as a layer and give each layer its own settings. StreamElements widgets and native Dima widgets run in an isolated area.

For the full package format and the Dima SDK, see [Building widgets (Dima SDK)](/building-custom-widgets-dima-sdk/).

## Import a widget

Open **Modules → Overlay Studio**, choose an overlay, and select **Import widget**. Choose the widget’s `.zip` or `.rar`, its folder, or its files. You can also drag the files into the import area. Many StreamElements widgets come as `.rar` archives, which import like `.zip` files. Password-protected or split archives cannot be opened; extract one first and choose its folder. Both archive formats allow up to 300 files and 8 MB unpacked. A normal StreamElements package contains:

| File | What it contains |
|---|---|
| `widget.ini` | The paths to the widget’s other files. |
| `html` | The page structure and content. |
| `css` | The widget’s appearance. |
| `js` | Its behavior and event handlers. |
| `fields` | A JSON object describing the settings you can change. |
| `data` | A JSON object with saved setting values. |

HTML, CSS, JavaScript, fields, and data files are required as a set, though missing fields or data files can be left empty. The package must include some HTML, CSS, or JavaScript. Overlay Studio also accepts a `widget.json` manifest for native Dima widgets; StreamElements packages usually do not have one.

Before you add the widget, Overlay Studio shows its engine and **Uses:** list. This list comes from the widget’s manifest or, for StreamElements packages, is inferred from its code. It tells you what live information it asks to receive:

- **Chat messages** — new messages, message deletions, and chat clears.
- **Follows, subs, Bits and raids** — alert events. Tip events are listed as a supported category, but real tips do not fire yet.
- **Saves its own data** — persistent key/value storage for the widget.
- **Commands can control it** — chat commands can send signals that the widget reacts to.
- **Command counters** — read command-use counts.
- **Recent events and stream totals** — the session’s recent alerts and totals.
- **Twitch polls and predictions** — read current poll and prediction totals, without voter identities.
- **Goals and their progress** — read goals and current progress from the Goals page.
- **Text-to-speech messages**, **Trigger alerts**, and **Channel-point redemptions** — observe these bot events as they happen.

A widget that does not ask for live data receives none. Overlay Studio only delivers the categories the widget declared.

## Write code in Studio

In the Add panel, choose **New widget** in the custom widgets list. Give the widget a name and choose a starter. **Dima SDK** is recommended: its settings update live and it includes a `widget.json`. **StreamElements-compatible** uses `onWidgetLoad` and `onEventReceived`; the same files also work on StreamElements. Choose **Start coding**, then **Create widget** to save it and add it to the current overlay. New widgets count toward your plan's custom widget limit: Free 1, Premium 5, Pro 25.

Choose **Edit code** in a custom widget layer's settings to open the same editor for an imported or created widget.

The pencil button beside the widget name is labeled **Rename widget**. Type a name and choose **Rename** or press Enter; press Escape to cancel. The new name is saved right away and isn't part of the files, so it doesn't create a version. If `widget.json` still has the old name, the editor changes it as an unsaved edit; save to keep it, since that name is used on import. Layers still showing the widget's old name follow the new name; layers you renamed keep their names.

The tabs contain HTML, CSS, JS, **Fields** (`fields.txt`, the settings shown in the right panel), **Data** (starting values from `data.txt`; changes in the right panel still win for each layer), and `widget.json`. A StreamElements widget without `widget.json` shows **Add widget.json**. It creates a manifest from what Studio worked out from the code.

The preview runs unsaved code at the layer's size in the same sandbox as the overlay. On phones, switch between **Code** and **Preview**. **Try it** sends test chat messages and alerts, but only the kinds listed in the widget's `widget.json`. Choose **Restart** to restart the preview. The widget log shows its messages, warnings, and errors.

Broken JSON or files over the size limits are errors. A tab shows the error count; choose a problem to jump to its line. Errors block saving, and the preview keeps the last version that worked. Settings or values that would be skipped appear as things to check, but do not block saving.

**Save** (or Ctrl/⌘+S) creates a new version. Studio layers use it right away. Overlays in OBS keep their version until you publish. Unsaved changes stay in this browser until you save or discard them; reopening the editor restores them.

If the widget changed somewhere else after you opened it, such as in another tab, saving warns you and offers **Save anyway**.

**Versions** lists the 10 most recent versions and any version used by a published overlay. **Open** loads a version as unsaved changes. Save to use it again.

Escape inside the code does not close the editor. Press Escape, then Tab, to move focus out of the code.

As you type, suggestions show Dima SDK calls, events (including any `widget.json` `uses` entry they need), handler data fields, your settings after `Dima.fields.` and in `{key}` placeholders, and StreamElements `SE_API`, event details, and listener names. Suggestions also show valid keys and values in `widget.json` and Fields; hover over `Dima` or `SE_API` for a description. Escape closes the suggestion list.

## Use your own code editor

In the preview column, open **Use your own code editor** and choose **Download for your editor**. The zip contains `widget.html`, `widget.css`, `widget.js`, `fields.json`, `data.json`, `widget.json` when the widget has one, and `widget.ini` so it can be imported again. It also includes `dima.d.ts` and `jsconfig.json` for Dima SDK, event, and setting suggestions and checks in editors such as VS Code, plus a `.vscode` folder with checks for `fields.json` and `widget.json`.

Edit the files, then choose **Load a folder** or **Load files** with a `.zip`, `.rar`, or individual files. Only loaded files replace their matching tabs, as unsaved changes. If `widget.json` is not included, the current manifest stays. Check the preview, then save. Archive limits and password or split archive restrictions are the same as for importing. In StreamElements widgets, `{key}` placeholders in `widget.js` are replaced before the code runs, so your editor may mark those spots.

## Add and adjust a layer

Add the imported widget from the layer palette. Open its **Settings** to edit it. Fields appear in collapsible groups; fields without a group appear under **General**. Use **Find a setting** to search. A **Changed** marker shows settings that differ from the widget’s saved values. Choose **Reset** for one setting or **Reset all** to restore them.

Settings belong to each layer. You can add the same widget more than once and style each copy differently. **Save draft** saves the overlay’s layer settings. **Publish live** sends a snapshot to connected OBS browser sources. Later draft changes do not affect OBS until you publish again.

When you replace a widget’s files, its changed settings stay unless the new files remove those fields. Draft layers use the newest files. An already published overlay keeps the widget version it was published with until you publish that overlay again.

## Commands can control it

A widget that lists `"signals"` in `uses` can react when a chat command runs. In the layer’s **Settings**, the **Commands** block shows each signal declared in `widget.json`, its description and example values, a ready-to-paste response, **Copy**, and **Make a command**. If the widget has no declarations, Studio offers one **Any command** entry.

**Make a command** opens the Commands page in a new tab with the command pre-filled (for example `!feed`), including its name, response, and description. Nothing is saved until you press **Save**. Choose the command’s access and cooldown as usual; for visual effects, you can make it mods-only. A pet command could reply `$(user) fed Mochi! $(widget.signal feed &p1)`: chat shows “Ada fed Mochi!” while the pet eats. Etsy or StreamElements pet widgets are a natural fit for `!pet` and `!feed`. Values use command arguments such as `&p1`, `&p2`, and `&t` (all text after the command), not `$(1)`.

A signal can reach every matching widget in published overlays open in OBS. When another widget in the same overlay also uses signals, Studio suggests a targeted response such as `$(widget.signal.to "Pet" feed &p1)`, so only that layer reacts. Targeting works when the layer name uses simple letters, numbers, spaces, and `_ ' . , ! ? -`. Otherwise, Studio notes that the other widgets can react too and suggests a simpler name. Two layers with the same name both react. If you rename a layer, update its commands. Studio also warns when another layer has the same name and shows how many command signals were skipped recently.

Signals are sent only by real Twitch chat commands, keywords, referenced commands (`#(name)`), and Chat event messages such as follow, sub, and raid announcements. Timers, channel-point rewards, roulette, AI requests, and dashboard or docs-assistant tests cannot send them; they return `Error: widget_signal_context_required`. Text typed by a viewer that looks like `$(...)` is never run. Names are lowercased, then limited to lowercase letters, digits, and `_` (up to 40 characters); for example, `FOCUS` becomes `focus`, while `pet.feed` returns `Error: invalid_widget_signal_name`. Values are limited to 500 characters (`Error: widget_signal_too_long`). Up to 5 signals are allowed per command run, shared with referenced commands, and up to 30 per channel in 10 seconds; extra signals are silently dropped and counted. Duplicate delivery of the same Twitch chat message does not send the signal twice. Signals are live-only and are not replayed when OBS reconnects, like chat.

## Test in Studio

Open **Test** and find **Custom widget tests**. Choose **Preview** to send tests only to the editor preview. The **Command signal** row lets you enter a name (or choose a declared signal chip), an optional value, and press **Send signal** to test the preview. Choose **OBS** to send it to OBS after the usual confirmation; OBS tests count toward the 30-per-10-seconds channel limit and appear as the broadcaster with source `studio`. Chat tests include **Viewer**, **Subscriber**, **VIP**, **Moderator**, **You**, **First-time chatter**, **Emotes**, **Reply**, **Long message**, and **!command**. Alert tests include **Follow**, **Sub**, **Resub**, **Gift sub**, **5 gift subs**, **Bits**, **Raid**, and **Tip**. Moderation tests include **Delete last message** and **Clear chat**.

The test buttons inside a widget’s own settings also send a button event to that widget in the preview. They do not send a real alert or message.

When a widget in the overlay uses a live-state or bot-event category, the **Bot events** row offers **TTS message**, **Trigger**, **Channel points**, **Sample poll**, and **Sample goals**. TTS sends a start event and an end event three seconds later. The same tests are available in the code editor preview. Choose **Preview** or **OBS** as the destination; sample state sent to OBS appears for about a minute, then the real state returns. Studio previews begin with the channel’s real polls and goals.

Widgets read poll and prediction totals with `Dima.state('polls', handler)` and goals with `Dima.state('goals', handler)`. The handler runs once when the value is first known and again when it changes. No callback means the value is not known yet; it does not mean there are no polls or goals. Polls and predictions reach the widget after their Twitch events are enabled. Open the layer’s **Polls & predictions** setup, which is the same setup shown on the Overlay tab. Poll state never identifies who voted. Goal state includes targets and progress, updates within seconds when goals or progress change, and is refreshed at least once a minute for time-based changes. It does not run goal completion actions.

Bot events are live-only and are not replayed after OBS reconnects. TTS sends `start` when audio plays and `end` once when it finishes; a message that never plays sends no event. Trigger events say which alert was sent but do not include its media URL or play the media in a custom-widget-only overlay. Channel-point events include every redemption, even one without a bot action. Treat redemption input as viewer text: display it with `textContent` or `Dima.escape()`.

The **Replay recent chat** button in the **Chat** row works in the preview only. It sends the last 20 stored channel messages, oldest first. Replay contains text only: it has no emotes, name colours, or badge images, and messages deleted by moderators may be included, so replay is not sent to OBS.

Test alerts also update session data, so goal widgets that listen for session updates react in the preview and in OBS. Studio sends the updated totals after each OBS test alert. Tests are sample data and never change your real totals or goals.

Choose **OBS** in the test drawer to send tests to the connected sources for the published version of this overlay. Publish your changes first if the widget changed. The editor asks you to confirm because chat tests and alerts can be visible on stream. A test alert for a tip is sample data only; real tip events are not available yet.

## Widget log

Open the widget’s **Settings** to see its **Widget log**. It shows messages written with `console.log` or `Dima.log`, warnings, and errors from the widget. In Studio it also notes each command signal the widget receives, for example “Signal feed → pizza from Ada”. Use **Clear log** to remove the current entries. The log keeps up to 200 recent entries; excess messages are dropped when a widget writes too many in one minute. If the widget freezes repeatedly, Studio restarts it and eventually turns it off; fix the code or replace its files, then reload the overlay.

## StreamElements media

After importing, Overlay Studio can find images, videos, and sounds loaded from StreamElements. Images, videos, and sounds hosted on `cdn.streamelements.com` or `static.streamelements.com` can be copied. Anything else keeps loading from its original link. Choose **Copy to my storage** to put supported files in your Asset Library. The widget then uses those stored copies. This keeps media working if the original StreamElements file is removed. Copying uses your plan’s design storage; a file over 50 MB or a file that cannot be copied remains linked to StreamElements.

Choose **Keep loading from StreamElements** to leave the links as they are. This saves your storage, but the widget’s media can stop appearing if StreamElements removes a file or the link stops working. You can copy files later from the widget’s settings.

## Export for StreamElements

Choose **Export for StreamElements** in the widget’s settings to download a StreamElements-compatible `.zip`. The export contains `widget.ini`, the original HTML, CSS, JavaScript, and fields files, plus a `data.txt` with the values for that layer. Use the zip when importing the widget into StreamElements.

## Plan limits

Each channel can import up to **1 custom widget on Free**, **5 on Premium**, or **25 on Pro**. The limit counts imported widgets, not the number of overlay layers using them. Deleting a widget removes its files, and you must first remove it from every draft and published overlay that uses it.

## Goal data

Widgets that read session data show a folded **Goal data** section in the layer settings. It identifies which Goals page entry supplies each **Manual** value: **Followers**, **Subs**, **Bits**, and **Money**. For each kind, the first active goal in your list is used; if none is active, the first reached goal is used. If there is no matching goal, the value is 0. **Open Goals** opens **Dashboard → Goals** in a new tab.

The manual value is goal progress, not its target. Choose how a goal counts on the Goals page: since creation, current count, set dates, rolling window, or calendar month. Money values use currency units (for example, `12.34`) and include everything counted by that goal, such as Bits, subs, and custom items—not only tips. Widgets update within seconds when goal progress or goals change.

Session data also provides `follower-month`, `subscriber-month`, `cheer-month`, and `raid-month` for the current UTC calendar month. `follower-total` and `subscriber-total` are your current dashboard totals; follows update as they happen. `cheer-total` and `raid-total` cover the last 90 days and can decrease as older events age out. Subscriber counts include each subscriber once plus gifted subs, so a 5-sub community gift adds 5. `*-session` covers the current stream, or the last 24 hours if no stream start is available; `*-week` covers the last 7 days. Tip event values (`tip-*`) stay at 0 until DomDimaBot tipping is available; the **Money** `tip-goal` value can still show a Goals page goal.

## Not available yet

- Pet events, DimaFX purchases, duels, and roulette events. Each needs fixes before it can be added.
- Live sync from a local editor.
- Real tips do not trigger custom widgets until DomDimaBot tipping is available; the Studio **Tip** test only sends sample data.
- 7TV, BetterTTV (BTTV), and FrankerFaceZ (FFZ) emotes are not supported.
- StreamElements API tokens and APIs that only StreamElements provides are not available.

## Safety

Widgets run in an isolated area. They cannot access your DomDimaBot account, sign-in, site storage, other overlay layers, or OBS controls. They only receive the live data categories listed in **Uses:**. Treat widget code as something that can appear on stream, and review a widget before publishing it.
