# Semantic moderation decision helper — 2026-10-30

## Scope and reuse

This migration slice covers `dimabot/src/utils/moderation/semantic.ts`: ten runtime exports and the exported `SemanticResult` interface. It reuses native advanced moderation policy/model selection, spam categories and questions, the shared spam rule identifier, JavaScript-compatible credit rounding, lossless JSON and UTF-16 helpers, and OpenRouter attribution. The new native path uses the opt-in `moderation-semantic` feature and its existing `http-client`/credit-policy dependencies. It does not add a MongoDB or Redis requirement.

The native module provides typed policy/result APIs plus raw ordinary-JSON request and evaluator adapters. The latter preserve missing versus explicit null values within JSON input and feed a concrete pooled HTTP client. Request construction precedes deadline/channel/key preflight. The environment-backed evaluator refreshes the API key for each request, bounds headers and body under one remaining-time duration, and retains the requested model when the provider response has no request ID. A private loopback HTTP path is used to exercise request bytes and transport behavior.

## Source contract and limits

The source API accepts `unknown` values and has JavaScript object semantics. The native boundary represents declared typed inputs and ordinary JSON data; it does not reproduce getters, prototypes, proxies, `undefined` identity, sparse arrays, symbols, functions, BigInt, cycles, arbitrary JavaScript model objects, or every engine-specific error message. The declared spam category literals are exactly `spam`, `ads`, `self_promotion`, `profanity`, and `insults`. Two oracle records carry unknown categories outside the declared union; they assert native enum rejection and retain the unchecked source result. Other invalid ordinary JSON inputs are checked through the native raw adapters.

Response parsing uses the shared lossless JSON implementation and inherits its nesting limit. Reqwest diagnostics and independent client/connect timeout identity are native behavior. The evaluator samples the injected wall clock after constructing the request and on caught failures; the initial remaining duration bounds monotonic HTTP work. A wall-clock jump during transport is therefore represented by the explicit clock seam rather than by assuming Date and monotonic time are interchangeable. Source fetch observations have no network bytes; transport error, deadline cancellation and clock-resampling behavior are checked separately through the native HTTP adapter.

The exact `semantic.ts` path is not a moderation worker: queue/Mongo orchestration, billing adapter and Polar integration, moderation consequences, and caller wiring remain separate dependencies. The live TypeScript source and callers remain active pending any later migration and adoption work.
