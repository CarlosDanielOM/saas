Follow Defense monitors incoming follows and can suppress follow alerts, track a burst, or queue bans when Attack is activated. It runs in the background. Review the settings and explain the moderation controls to your moderators before enabling automatic Attack actions.

## Modes and default settings

| Mode | Default behavior |
|------|------------------|
| **Normal** | No active defense mode. |
| **Silent** | Enabled by default. Starts at 10 follows within 5 seconds. Follow alert chat messages are suppressed, and the burst is tracked. It does not ban accounts. |
| **Protection** | Enabled by default. Starts at 100 follows in the detection window. Outside a raid, it posts a warning and tracks the burst. It does not queue bans; the wave can later escalate to Attack. |
| **Attack** | Enabled by default, but its automatic threshold is dynamic by default (the setting is empty), not a fixed 500. When triggered outside a raid, it queues bans for the tracked wave. A moderator can also request it manually. |

The default mode duration is 60 seconds. New qualifying follows can extend an active mode. The silent threshold, detection window, protection threshold, mode toggles, duration, and attack threshold can be changed in the Follow Defense dashboard. Thresholds are positive follow counts; the detection window and duration are in seconds.

<Aside type="caution">
Outside separately authorized raid-session moderation, only Attack queues Twitch bans. Those are not timeouts, and bans may be permanent. Protection tracks the burst and warns without banning. A threshold is only a signal of unusual activity, not proof that every follower is abusive. Tune thresholds to your channel and review the tracked wave before enabling automatic Attack actions.
</Aside>

## Automatic attack sensitivity

Leave **Attack threshold** empty to use dynamic sensitivity. The system derives a threshold from recent channel follow and stream history after it has at least 7 sample days and 3 completed stream records. The calculation is at least 500 and may be higher for channels with a larger baseline. If there is not enough usable history, automatic attack mode has no threshold and will not activate from a threshold; Protection and Silent can still activate. You can enter a positive integer to set a fixed attack threshold.

The settings API still stores a `baselineFollowsPerHour` value, but the current follow detection code does not use it to calculate thresholds, and the Follow Defense page does not expose it as an editable field. Automatic attack sensitivity comes from the historical baseline described above.

## Follow alerts and tracking

Silent mode suppresses follow alert chat messages while defense state is active. The follow handler may also skip alerts when the same event has already been assigned to a defense state, preventing duplicate messages. The source code does not establish that every third-party overlay or unrelated trigger is suppressed, so check those integrations separately.

The system tracks follows in the active burst for escalation and history. A follow burst by itself does not establish malicious intent. Attack history records the triggering mode, whether a raid was associated, follow totals, and ban outcomes where available.

## Raid behavior

An incoming Twitch raid creates a five-minute raid marker when it meets the EventSub raid minimum configured for the channel. Follows are tracked during the raid session, but ordinary burst thresholds do not automatically start Attack mode or ban raid follows. Raid sessions also have separate review and moderation controls in the dashboard.

When **Reset attack on new raid** is enabled (the default), an active Attack state is changed to Protection for a new raid. Turning this option off carries an eligible active Attack state into the new raid, which can result in the new raid's follows being banned. This option requires moderation-management access to change.

<Aside type="note">
Use the dashboard's raid-session controls to review or authorize raid moderation. A manual `attack` request while a raid is being tracked may queue recorded raid followers for moderation review; it does not guarantee immediate bans. Follow Defense may retain raid history and identify a raider as a possible hate-raid source, but that label is not proof of intent.
</Aside>

## Manual controls

The AST function `$(bot.mode attack)` requests Attack mode; `$(bot.mode status)` reports the current mode and remaining time. For example, you can make a command named `!defmode` whose response is `$(bot.mode attack)`. The function requires moderator-level permission in normal command execution. Keep the command restricted to trusted moderators because it can queue bans.

The dashboard also offers **Activate Attack**, **Reset mode**, current status, attack history, and raid-session review. Dashboard access requires channel owner or admin access; activating attack and changing raid moderation settings require moderation-management permission.

## Recommended setup

<Steps>

1. Open Follow Defense from your channel dashboard and review the current mode and tracked followers.
2. Keep the defaults for an initial observation period, or disable the system if another service already handles follow defense.
3. Set thresholds above normal bursts. Leave the attack threshold empty for historical dynamic sensitivity, or set a fixed threshold only when you have a clear reason.
4. Decide whether Attack should reset to Protection on a new raid. Leave the default enabled unless your moderators explicitly want active Attack mode to carry into incoming raids.
5. If you create `!defmode`, restrict it to trusted moderators and explain that it may queue moderation actions.
6. After an incident, review attack history and raid sessions, then adjust thresholds based on what happened.

</Steps>

## Disable Follow Defense

Turn off **Enable Follow Defense** in the dashboard to stop follow-defense processing for the channel. This prevents new defense decisions and defense-driven alert suppression. It does not delete existing history. Disabling Attack or Protection cancels pending defense actions. If you depend on another bot or service, confirm its alert and moderation behavior before switching systems.
