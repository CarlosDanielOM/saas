# Retired TypeScript worker entrypoints

This archive preserves the five TypeScript worker entrypoints removed from the cron source tree on 2026-10-21. Their original paths, source digests, and base commit are recorded in [`manifest.json`](manifest.json).

The archived files preserve their original bytes and import paths. They are historical source only: the archive is outside the application build and Docker image, and its files are not executable in place. The five scheduled responsibilities always use their native Rust binaries in both the Node cron runtime and `tsx` development. The former `*_RUNTIME=typescript` keys are retired selectors; setting them does not select archived code. Native startup or process failure is handled by the supervisor's same-worker Rust restart, with no TypeScript fallback. `cron:dev` with `CRON_WORKER_RUNTIME=tsx` requires the five native binaries at the paths defined by native worker metadata under `/usr/local/bin/`; missing binaries are reported/retried as Rust children without TypeScript substitution.

The current Rust-only policy requires the five worker behavior suites and a sixth retirement check on each cron candidate. To intentionally restore TypeScript, manually copy the required original file to its recorded path, review the supervisor registration and corresponding tests, and revise the matching Rust-only retirement assertions that require its absence. Preserve the five workers' functional coverage and verify the updated candidate before deployment. There is no automatic archive restore command, selector, fallback flag, or quick restore script. Follow the current policy and release record in [`migration-notes/typescript-worker-retirement.md`](../../../migration-notes/typescript-worker-retirement.md).

The archive covers only these five scheduled entrypoints: stream activity; raid analytics; follow-defense **baseline**; roulette **completion**; and AI usage receipts. Other TypeScript cron workers, producers, APIs, utilities, and the `roulette-actions` child remain active. Some shared TypeScript helpers serve both APIs and parity fixtures; retained helpers and fixtures do not provide a scheduled worker runtime or fallback.
