# Blacklist native authoring handoff

The owned files are an uncompiled draft. Copy `src/utils/moderation/blacklist.rs` and `tests/moderation_blacklist.rs` into the crate, register `moderation::blacklist`, and add the opt-in `moderation-blacklist` feature depending on `moderation-normalize` and `js-regexp-unicode`. The implementation assumes `js_regexp_unicode::{canonicalize,is_letter_or_number}`, `js_compat::is_whitespace`, `js_string::JsString`, and `moderation::normalize::{fold_text,escape_reg_exp}`. It needs no production services or new dependencies; tests use the existing serde_json dev dependency. Neither compilation nor tests were run under the authoring-only restriction.

The native `BlacklistRule { terms: Vec<JsString> }` corresponds to the source's `Pick<IModerationRule, 'terms'>`; the schema has required `terms: string[]`, and the evaluator does not read it. `Option<&JsString>` represents the source typed string/nullish `input.text` boundary, not arbitrary JS coercions. `compile_blacklist_pattern` accepts undefined/empty terms as `None`/empty slice; each supplied term is a string. `source()` and returned matches preserve UTF-16 including lone surrogates. `exec` accepts already-folded or raw text and returns UTF-16 indices into that exact input. Evaluation returns the matched folded substring. `flags()` is `iu`.

The exported TS evaluator can receive any RegExp, including mutable global/sticky instances, but this Rust API only accepts its own compiled blacklist patterns. Current handler caches results of `compileBlacklistPattern`, rules/index forwards them, and advanced.ts uses `compileBlacklistPattern(...).exec(folded)` for original-offset mapping. General RegExp inputs and state are not supported and no caller integration is included. Source trace: `src/utils/moderation/rules/blacklist.rule.ts`, `rules/index.ts`, `handlers/moderation.handler.ts`, `utils/moderation/advanced.ts`, and the terms schema.

The trie tracks original alternative rank after stable descending UTF-16 sorting, retaining leftmost search, greedy whitespace and boundary fallback. Valid pairs are read atomically; lone surrogates stay intact. Boundary classification uses the pinned simple case-folded value, including U+0345. The /iu Unicode compatibility helper is independently authored and is a required dependency; verify its property/case-fold behavior against the oracle. `normalize` remains a required dependency and its Unicode 17 behavior must also be verified independently. No performance claim is made.

The ignored replay expects an external actual-source fixture `moderation-blacklist-reference.json` in `DIMA_MODERATION_BLACKLIST_FIXTURE_DIR` (absolute, canonical, outside crate), with independently supplied `DIMA_MODERATION_BLACKLIST_FIXTURE_SHA256`. It checks Node/Unicode/TS versions, Node executable hash, source file hashes and case results. The fixture schema was coordinated with `/root/blacklist_reference`: `metadata` includes `format`, `pins`, `nodeSha`, `versions`; `cases` includes `name`, `terms`, `text`, `compiled`, `foldedText`, `execFolded`, `execRaw`, and `evaluation`. Test integration and replay still need validation with the generated fixture and the shared Unicode helper. No generated fixture, test execution, deployment, commit, or production action was performed.
