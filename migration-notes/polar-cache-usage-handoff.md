## Source and reuse

`dimabot/src/utils/polarsh.ts` SHA-256 `5164452aea1747b72a410098bb8cd54c2cc0a4312f52e40728936c9c2f6e9fec`. The semantic call uses `contextual_moderation`, a stable `moderation:{decisionId}` external ID, LLM tokens, request ID, model and resource metadata. The event list `twitch:{channel}:ai:polarshevent` is separate from `cron:ai-usage-receipts:queue`. `queueEvent` inspects and migrates legacy string JSON, deletes it before pushing migrated elements and then the new event. `projectAcceptedUsage` runs local projection, receipt enqueue, then analytics; cache branch makes no Polar provider call. Existing Rust `AiCreditProjection`, `AiUsageProducer`, lossless PostHog transport/tracking, native Redis manager, JS rounding/number/JSON compatibility and new shared `ai_usage_lossless` context/enrichment are reused. Producer and projection constructors have no IO; default Redis and PostHog are lazy. Receipt/PostHog failures are best effort; the existing projection wrapper catches its own error. Unknown Redis mutation outcomes must not be replayed.

The 8-second NX/PX channel lease protects queue migration and flush coordination. The source polls at 350 ms while its nominal 2.5-second coordination budget remains, so its final unconditional sleep can overshoot that budget. The native implementation caps the final sleep to the remaining monotonic time, keeping the coordination wait within the nominal budget. These waits are for a future lease, not an artificial ready-work cadence. After contention the caller still queues and projects without acquiring the lease, as source does. Source release performs separate GET and DEL and may delete a replacement owner in the interval between them. Following the parent’s user-facing review decision, the native branch intentionally replaces both operations with one atomic owner-checked `ai_usage_lock::RELEASE_SCRIPT` EVAL. Normal release outcomes are preserved, an expired owner cannot delete a replacement, and an unknown EVAL outcome is not replayed. The capped wait and atomic release are accepted migration improvements, not byte-for-byte source I/O.

## Authored tests and exact gaps

The pinned Node/V8/TypeScript oracle extracts actual checkout declarations, records AST/type/hash evidence, and uses actual `ai_usage_event.ts` and receipt builder/enqueue source through the existing loader with scripted boundaries. It generates valid, missing-input, numeric/model, UTF-16, context overrides, legacy and array-like coercion, failed legacy migration, contended, owner-change, projection/receipt/analytics failure, and ordering scenarios. It demands an existing owner-created directory, exclusive `--write`, and byte comparison with `--check`.

The authored Rust replay visits every generated record and compares event bytes; an additional private-Redis replay compares the complete normalized Redis call sequence, including logger call position, queue values, projection keys and arguments, receipt payload (excluding real clock fields), result and diagnostic categories, and a concrete loopback PostHog event's identity/properties. It collapses repeated contention polls into one acquisition, maps source lock GET/DEL to the accepted atomic EVAL, and normalizes Redis adapter-specific injected error messages. PostHog capture is checked by flushing the concrete queue after ingestion; the external HTTP delivery time is not proof of the exact synchronous source capture instant. Source projection-failure behavior is a scripted boundary equivalent to the existing projection wrapper, rather than running real billing TypeScript.

`tests/support/polar_cache_usage.rs` authors a bounded protocol forwarder to real private Redis. Its native lock-owner test waits for successful upstream Polar RPUSH acknowledgement, substitutes a new owner while the response is gated, and checks the actual atomic release retains that token. Its response-loss test forwards Polar RPUSH, consumes the successful real reply, disconnects without returning it, verifies one item using an independent socket, and counts one forwarded Polar RPUSH and one release EVAL. These assertions and the broader replay passed in `compiler-fixtures-1793351297978548916`; the final Node source corpus is bound to `node-1793351297978993028`. They require the literal alias `redis://keyword-redis:6379/`, `KEYWORD_FIXTURE_OWNER=polar-cache-usage`, an explicit `keyword-fixture-[12 lowercase hex]:` namespace, and fresh exact keys; tests must run serially because the receipt queue uses its original global name. Panic-path cleanup targets only the task-owned event, receipt payload and keys; an early cleanup failure can still leave them for the parent to remove with the isolated fixture. The older real-Redis test owns its exact keys on success; the parent must clean its isolated fixture after a failure.

The adapter uses the concrete native `Logger` with `RedisCacheSink` and `StdConsole` by default, or accepts an already shared concrete application logger, and uses a console-only logger if default Redis acquisition fails. Its sinks are bounded and use `serde_json` and UTF-8: source diagnostics containing lone UTF-16 surrogates are lossy here. Default construction does not attach the TypeScript logger's `recordLog` telemetry and OpenTelemetry providers; a shared application logger with those concrete sinks is required to recover that integration, and no application-wide lazy logger runtime currently supplies it. Redis error wording and bounded sink behavior also differ from source; native selected sinks run concurrently whereas the TypeScript logger awaits cache before console. These are named adapter limitations rather than parity claims; no telemetry provider is created autonomously.
