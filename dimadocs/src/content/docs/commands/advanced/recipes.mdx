Use these patterns as starting points. Test state changes and action functions in a restricted command before enabling them for chat.

## Best practices

### Initialize or increment a channel counter

```bash
*( ^(#wins) ? %(#wins *(%(#wins) + 1)) : %(#wins 1) )
"$(user) has %(#wins) wins!"
```

This writes `#wins` in channel cache. Cache values expire 24 hours after their most recent write. For durable state, use a database variable such as `%(*wins ...)` or a user database variable such as `%(**wins ...)`; database writes require Premium or Pro.

### Read another user's state

```bash
%(##rank(&p1))
```

Here `&p1` must resolve to the target user's login. Without a selector, `##` and `**` variables refer to the current user.

### Guard an action with a condition

```bash
*( %(#ready) == 1 ? "Ready" : "Not ready" )
```

A ternary chooses one result. Put state-changing functions only in the branch where they should run, and make sure the command’s configured permissions allow the intended users to invoke it.

## Pattern summary

| Pattern | Syntax idea | Purpose |
|---------|-------------|---------|
| Initialize-or-increment | `*(^(#x) ? %(#x *(%(#x) + 1)) : %(#x 1))` | Create a missing counter or increment it |
| User selector | `%(**rank(&p1))` | Read a user's persistent value |
| Guard | `*(condition ? ACTION : "")` | Run an action only when a condition is true |
| Branch | `*(condition ? YES : NO)` | Choose one expression based on a condition |

## Event driven patterns

For redemption or EventSub commands, first confirm the command is attached to the relevant event. For example, `$(reward.input)` is meaningful in a channel points redemption context; it can be empty during ordinary chat execution.

Keep moderation, role changes, channel settings, polls, TTS, and trigger actions behind appropriate command or event access controls. Test the text and conditions before adding those actions.

<Aside type="caution">
The bot performs real actions when these functions run. Test with a harmless message or a restricted command before enabling actions such as `$(ban ...)`, `$(set.title ...)`, or `$(trigger.send ...)`.
</Aside>

## When a command gets hard to maintain

Split the work into smaller custom commands and call them with `#(commandName args...)`. References are limited to five nested levels, and repeated references on the same call path are stopped.
