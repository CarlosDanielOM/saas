Overlay Studio lets you design one or more layouts for OBS. Each layout can show alerts, text-to-speech, clips, trigger media, Twitch polls and predictions, text, images, and videos. Overlay Studio is in **Alpha** and is available on every plan, starting with Free. Only the channel owner can edit overlays. Sign in as the Twitch account that owns the channel.

## Set up an overlay

1. Open **Modules → Overlay studio**.
2. Select **New overlay** or pick an existing one. Enter a name, then set **Canvas width** and **Canvas height**. Each can be 100 to 7,680 pixels.
3. Add layers from the palette. Drag them on the canvas, or change their position, size, visibility, lock, and order in the editor.
4. Select **Save draft** while you work.
5. Select **Publish live** when the overlay is ready. Use **Save & publish live** for alert designs.
6. Open **Browser source & publishing**, select **Copy URL**, and add the URL to OBS as a **Browser Source**. Set the width and height to the canvas size shown in the editor. Keep the source active.

Each channel can have up to 25 overlays, 50 alert designs, and 60 layers per canvas. Changing the canvas size keeps every layer where it is. If a layer now sits past the edge, the editor shows a warning, and you can select it under **Layers** to move it.

## Layers you can add

| Layer | What it shows |
|---|---|
| Poll | Twitch poll and live vote totals |
| Prediction | Twitch prediction, points, and results |
| Text to speech | Spoken messages and alerts |
| Trigger alerts | Trigger media. You can limit a trigger widget to chosen triggers |
| Clips | Viewer clips |
| Alerts | A saved alert design, placed anywhere |
| Image, Video | A permanent image or looping video |
| Shape | A rectangle or ellipse |

Polls and predictions show real Twitch data only after you publish the overlay and activate Twitch events from the editor. Until then, the editor shows sample data.

Inside an alert design you can also add **Text**, **Image**, **Video**, **Animation**, and **Shape** layers.

## Build alert designs

An alert design has its own layout for **Follows**, **Bits**, **Subscriptions**, and **Raids**. An alert layer picks which of those events it shows. An overlay can have several alert layers. You can reuse a saved design in other overlays.

- Editing a shared design changes every draft that uses it. Publish each overlay to update its live version.
- Use **Save as a new design** to copy a design instead of changing it.

Alert text uses these values:

| Value | Shows |
|---|---|
| `$(user)` | Viewer name |
| `$(cheer.amount)`, `$(cheer.message)` | Bits amount and message |
| `$(sub.tier)`, `$(sub.months)`, `$(gifted.user)` | Subscription tier, months, and gift recipient |
| `$(raid.channel)`, `$(raid.viewers)` | Raiding channel and viewer count |

For Bits, use `$(cheer.amount)`. `$(amount)` does not work. Alert text can format values (for example `upper` or `title`). It cannot run commands or change state.

### Bits looks

On the **Bits** tab, your [Bits rules](/chat-events/#bits-rules) decide which look plays. They're the same rules as in Chat events.

- **Default look** plays for cheers that match no rule, and for rules without their own look.
- Select **Give it its own look** on a rule to start a look from the default one, then edit it on the canvas. **Use the default look** removes it.
- **New rule** creates a rule (it shows in Chat events too) and gives it its own look right away.
- A rule with its overlay alert off plays no alert. Select **Turn alert on** to change that.
- Type a **Sample amount** to see which look a cheer would play.

Rule changes (amounts, on/off, alert) save and apply right away, even to published overlays. Looks are part of the design: save and publish the overlay to update them in OBS.

Subscriptions and raids use variants instead: add one for a subscription tier or a minimum raid size. The first matching variant that's on plays.

### Alert sounds

Choose **Choose sound** on an alert event to add a sound from the Asset Library. Sounds can be MP3, WAV, or Ogg, up to 10 minutes and 50 MB. You can set volume, delay, and fade in and out. The sound plays once and stops when the alert or the file ends. A delay longer than the alert means no sound plays. Set the volume to 0% to mute it.

## Images and videos

Select **Browse Asset Library** on an image or video layer to pick a design asset. You can also enter an HTTPS **Media URL**. Videos on global layers loop without sound. See [Media Library](/media-library/#design-assets) for file types and storage limits.

The overlay link is private, but anything shown on stream is visible to viewers.

## Publish and OBS

- **Save draft** saves your changes but does not change OBS.
- **Publish live** updates connected sources. Each source gets the new version and keeps its pending playback.
- Publishing saves a snapshot of the overlay and the alert designs it uses. Later draft changes do not appear until you publish again.
- An event that is already playing keeps the layout it started with.

The overlay URL is a private, read-only link. Treat it like a password. **Replace overlay URL** creates a new link, and the old link stops working right away. Update your OBS sources afterwards. The overlay page sends no referrer.

### Test in OBS

Use the preview under **Try it** to check layout and sample alerts without sending anything to OBS. For a real test, publish first. Then choose an event under **Test in OBS** and select **Test this overlay in OBS**. You confirm before anything plays on stream. The test needs at least one connected, published source.

## Queues and playback

- **Wait for each other** is a setting for each event type. Selected events share one queue and play one at a time. Other events play right away.
- A connected source gets new events while it stays connected.
- A refresh or a brief disconnect recovers pending playback within about 2 minutes. If a source stays offline longer than that, its pending playback is dropped, and events from that time are not played when it returns.
- Each source keeps up to 200 pending events for 30 minutes. A channel keeps up to 512 MB of generated media. Older events are removed first.
- Adding an Overlay Studio source does **not** turn off older TTS, clip, or trigger browser sources. If both run, viewers will hear events twice. Keep only one path active.

## Troubleshooting

- **You cannot open the editor:** Sign in as the channel owner. Only the owner can edit overlays. Published overlays keep working after plan changes as long as the linked Twitch account exists.
- **A change is missing in OBS:** Select **Save draft**, then **Publish live**, then refresh the browser source.
- **OBS stopped after you replaced the URL:** Use the new URL. The old link no longer works.
- **An alert or media layer is silent:** Check that the source is connected, the layer is visible, the event is selected for that alert, and the event is not waiting behind another queued event.
- **An asset cannot be selected or deleted:** Check the file type, the file size, your plan's storage, and whether a saved design or published overlay still uses it.

## Not yet available

Overlay Studio Alpha does not have a general trigger image or GIF mode, or a way to clear the queue from an alert text value. Alert layers choose events, not triggers. Only trigger widgets can be limited to chosen triggers.
